## 2. 怎么修

### 2.1 立项记录一定存在（修 5、8c）
- 打开 01 编辑已有项目、进入 02–07 任一步时，若项目还没有 `av_inquiry` 记录，**自动补建**（业务线按项目已有服务包推断；LED 项目 → `packs.led`，规则包取当前最新）。
- `PATCH /api/av/inquiry` 改为「没有就建」，**不再静默丢字段**；真失败时界面提示「没保存上，请重试」。
- 上线时做一次性补齐：所有带 AV 服务包但没有立项记录的项目都补建（数据库增量变更，写进上线操作单）。
- 补齐后，「需求补充说明」「项目地点」可编辑，02–04 不再提示「未经 01 立项询价」。

### 2.2 点间距一定能选（修 6）
- **候选来源 = 价格库型号 ∪ 标准档位**。标准档位：P1.2 / P1.5 / P1.8 / P2.0 / P2.5 / P3.0 / P4.0 / P5.0 / P6.0 / P8.0 / P10，按规则 LED-VD-01（点间距 mm ≤ 最近观看距离 m）只列合格的。例：观看距离 3 m → P1.2–P3.0。
- 价格库里有的档位标「有价格」；只有标准档位的标「**待报价**」，可以选、可以带入 05，到 06 时该行显示「待报价 · 先在价格库补这款」，不阻断。
- **点历史案例 = 套用它的点间距**：卡片可点，点了选中该案例的点间距并高亮卡片，旁边写「已套用 TMKL LED 的 P2.5」。
- 「图上读到的点间距」格子在模型没读到时也可手填。
- 服务端校验同步：接受价格库型号或标准档位，其余拒绝。
- 价格库识别放宽：单位 `㎡` / `m²` / `m2` / `sqm` 都算；手工新增时分类选「LED」就算（存内部代码，不存中文标签）；已有的中文标签数据做一次映射。
- 历史案例卡片：尺寸写明单位「5120 × 2880 mm」；请核实这三条数据（`SELECT name,width_mm,height_mm,pitch FROM av_case WHERE name LIKE '%Canberra%' OR name LIKE '%TMKL%' OR name LIKE '%Sora%'`），若是导入错列，修导入并重新导入。

### 2.3 答案不丢（修 8）
- 答题接口改为**按字段合并**：前端只发改动的那一项（`{key, value}`），服务端在事务里合并，不整体覆盖。`confirmed` 同理。
- 数字输入在停止输入约 0.8 秒后保存，失焦再补一次；每格显示「已保存 ✓」。
- 「重新识别 / 改读第 N 页」**保留已答内容**，只刷新模型读到的值；读到的新值和已答不一致时，在该格提示「模型这次读到 X，保留你填的 Y？」。
- 列表状态改为真实进度：「识别中」「待作答 · 已答 3/5」「可带入 05」「已带入 05 ✓」「识别失败 · 已留档」。底部提示同步（如「还差 2 项：点间距、观看距离」），不再笼统写「还有 2 张图片待确认」。

### 2.4 不再重复上传（修 8b）
- 上传成功后清空文件框；上传中按钮锁定。
- 入库时按文件内容哈希去重：同一项目同一文件再传，提示「这张图已经在列表里（01-Oct 17:56 · 总监 PD），要打开它吗？」，可选「仍然再传一份」。
- 现有重复数据：PD / BD 可在列表里删除多余的一条（沿用 AV-016 的删除权限和日志），**不自动删除**。

### 2.5 数据一路带到 05（修 7、7b）
- 02–04 的「带入 05 方案配置」和底部「下一步：05」**是同一个动作**：判读已可带入时，点「下一步」= 带入 + 跳 05；还不能带入时，「下一步」照样能进 05，但弹窗说明「还差 2 项没答，05 会用默认值」，二选一：「回去补」或「先进 05」。
- 带入内容：开口宽 / 高、点间距、离地高度、最近观看距离、维护方式（后维护 / 前维护）、控制室距离、配电箱距离、形状（弧形等）。05 每个带入的字段下标「来自图片判读 · 01-Oct」。
- 05 已有草稿时，图纸 / 判读有更新也要提示「图纸校核有更新，是否重新带入？」，不自动覆盖（补上 7b）。
