# 需求：Job Record 业务可重复添加 + 可删除

- **需求编号**：REQ-026
- **标题**：Job Record 同类业务可重复添加、也可删除
- **所属系统**：Project-Management
- **状态**：已确认
- **创建日期**：2026-08-11
- **优先级**：P2 · 0811 批次

## 1. 背景
Job Record 底部「添加业务」目前不能重复添加同一类业务，但实际一个项目常有多块同类，例如两块 LED、两个沙盘模型。加错 / 不需要的业务也删不掉。

## 2. 目标
① 「添加业务」支持重复添加同一类业务（一个项目可有多份 LED、多份沙盘模型等），每份是独立的资料卡。
② 已添加的业务可以删除。

## 3. 范围
**做：**
- 「添加业务」下拉选业务类型 → 点「添加」，可对同一类型重复添加，生成多张独立资料卡；多份之间用序号 / 备注区分（如「LED ①」「LED ②」，或允许填一个实例名）。
- 每张业务资料卡可删除（删除按钮 + 二次确认）；删除只影响该项目此实例，不影响其它项目、不影响服务类型的字段模板。
- 多份同类业务各自独立填写字段值（含 REQ-023 的自定义 / 公式字段）。

**不做：** 不改字段模板机制（字段仍按服务类型同源，见 REQ-023）；不做业务卡之间的数据复制（本期先各自独立填）。

## 5. 验收标准
- [ ] 同一类业务可重复添加，生成多张独立资料卡，彼此区分清楚。
- [ ] 每张业务资料卡可删除，删除有二次确认。
- [ ] 删除某实例只影响本项目该实例，不影响其它项目 / 服务类型模板 / 其它实例。
- [ ] 多份同类业务各自独立保存字段值，互不串数据。
- [ ] 老数据兼容：原有单份业务照常显示，可正常删 / 增。

## 7. 备注（含默认假设，如需调整请在 PR 指出）
- 多份同类业务的区分默认用「类型 + 序号」（LED ①/②）；如需支持自定义实例名（如「大堂 LED」「入口 LED」），请指出，我在验收里加。
- 与 REQ-023 配合：字段模板按服务类型同源，字段「值」按业务实例各自存。

## 8. 开发前必须先解决（实现层面的硬约束）
现在一个项目的服务包是 `packages[]`，而 `packages[i].svc` 在多处被当成**唯一键**使用：
- `matchPackage(src, svc)` 按 svc 找包（REQ-012 的导入 / 复制）
- Project Registers 每行按 `svc` 归表
- `addServicePackage` 目前排除已有的 svc（正是「不能重复添加」的来源）

要支持一个项目多份同类业务，得先给每个包一个**独立实例 id**，并把上述按 svc 查找的地方改成按实例 id。这是数据模型改动，不是加个按钮，工作量与风险都要按此评估。
