## 1. 背景

历史案例现在只能按面积从大到小看，筛选只有关键词、状态、点间距、面积；年份混在「状态」栏里（已完成表显示的是表内编号 `#066`）；没有交付日期和保修信息；数据只能靠重新导入整张统计表来改，而且重新导入会**整表清空再写入**（`importCases` 里的 `DELETE FROM av_case`）。

团队希望：能换顺序看、能按年份和客户筛、能看到每块屏什么时候交付、保修到什么时候，并且能直接在平台上改。

## 2. 目标

1. **显示顺序**可切换（下拉 + 方向按钮，列头也能点）。
2. 新增**「筛选」按钮**：年份、客户。
3. **年份单独一列**；新增 **Handover date**、**Expire Warranty** 两列。
4. 新增**「编辑」按钮**，可逐块屏修改；**重新导入统计表时保留人工修改**。

## 3. 功能说明

### 3.1 显示顺序（批注 1）

- 检索栏下方加一条「显示顺序」栏：一个排序字段下拉 + 一个方向按钮（文字随字段变化，如「↓ 大→小」「↑ 近→远」「↑ A→Z」）。
- 可选字段与默认方向：

  | 字段 | 默认方向 |
  |---|---|
  | 面积（**页面默认**） | 大→小 |
  | 年份 | 新→旧 |
  | Handover date | 晚→早 |
  | Expire Warranty | 近→远（最先到期的在最上面） |
  | 项目名 | A→Z |
  | 客户 | A→Z |
  | 点间距 | 小→大 |
  | 功耗 kW | 大→小 |

- 这几列的**列头可点**：点一次按该列排序（用上表的默认方向），再点一次反向；当前排序列高亮并显示 ▲/▼，其它可排序列显示 ⇅。下拉和列头始终同步。
- **空值永远排在最后**，不论升序降序。同值按导入顺序（id）稳定排序。
- 排序在**服务端**做（`ORDER BY` 字段必须走白名单，不能拼接前端传来的列名），因为列表仍有 500 条上限，前端排序只排得到前 500 条。
- 记住每个人上次选的顺序（localStorage 即可）。

### 3.2 「筛选」按钮（批注 2）

- 放在「检索」「清空」右边。点开是一个浮层：
  - **年份**：列出库里出现过的所有年份（新→旧）做成可多选的标签，最后一个是「未填年份（N）」。年份口径与 3.3 的「年份」列显示值一致。
  - **客户**：带搜索框的多选列表，按字母排序，每项后面显示块屏数。
  - 底部「重置」「应用」。
- 已应用的条件以标签形式显示在检索栏下方（如「年份：2025 ×」「客户：Perennial ×」），可以单个移除，也有「清除全部筛选」；按钮上显示已选条件数。
- 与现有的关键词、状态、点间距、面积**同时生效（AND）**；同一类里多选是 OR（选了 2024 和 2025 = 两年都要）。
- 「清空」一并清掉筛选。
- 服务端过滤：`GET /api/av/cases` 增加 `years=2024,2025,none`、`clients=<多值>` 参数。

### 3.3 年份单独一列 + Handover date + Expire Warranty（批注 3）

列顺序：项目｜客户｜**年份**｜状态｜尺寸｜面积｜点间距｜型号｜模组｜功耗｜电源线｜数据线｜**Handover date**｜**Expire Warranty**｜备注。

- **年份**：取统计表的年份（进行中表 A 列）。已完成表大多没有年份：若该屏填了 Handover date，则**灰色显示交付年份**，悬停提示「统计表没有年份，按 Handover date 显示」；两者都没有显示「—」。
- **状态**：只显示「已完成 / 进行中」标签。原来跟在后面的表内编号（`#066`）挪到项目名下方的小字「表内编号 #066」，关键词检索仍能搜到。
- **Handover date**：手填（在「编辑」里），格式与全站一致 `DD-Mon-YYYY`；下方小字「保修 N 个月」。未填显示「未填」。
- **保修期（月）**：手填，**默认 12 个月**，可逐块屏修改。
- **Expire Warranty**：**自动计算 = Handover date + 保修期（月）**，不可手改。下方标签：
  - 距今 > 30 天：**在保**（绿）
  - 0–30 天：**N 天后到期**（琥珀）
  - 已过：**已过保**（红）
  - 没填 Handover date：「—」
- 同一项目的多块屏各自独立填写（常见情况是同一天交付，编辑时可以考虑「同步到本项目其它屏」的勾选，见第 7 节）。

### 3.4 「编辑」按钮（批注 4）

- 放在「导入项目统计表（xlsx）」左边。**只有 PD / BD / 管理员可见**，与导入权限一致；其他角色看不到按钮，后端写接口同样按角色拒绝（前端隐藏 + 后端校验双保险）。
- 点「编辑」进入**编辑模式**（按钮变为「完成编辑」，顶部出现一行说明），每行最左侧出现「✎ 编辑」。
- 点「✎ 编辑」打开右侧抽屉，可改的字段：项目名、客户、年份、地址、状态、表内编号、长、高、面积、点间距、型号、模组、功耗、电源线、数据线、备注，以及新增的 **Handover date**、**保修期（月）**。
  - 面积：可改；若与「长 × 高」相差超过 5%，字段下给出提示（AV-012 记录过统计表本身有 6 行是这样）。
  - 抽屉底部实时显示「Expire Warranty（自动）= … + N 个月 = …」和对应状态标签。
  - 字段旁标出哪些已经人工修改过。
- 保存后：该行项目名下显示「**已人工修改 · N 项**」标签，悬停列出改过的字段；写一条操作日志（谁、何时、哪块屏、字段、改前→改后），日志用「键 + 参数」的方式（沿用 `lib/logmsg.ts`），中英两套。
- 本期**不做**：批量编辑、手动新增 / 删除屏（数据来源仍是统计表）。

## 4. 数据与重新导入（关键）

> 决定：**重新导入时保留人工修改。** 统计表仍是正本，没人改过的字段一律以最新统计表为准；人工改过的字段、手填的 Handover date / 保修期一律保留。

- **存储**：`av_case` 仍然只存导入的原始数据（导入逻辑不改）。新增一张表存人工值，例如 `av_case_edit(case_key, field, value, edited_by, edited_at, PRIMARY KEY(case_key, field))`。Handover date、保修期也存在这张表（它们没有统计表来源）。页面显示 = 原始数据叠加人工值。
- **case_key（跨导入的身份）**：由**原始导入值**算出，不用编辑后的值——否则改了项目名就对不上了。建议：规范化后的「项目名 + 客户 + 长×高（取整 mm）」，同一次导入里完全相同的多块屏再加出现序号。**不含工作表 / 状态**，这样项目从「进行中」表挪到「已完成」表，人工修改仍然跟着它。
- **重新导入流程改成两步**：
  1. 上传后先出**预览**（dry-run）：新增 X 块屏｜按统计表更新 Y 块屏｜保留人工修改 Z 个字段（涉及 W 块屏）｜保留手填交付/保修 V 块屏｜统计表里已没有的屏：移除 A 块（没人改过）、保留 B 块（有人工修改）。
  2. 点「确认导入」才写入。
- **统计表里已经没有的屏**：没人改过 → 移除；有人工修改或手填了日期 → 保留（沿用上一次的原始数据），项目名下标「**不在最新统计表**」，供人判断是否删除。
- 若新统计表的值已与人工值相同，自动清除该字段的人工标记（不再显示「已人工修改」）。
- 数据库变更为**增量**（新增表 / 可空列，不改不删旧表旧字段），与 AV-012 已上线的数据兼容；升级后第一次打开，所有屏都是「未人工修改、未填交付日期」。

## 10. 落地口径（2026-09-30，实现时定下的，请验收时确认）

### 10.1 三个待确认项，按需求默认值做了

| 项 | 取值 | 在哪改 |
|---|---|---|
| 保修期默认 | **12 个月** | `DEFAULT_WARRANTY_MONTHS`（`src/server/avdb.ts`，前端同名常量） |
| 「即将到期」阈值 | **30 天**（含当天；0–30 天标黄，过了标红） | `warranty()`（`AvCasesView.tsx`） |
| case_key 规则 | `项目名 | 客户 | 长(取整 mm) | 高(取整 mm)`，各段去首尾空白、合并连续空白、转小写；同一次导入里完全相同的第 2、3… 块依次加 `#2`、`#3`。**不含工作表与状态** | `caseKeyOf` / `keysFor` |

保修期填的正好是 12 时**不算一处人工修改**（它就是默认值）。否则每块填了交付日期的屏都会多挂一项，「已人工修改 · N 项」就失真了。

### 10.2 比需求多做的一处：「恢复统计表的值」

需求只写了「新统计表追上人工值时自动清标记」。实现时发现缺一条退路：人改错了一个数，想让它回去跟着统计表走，只能凭记忆把统计表里那个数原样打回来 —— 清空输入框不行，**清空本身也是一处人工修改**（`value = ''`，和「没改过」必须分得开，否则就没法表达「统计表写了，但我们确认这里应当为空」）。

所以编辑抽屉里，人工改过、且统计表里有来源的字段旁边多一个「恢复统计表的值」。交付日期 / 保修期没有来源，清空输入框就等于不改了，不需要这个按钮。接口上是 `PATCH` 的 `revert: [字段…]`，白名单之外的字段忽略。

### 10.3 操作日志

- 一次保存写**一条**：显示第一处改动，其余用「另 N 处」带过 —— 对应 §6「操作日志有一条记录」。完整的改前→改后存在参数 `changes` 里（模板不引用，所以不显示，但留着）。
- 案例库是公司级数据、不挂项目，所以不走项目的 `audit_log`，自带一张 `av_case_edit_log`，与价格库的 `av_price_history` 同一路子。编辑抽屉底部「修改记录」列最近 20 条。
- 键 `av.caseEdit` / `av.caseEditMore`；字段名槽位叫 `{cf}` 而不是 `{field}` —— `sched.date`、`pkg.field`、`fin.edit` 早就在用 `{field}`，注册成翻译槽会把它们一起误翻。

### 10.4 两步导入

预览和确认各上传一次同一个文件，服务端不在两步之间暂存。多解析一次统计表（几秒），换来 Vercel 预览和内网服务器上的行为完全一样 —— 暂存在内存里的话，Vercel 上两个请求可能落到两台实例，确认时找不到预览。

### 10.5 编辑用的是弹窗，不是原型的右侧抽屉

按「交互以原型为准，视觉用平台现有样式」：字段、分段、实时到期日、面积提示、人工修改标记都照原型；外框用平台现有的 `.overlay` / `.modal`（与新建项目等弹窗一致）。

### 10.6 升级已有数据

AV-012 时代导入的行没有 `case_key`，第一次启动时按 10.1 的规则补算。判断条件是「有行、但一行都没有 key」，补算在一个事务里 —— 要么全补上，要么一行没动。已经有 key 的库**绝不重算**（重新导入后保留下来的旧行与新行 id 交错，重算会把重复屏的序号排乱，和人工修改对不上）。

实测：用 AV-012 的代码导入 8 块屏 → 换新代码打开同一个库 → 列与表补上、8 行 key 全部补算且互不重复、原有每个字段一个没变、没有凭空多出人工修改；升级后第一次重新导入同一份统计表，预览为「新增 0、更新 8、移除 0」—— 补算的 key 与导入时算的完全一致。另模拟「加完列、补算前进程挂了」的遗留状态，下次启动能补上，且与正常补算结果 8/8 一致。

### 10.7 同步到本项目其它屏（§7 第 2 条，2026-09-30）

- 编辑弹窗的「交付与保修」一段，**这个项目还有别的屏时**出现勾选「把交付日期与保修期同步到本项目其它 N 块屏」，下面列出那几块的尺寸与现在的交付日期 / 保修期。只有一块屏的项目不出现。默认不勾。
- **「同一项目」按页面上看到的项目名 + 客户认**（去首尾空白、不分大小写），不按 case_key —— case_key 是原始导入值算的，谁改过项目名就对不上了，而人判断「是不是同一个项目」看的是页面上那个名字。客户不同就不算（095-GMC 的客户是 Perennials，不会被当成 Perennial 的 8SW）。
- **只同步交付日期与保修期**。尺寸、面积这些每块屏各不相同，不碰。
- 带过去的是这块屏**保存后**的值 —— 所以只改了面积、顺手勾了同步，其它屏也会对齐到这块屏。
- 同项目的屏在**保存前**找：同一次保存里连项目名一起改了，照样同步到原来那几块。
- 每块被同步的屏各留一条修改记录，写明「随同项目其它屏同步」（键 `av.caseSync` / `av.caseSyncMore`，中英两套）。本来就一致的屏不算、不写空记录。
- 同步回默认的 12 个月时，其它屏也回到默认，不留人工修改标记。

### 10.8 保修到期提醒 + 保修状态 / 交付日期范围筛选（§7 第 1、3 条，2026-09-30）

**筛选**（「筛选」浮层里，年份与客户之外）：

- **保修状态**四档多选，每档带块屏数：在保 / 30 天内到期 / 已过保 / 未填。与表格里的三色标签同一口径 —— 距今 0–30 天（含今天和第 30 天）算「30 天内到期」，第 31 天起算「在保」，昨天及以前算「已过保」。
- **交付日期范围**：起、止两个日期，含两端；只填一头也行；起止填反了自动对调。
- 服务端过滤（`warranty=ok,soon,expired,none`、`handoverFrom`、`handoverTo`），与其它条件 AND、同类 OR；不认识的值忽略。
- 「今天」取**服务器本地日期**，不用 SQLite 的 `date('now')`（那是 UTC，新加坡早上八点前会差一天）。

**提醒**：
