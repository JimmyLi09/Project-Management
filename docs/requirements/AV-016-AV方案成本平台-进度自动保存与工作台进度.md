## 1. 现状（查代码确认的原因）

1. **上传的图纸解析失败就整个丢掉。** `api/av/ingest` 先把文件写进临时目录 → 调解析 → **成功才** `insertDrawing` → `finally` 删临时目录。0930 上传的 PNG 因为 OCR 没装解析失败，文件和记录都没留下，所以图纸页显示「该项目还没有上传图纸」，同事以为白传了。
2. **工作台不数「立项」这一步。** `api/av/overview` 的 `counts` 只有 review / config / quoting，`intake`（刚立项、还没图纸）的项目不计数，所以刚立项的项目在四个数字里都是 0。
3. **立项后的「下一步」指回 01。** `intake` 的下一步是「补充信息 → avinquiry」，立项信息其实已经填完了，真正该做的是 02 上传图纸。
4. **05 方案配置只有手动保存。** 只有点「保存方案到项目」才落库；改到一半切走或刷新，改动全丢。
5. 工作台看不出每个项目「做到哪、谁、什么时候」。

（04 校核逐项确认本来就是即时保存的，这部分不用改。）

## 2. 目标

**做过的每一步都自动留下来，回来能接着做；工作台一眼看出每个项目卡在哪。**

## 3. 功能说明

### 3.1 立项后的状态（01 → 02）

- 立项成功后项目进入「**待上传图纸**」，工作台出现在这一栏；「下一步」= **上传图纸 ›**，直接跳到 02 并选好该项目。
- 只有立项必填项缺失时，下一步才显示「补充信息 ›」回 01（例如缺交付日期 / 业务线）。
- 01 立项表单编辑已有项目时同样自动保存（见 3.4 的机制），不再需要记得点保存。

### 3.2 上传的图纸先留档、再解析（02）

- 上传后**先把原始文件存进项目**（`data/` 下按项目分目录，随数据一起备份），立刻建一条图纸记录，状态「解析中」；然后再调解析。
- 解析成功 → 「待校核」，与现在一样。
- 解析失败 → 记录**保留**，状态「**解析失败 · 已留档**」，附一句人话原因（例：「本机识别服务暂不可用」「比例尺未标定」「文件损坏」），给两个按钮：**重新解析**、**手填**（手填后同样进入校核）。技术错误信息只进服务器日志和管理员状态页，不显示给同事。
- 02 页面列出该项目所有上传过的文件：文件名、谁 / 何时上传、分级、状态、确认进度（如 4 / 6）。可下载原件；删除需 PD / BD，且写操作日志。
- 解析失败的图纸，项目在工作台算「**图纸待处理**」（计入「待图纸校核」数字，行内标红）。

### 3.3 工作台（AV 工作台）

- 数字从 4 个改为 5 个：**待上传图纸（新增）**｜待图纸校核（含解析失败待处理）｜待方案配置｜待核算｜待报价；「价格已过期物料」保留。点数字可筛选下面的列表，再点取消。
- 每行增加：
  - **进度条**：01 立项 → 02 上传 → 03–04 校核 → 05 配置 → 06 成本 → 07 报价，已完成绿色、当前橙色，悬停显示每步状态；
  - **最近更新**：「今天 16:20 · Skye · 草稿自动保存」「今天 10:05 · 已确认 4/6」这类一句话；
  - **下一步**：按真实状态给链接，**点了直接到上次停下的那一步 / 那个标签**（沿用 `setLedProjectId` + `setView`）。
- 阶段判定（`api/av/overview`）调整：`intake` 拆成「待上传图纸」和「缺立项信息」；有解析失败的图纸 → 「图纸待处理」；其余沿用现有规则。仍然先过 `visibleProjects`（REQ-043）。

### 3.4 方案配置自动保存草稿（05）

- 每次改动后约 1.5 秒自动存为**草稿**（按 项目 × 业务线 × 用户 一份），右上角显示「● 正在保存草稿…」→「✓ 草稿已自动保存 · 19:32」。切走、刷新、关浏览器都不丢。
- 再次打开：自动恢复草稿，并提示「已恢复你 19:32 的草稿；正式版本 v1（28-Sep 由 PD 保存）」。
- 「**保存方案到项目**」= 生成正式版本（v1、v2…），草稿清空；「放弃草稿」= 回到最新正式版本。
- **草稿不影响别人**：成本核算、报价、工作台阶段判定只认正式版本；别人打开看到的是正式版本，并提示「Skye 有未保存的草稿（今天 16:20）」。
- 权限：谁能编辑这一页，谁就能存草稿（沿用 `canCostProject` 等现有判断，后端校验）。
- 离开页面时若草稿还没来得及存（网络断），浏览器弹「有未保存的改动」提醒。

### 3.5 通用

- 自动保存都写操作日志，但**合并记录**：同一人、同一页、10 分钟内的连续草稿只记一条，避免日志刷屏；生成正式版本单独记一条。
- 新增文案中英两套。
- 数据库只做增量变更（新表 / 可空列），已有数据不迁移、不丢。

## 4. 验收标准

- [ ] 新建一个 LED 立项 → 工作台「待上传图纸」+1，该行下一步是「上传图纸 ›」，点了直接进 02 且选好该项目。
- [ ] 在识别服务不可用的情况下上传一张 PNG → 图纸列表里**有这条记录**，状态「解析失败 · 已留档」，原因是人话；刷新页面、换人登录都还在；「重新解析」「手填」可用；工作台该项目显示「图纸待处理」。
- [ ] 解析成功的图纸行为与现在一致；已上传的文件可下载原件。
- [ ] 05 改几个参数不点保存 → 刷新 / 退出重登 → 改动还在，并提示恢复了草稿；成本页和工作台仍按正式版本；「保存方案到项目」后生成新版本、草稿清空；「放弃草稿」恢复正式版本。
- [ ] 两个人同时改同一项目：各自草稿互不覆盖；另一人看到「X 有未保存的草稿」提示。
- [ ] 工作台 5 个数字与列表一致，点数字能筛选；每行有进度条、最近更新、正确的下一步。
- [ ] PM / Engineer 只看得到自己项目的数字和行（REQ-043）。
- [ ] 操作日志：连续自动保存只记一条，正式保存单独一条；EN 模式为英文。

## 5. 不做（本期）

- 草稿的多版本历史（只保留每人最新一份草稿；正式版本本来就有版本号）。
- 多人实时协同编辑同一份草稿。
