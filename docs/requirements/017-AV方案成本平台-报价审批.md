# 需求：AV 方案成本平台 · 07 报价审批

- **需求编号**：REQ-017
- **标题**：07 报价审批：合并报价、折扣与 GST、PD / BD 审批、客户报价单
- **所属系统**：AV 方案成本平台
- **状态**：已实现
- **创建日期**：2026-09-26
- **优先级**：P1 · 决策来源：2026-09-26 Jimmy「开始做 07 报价审批」及同日四项选择

## 1. 决策（2026-09-26）

| 问题 | 决定 |
| --- | --- |
| 谁审批 | **全部报价由 PD / BD 审批**（一级）。销售 / PM 汇总并可调折扣后提交；折后毛利低于公司下限（默认 18%）时提交人必须填写理由 |
| 草案规则包的业务线 | **只收成本已确认的业务线**，沿用 06 的规则：草稿、方案改过需重算、未核算的业务线都不能进报价。目前实际只有 LED 能进报价 |
| 报价单形式 | **网页报价单 + 浏览器打印 / 另存 PDF**，不增加依赖 |
| 税 | **价格库售价不含税**，报价单列出不含税小计、GST 9%、含税总计 |

规格书 v1.0 把报价单与审批流放在第二期，原型没有 07 页面；本页按以上决定设计。

## 2. 流程

1. **提交**（销售、PD / BD，或该项目的 PM）：07 页选项目，列出项目的每条业务线及其状态
   （可报价 / 成本未确认 / 方案已改需重算 / 未核算）。可报价的默认勾选；填写折扣 %（作用于售价合计）；
   右侧实时显示售价合计、折扣、不含税小计、GST、含税总计、成本、折后毛利率。
2. **检查**（服务端重算，不信任前端）：
   - QUOTE-EMPTY：至少一条已确认业务线 —— 阻断；
   - QUOTE-DISC：折扣须在 0–100% —— 阻断；
   - QUOTE-MARGIN：折后毛利低于下限，未填理由阻断，填了理由转为提示，由审批人决定；
   - 所选业务线不是「已确认的最新成本」—— 接口返回 400。
3. **锁定**：报价保存提交时的各业务线成本表快照（只含售价行）、折扣、GST 税率、毛利下限；
   之后改价、改方案不影响已提交的报价，需要时重新提交。
4. **取代**：同一项目再次提交，会把仍在「待审批」的旧报价标为「已被新版本取代」；已批准 / 已退回的不受影响。
5. **审批**（PD / BD）：批准（意见可选）或退回（意见必填）。只有「待审批」可以决定，重复操作返回 409。
6. **报价单**：`/av/quote/<id>`，编号 `AVQ-0001`。只含售价：各业务线明细（名称、价格库条目、数量、单位、单价、金额）、
   分线小计、合计、折扣、不含税小计、GST 9%、含税总计；批准后页脚写审批人与日期。
   未批准的报价单顶部有红框「未经审批，不得对外发出 — NOT APPROVED, NOT FOR ISSUE」。
   页面右上「打印 / 另存为 PDF」，打印版 A4、隐藏按钮。

每次提交、批准、退回都写入项目动态（审计日志）。

## 4. 数据

`av_quote`：project_id、sections（JSON 快照：业务线、来源成本表 id、成本、售价、售价行）、discount_pct、gst_rate、
margin_floor、reason、status（submitted / approved / rejected / superseded）、提交人与时间、审批人、时间与意见。
合计由 `src/av/core/quote.ts` 从快照确定性计算：折扣与 GST 均四舍五入到分。删除项目时一并删除。
