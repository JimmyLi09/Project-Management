# 需求：角色权限 —— 可见性 + 编辑权限（PM / Engineer 只看只编自己的项目）

- **需求编号**：REQ-043
- **标题**：按角色的项目可见性与编辑权限（PM / Engineer 只涉及自己管理 / 参与的项目）
- **所属系统**：Project-Management
- **状态**：已确认
- **创建日期**：2026-09-28
- **优先级**：P1 · 0922 批次
- **来源**：Progress comments 0922 · 图3（可见性）、图6（编辑权限）

## 1. 背景
现在所有人（含 PM、Engineer）都能看到、也能改所有项目。团队希望：PM 和 Engineer **只看到 / 只能编辑自己负责或参与的项目**，别人的看不到、也不能改；总监 / 管理员仍看全部。这既是信息范围，也是权限安全。

## 2. 目标
① **可见性**：PM 只看到自己是 PM 的项目；Engineer 只看到自己被指派的项目；总监 / 管理员看全部。
② **编辑权限**：PM / Engineer 只能编辑自己管理 / 参与的项目内容，其它项目对其只读（编辑 / 总编辑等入口禁用）。

## 3. 范围
**做：**
- **角色与归属（用现有数据）**：
  - 角色来自现有用户体系（如 总监/PD·管理员、PM、Engineer、Sales）。
  - 项目归属来自现有指派：项目的 **PM** 字段、**Engineer / 参与人** 字段。
- **可见性规则**（默认，见备注可调）：
  - 总监 / PD / 管理员：看全部项目。
  - PM：只看 `project.pm == 当前用户` 的项目。
  - Engineer：只看被指派为该项目 Engineer / 参与人的项目。
  - 影响范围：**项目列表**（大卡片 / 列表 / 紧凑）、**我的待办**、**统计报表**、**向上汇报**、**项目档案**、搜索结果——都只在该用户可见的项目集内。
  - 「全部负责人」筛选：对 PM/Engineer 隐藏或锁定为「我」（不再能切到看别人）。
- **编辑权限规则**：
  - 对**非本人管理 / 参与**的项目：概览 / Job Record（总编辑）/ 信息清单（编辑）/ 排期 / 联系人等**编辑入口禁用或隐藏**，内容只读；显示「非你管理的项目 · 只读」提示。
  - 对**本人管理 / 参与**的项目：照常可编辑。
  - 后端也要校验（不只是前端隐藏）：非授权用户的写操作被拒绝。
- **总监视角不变**：总监 / 管理员可见可编辑全部。

**不做：** 本期不做字段级 / 分区级细粒度权限（只到「项目级」）；不做审批流；不做自定义角色（用现有角色枚举）。

## 5. 验收标准
- [ ] 以 PM 登录：项目列表 / 我的待办 / 统计 / 向上汇报 只出现自己是 PM 的项目；看不到别人的。
- [ ] 以 Engineer 登录：只出现自己被指派的项目。
- [ ] 以 总监 / 管理员登录：看到全部项目（行为不变）。
- [ ] PM / Engineer 打开**非自己**的项目（若能通过链接直达）：内容只读，编辑 / 总编辑等入口禁用，有「只读」提示；后端拒绝其写操作。
- [ ] PM / Engineer 打开**自己**的项目：可正常编辑。
- [ ] 「全部负责人」等筛选对 PM/Engineer 不再暴露他人项目。

## 7. 备注（含默认假设，如需调整请在 PR 指出）
- **Sales / 其它角色** 的可见范围默认「看与自己相关的项目」（如自己是 Sales 对接的）；若 Sales 应看全部或另有规则，请指出。
- **Engineer 归属字段**：以项目现有的「Engineer / 参与人」指派为准；若目前项目上还没有 Engineer 字段，需先补一个指派字段（请在 PR 说明用哪个字段）。
- **多 PM / 协作人**：若一个项目允许多个 PM / 参与人，任一归属者都可见可编。
- **越权直达**：即使 PM 拿到别人项目的 URL，也应只读（前端禁用 + 后端校验双保险）。
- 与 REQ-008（删除权限）一致：写 / 删操作都按角色 + 归属校验。
