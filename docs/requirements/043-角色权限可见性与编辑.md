# 需求：角色权限 —— 可见性 + 编辑权限（PM / Engineer 只看只编自己的项目）

- **需求编号**：REQ-043
- **标题**：按角色的项目可见性与编辑权限（PM / Engineer 只涉及自己管理 / 参与的项目）
- **所属系统**：Project-Management
- **状态**：已确认
- **创建日期**：2026-09-28
- **优先级**：P1 · 0922 批次
- **来源**：Progress comments 0922 · 图3（可见性）、图6（编辑权限）

## 1. 背景
现在所有人（含 PM、Engineer）都能看到、也能改所有项目。团队希望：PM 和 Engineer **只看到 / 只能编辑自己负责或参与的项目**，别人的看不到、也不能改；总监 / 管理员仍看全部。这既是信息范围，也是权限安全。

## 2. 目标
① **可见性**：PM 只看到自己是 PM 的项目；Engineer 只看到自己被指派的项目；总监 / 管理员看全部。
② **编辑权限**：PM / Engineer 只能编辑自己管理 / 参与的项目内容，其它项目对其只读（编辑 / 总编辑等入口禁用）。

## 3. 范围
**做：**
- **角色与归属（用现有数据）**：
  - 角色来自现有用户体系（如 总监/PD·管理员、PM、Engineer、Sales）。
  - 项目归属来自现有指派：项目的 **PM** 字段、**Engineer / 参与人** 字段。
- **可见性规则**（默认，见备注可调）：
  - 总监 / PD / 管理员：看全部项目。
  - PM：只看 `project.pm == 当前用户` 的项目。
  - Engineer：只看被指派为该项目 Engineer / 参与人的项目。
  - 影响范围：**项目列表**（大卡片 / 列表 / 紧凑）、**我的待办**、**统计报表**、**向上汇报**、**项目档案**、搜索结果——都只在该用户可见的项目集内。
  - 「全部负责人」筛选：对 PM/Engineer 隐藏或锁定为「我」（不再能切到看别人）。
- **编辑权限规则**：
  - 对**非本人管理 / 参与**的项目：概览 / Job Record（总编辑）/ 信息清单（编辑）/ 排期 / 联系人等**编辑入口禁用或隐藏**，内容只读；显示「非你管理的项目 · 只读」提示。
  - 对**本人管理 / 参与**的项目：照常可编辑。
  - 后端也要校验（不只是前端隐藏）：非授权用户的写操作被拒绝。
- **总监视角不变**：总监 / 管理员可见可编辑全部。

**不做：** 本期不做字段级 / 分区级细粒度权限（只到「项目级」）；不做审批流；不做自定义角色（用现有角色枚举）。

## 5. 验收标准
- [ ] 以 PM 登录：项目列表 / 我的待办 / 统计 / 向上汇报 只出现自己是 PM 的项目；看不到别人的。
- [ ] 以 Engineer 登录：只出现自己被指派的项目。
- [ ] 以 总监 / 管理员登录：看到全部项目（行为不变）。
- [ ] PM / Engineer 打开**非自己**的项目（若能通过链接直达）：内容只读，编辑 / 总编辑等入口禁用，有「只读」提示；后端拒绝其写操作。
- [ ] PM / Engineer 打开**自己**的项目：可正常编辑。
- [ ] 「全部负责人」等筛选对 PM/Engineer 不再暴露他人项目。

## 7. 备注（含默认假设，如需调整请在 PR 指出）
- **Sales / 其它角色** 的可见范围默认「看与自己相关的项目」（如自己是 Sales 对接的）；若 Sales 应看全部或另有规则，请指出。
- **Engineer 归属字段**：以项目现有的「Engineer / 参与人」指派为准；若目前项目上还没有 Engineer 字段，需先补一个指派字段（请在 PR 说明用哪个字段）。
- **多 PM / 协作人**：若一个项目允许多个 PM / 参与人，任一归属者都可见可编。
- **越权直达**：即使 PM 拿到别人项目的 URL，也应只读（前端禁用 + 后端校验双保险）。
- 与 REQ-008（删除权限）一致：写 / 删操作都按角色 + 归属校验。

## 8. 实现口径（2026-09-28 确认，以此为准）

上面 §7 里留的两个待确认，已经定了：

- **Sales / Finance / Viewer 保持看全部**。项目上没有「Sales 对接人」这类归属字段，硬收窄会让 Sales 看不见自己该跟的单子、Finance 开不了别人项目的票。本期只收窄 PM 与 Engineer 两个角色。
- **Engineer 是项目级指派，和 PM 同一性质：一个项目一个 engineer**。为此在 `Project` 上新增可选字段 `engineer?: string`（老项目读出来是 `undefined`，不迁移、行为不变）。
  - 指派权限：与指派 PM 同一档，仅 PD / BD（`setEngineer` action）。被指派的人自己改不了。
  - 被指派的 engineer 对该项目**可见且可编辑生产内容**（`canEdit` 把 `p.engineer === 我` 算作一档，等同于在 `perm` 里）。
  - 人员转交（`transferProject` / 批量转交）与改名传播都会带上这一栏，否则人一走项目就挂在空名下。
  - 可见性判据兜底仍保留「有一行任务点名指派给我」：没被指派为项目工程师、只来帮一行忙的人，也得看得见那个项目，否则他连自己的待办都点不开。

## 9. AV 平台接入（2026-09-29）

§3 的可见性原来只在项目本身的接口上落实。AV 方案成本平台是另一条开发线接进来的，它的接口**没有接上这一层** —— 实测：PM 拿 `/api/projects/<别人的>` 是 403，同一个 id 走 `/api/av/cost` 却是 200，能读到那个项目的方案、成本表、公司毛利下限。

写操作没事：`canEdit` 早就把 PM 挡在别人项目外面了。漏的全是**读**。

补法是在 `src/server/avguard.ts` 里加一个 `denyUnlessVisible`，在拿到项目之后、干任何事之前问一句 `canSeeProject`，口径与 §3 完全一致、不另立规矩。已接上的口子：

## 10. 字段级隔离：成本价与毛利（2026-09-30）

§3 管的是「看不看得见这个项目」；这一节管「看得见的项目里，每个数看不看得见」。

### 10.1 口径（2026-09-30 定）

| 角色 | 成本价 / 毛利 / 毛利下限 | 售价 / 报价金额 | 成本单 | 报价 |
|---|---|---|---|---|
| PD / BD | ✓ | ✓ | 挑物料、保存、**确认** | 提交、审批 |
| 财务 | ✓ | ✓ | 只读 | 只读 |
| Sales | ✗ | ✓ | 只读（只见售价列） | 提交（不提示毛利） |
| PM | ✗ | ✗ | 挑物料、定数量、保存（页面上无任何单价与金额），**不能确认** | 看不到 |

由此带出的几处流程变化：

- **确认成本改由 PD / BD 做。** 原来（AV-004）是 PM。确认要看着毛利才确认得了，PM 看不到成本就确认不了。PM 照旧挑物料、定数量、保存；按钮从「保存草稿 / 确认成本」变成一个「保存」，旁边写明「确认成本由 PD / BD 进行」。
- **PM 不再发起报价，也看不到报价页。** 报价就是售价，PM 连售价也不看。「成本与报价」页对 PM 只剩「成本核算」一档，报价打印页也进不来。
- **Sales 提交低于毛利下限的报价时不提示、不要求填理由**（2026-09-30 选「完全不提示」）。照常提交，由 PD / BD 审批时看 —— 审批人的报价记录里，低于下限的那份毛利标红，下面写「低于下限 18%」。PD / BD 自己提交时仍要填理由。

### 10.2 做法

- 服务端按人**把字段置空再回包**（`src/server/avredact.ts` 集中处理），前端藏列只是跟着走。涉及：价格库条目与改价历史、成本单每行的快照单价与合计、项目汇总、共用资源去重、报价分段与合计、毛利下限、检查提示的文字（「毛利率 x% 低于下限」整条拿掉；「价格库已变动（成本 a / 售价 b）」改成不带数的一句）、报价打印页的页面数据。
- **项目日志也抹。** 「单线成本确认」「提交报价」「批准 / 退回报价」这几条的参数里带着金额与毛利；读日志时按人把这些参数置空（显示为「—」）再渲染。09-29 之前写下的老日志只有一句中文，按当时的固定句式把数字抹掉。
- 浏览器里实时预算的成本单也按人处理：看不到成本价的人，本地算不出「缺少成本价」「价格已变动」「毛利」这三条检查，页面上不显示；确认时服务端拿真价再查一遍。

### 10.3 验收（已测）

对 PD、财务、Sales、PM 四个角色的**每一个**价格相关回包做深度扫描（价格库、改价历史、毛利下限、成本单、报价、项目日志）：Sales 的回包里任何成本键上都没有值、文字里没有毛利数字；PM 的回包里成本与售价键上都没有值。PM 确认成本 / 提交报价 / 打开报价打印页都被拒；Sales 不填理由能提交低于下限的报价，PD 仍被拦；PD 看 Sales 那份报价，成本与下限都在。老格式日志逐字核对抹后的样子。
