## 1. 开票日期：填了日期还提示「请填写开票日期」（第 1 条）

### 1.1 现状
- 截图：161-Dedao MAXHUB Donlge，「已开 Invoice」弹窗，开票日期 2026/09/30，确认后弹出「请填写开票日期」。
- 这句来自 `actions.ts` 的 `markInvoiced`：`validDay(day)` 不通过时报出。
- 10/10 之前 `isoDate` 用的是 `toISOString`（UTC）。服务器在 UTC+8，`isoDate(parseISO('2026-09-30'))` 得到 `2026-09-29`，和输入对不上，所以报错。**提交 3c0c6df（10/10）已经修好**。
- 截图很可能是 10/10 之前截的。我在 4 个时区用现在的代码复核过 `validDay('2026-09-30')`，都通过。

### 1.2 要做的
1. **先复现**：在当前 main、服务器时区 UTC+8 下，按截图操作一次。
   - 不复现：只做下面第 2–4 点，作为保护。
   - 还复现：查根因修掉，并在 PR 里写清原因。
2. 弹窗**前端先校验**：Invoice 号必填、开票日期必须是合法日期、到期日不能早于开票日期。错误显示在对应输入框下面，**不再弹浏览器 alert**。
3. 服务端校验失败时，把收到的原始值（`issuedDate`、`dueDate`）写进服务器日志，方便以后定位。
4. 加自动测试：`TZ=Asia/Singapore` 下，开票日期 `2026-09-30`、`2026-10-01`、`2026-12-31` 都能通过并归档。

## 2. 新建项目：相关公司的角色下拉加「发展商」（第 2 条）
- **现状**：`ProjectsView.tsx` 的 `COMPANY_ROLES` 特意去掉了 `developer`，理由是上面「① 客户信息」就是发展商。但客户不一定是发展商：客户可能是总包或 ID 公司，这时发展商需要另外填。
- **改成**：`COMPANY_ROLES` 包含全部 6 个角色，**「Developer / 发展商」排第一**。选了就存成键 `developer`。通讯录里显示「发展商」，规则和 REQ-052 一致。
- 项目详情里「添加联系人」的下拉已经有发展商，不用改。

## 4. 项目 PM 也能删除业务（第 5 条）

### 4.1 现状
- 删除业务的功能已有：资料卡右上角「✕ 删除业务」，Job Record 顶部业务条上也有。
- 但只有 `canDelete(u)` 能用，也就是 Sales / PD / BD。PM 登录时看不到按钮，JM 截图就是这种情况。
- 删除时（`removeServicePackage`）：
  - 排期阶段和资料卡一起删；
  - 只属于这个业务的清单项移到「已移除的项」，可恢复；
  - Job Record 的 4 栏行和额外项目保留；
  - AV 数据按「项目 + 业务线」存，**不受影响**。

### 4.2 改成
- 新判断 `canRemovePkg(u, p, pk)`，前端和后端用同一个：
  - **Sales / PD / BD**：照旧，可以删。
  - **项目 PM**（`p.owners` 里有他、角色是 pm）：可以删，但这个业务**还没开工**时才可以。下面任一条成立就算已开工：
    - 它的排期有阶段状态是「进行中 / 已完成」；
    - 信息清单里只属于它的项，有任何一项已收到 / 已确认，或有收料记录。
    - 已开工时，按钮置灰，悬停提示「这个业务已经开工 / 已收到资料，请找 Sales / PD 删除」。后端返回 403，文字相同。
  - **Engineer、Finance、Viewer**：看不到按钮。
- 照旧的限制：
  - 项目只剩一个业务时不能删，按钮置灰并提示「至少保留一个业务」；
  - REQ-057：PM 端已收尾的项目只读，不能删；
  - REQ-054：已关闭的售前记录不能删。
- 确认弹窗沿用现在的文案，再加一句：「AV 方案 / 成本里这条业务线的数据不删，重新加回这个业务就会回来。」
- 每次删除写日志（现有 `pkg.remove`）。
