# 需求：积分定义标准（积分规则）

- **需求编号**：REQ-038
- **标题**：积分定义标准——按业务 / 规格档位给分（来源《项目积分算法》），可配置、留版本
- **所属系统**：Project-Management
- **状态**：已确认（分值口径以用户《项目积分算法》为准）
- **创建日期**：2026-09-02
- **优先级**：P1 · 运营中心批次

## 1. 背景
KPI「积分产出」维度需要一个明确、可维护的积分口径。用户提供了《项目积分算法》，按**业务（服务类型）× 规格 / 数量档位**给分。需要把它做成平台里可配置、可留版本的「积分规则」，作为积分产出的统一来源。

## 2. 目标
在「规则设置 · 积分规则」里，按下述标准配置每个业务的分档；项目 / Job Record 按业务 + 规格自动匹配得分；规则可改、改动留版本、注明生效日。

## 3. 范围
**做：按业务分档（初始值＝《项目积分算法》，均可在界面改）**

- **效果图（CGI 静帧）**：5 张=1 · 10 张=2 · 15 张=3 · 20 张=5
- **动画**：1 分钟=2 · 2 分钟=4 · 2 分钟以上=5
- **360 / 720 全景**：1–2 房 VR=2 · 3–4 房=3.5 · 4 房以上=5 · 室外 720=3–5（区间）· 项目 360=5
- **实体模型**：比例 50 以上=3 · 30–50=5 · Unit / Landscape Model=3
- **Sales Kit**：不带 360=5（自设计 UI=7）· 带 360=7（自设计 UI=10）
- **LED & Projectors**：LED 计算与安装=3–7（区间）· Projector 融合与调试=3–10（区间）

**能力：**
- 每个业务的档位（条件 → 分值）可增 / 删 / 改；可新增业务。
- **区间档**（如 LED 3–7）：区间内取值规则可配（默认：由 PM 在项目里按规模 / 复杂度手选具体分值；见备注待确认）。
- **档位匹配**：项目 / Job Record 按业务 + 规格（张数 / 时长 / 房数 / 比例等）自动匹配对应档位得分；无法自动判定时由 PM 选档。
- **版本化**：规则改动存为新版本、注明生效日、可回看；历史项目按其生效时的规则计分（默认）。
- 该分值即 KPI（REQ-037）「积分产出」维度的来源。

**附加规则（《项目积分算法》未含，作为可选、默认关闭，待确认）：**
- 准时交付加成 / 逾期扣减（默认 0）。
- 积分归属：默认「全归 PM」；可选「按角色分配（PM / 制作 / Sales 比例）」。

**不做：** 不内置写死复杂公式（档位为主）；本期不做跨业务的组合折算。

## 5. 验收标准
- [ ] 「规则设置 · 积分规则」按上述业务 / 档位展示，初始值与《项目积分算法》一致。
- [ ] 每个档位分值可改；可增 / 删档位、可新增业务；改动存为新版本、带生效日。
- [ ] 项目 / Job Record 能按业务 + 规格匹配到对应档位得分（不能自动判定时可手选档）。
- [ ] 区间档（LED / Projector / 室外720）可设定区间内取值方式，不报错。
- [ ] KPI 看板「积分产出」用的就是这套规则的结果。
- [ ] 附加规则（加成 / 归属）默认关闭时，不影响基础积分。

## 7. 备注（含默认假设，如需调整请在 PR 指出）
- **待确认（沿用留档）**：① 区间档（3–7 / 3–10 / 3–5）区间内怎么定分（默认 PM 手选）；② 实体模型「50 以上 / 30–50」指比例还是尺寸；③ 张数 / 时长等是自动读项目数据匹配档位还是人工选；④ 附加加成 / 归属要不要。
- 分值与档位口径**以用户《项目积分算法》为准**，本文档表格为落库初始值。
- 与 REQ-037 对齐：本条产出「积分」，037 把它作为一维加权。
- 与 REQ-023（字段 / 公式）相关：积分档位是「按服务类型的规则」，与字段 schema 同源思路一致。
