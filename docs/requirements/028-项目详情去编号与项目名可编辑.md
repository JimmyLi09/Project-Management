# 需求：项目详情页去系统编号 + 项目名可编辑

- **需求编号**：REQ-028
- **标题**：项目详情页顶部去掉系统编号前缀 + 项目名可编辑
- **所属系统**：Project-Management
- **状态**：已确认
- **创建日期**：2026-08-11
- **优先级**：P2 · 0811 UI 批次

> **编号说明**：这条在 0811 UI 批次的脚本里原本写作 REQ-027，但 REQ-027 已被「资料卡公式字段 + 字段分组 / 两列排布」占用并已开发上线，故改用 REQ-028，避免两份文档同号。

## 1. 背景
项目详情页顶部标题前带系统自动编号（如 `04`），和 REQ-025 列表去编号不一致，显冗余；且项目名目前不能改 —— 改错了、或复制出的「副本」想改名都没法改。

## 2. 目标
① 详情页顶部去掉系统编号前缀（如 04），项目名整段保留。
② 项目名可编辑：点击进入编辑、改完保存生效。

## 3. 范围
**做：**
- 详情页头部不再显示系统编号（04），与 REQ-025 一致（编号仅不显示，数据保留）。
- 项目名可编辑：点标题或旁边铅笔图标 → 变输入框 → 改 → 回车 / 失焦保存；Esc 取消；保存后持久化。
- 权限沿用现有 `canMeta`（PD / BD / Sales / PM 可改；viewer 只读，且看不到编辑入口）。

**不做：** 不自动改项目名里本身的数字（如 `140-`，由用户在可编辑框里自行增删）；不做改名历史留痕（但项目日志会记一条「项目更名：旧 → 新」）。

## 5. 验收标准
- [ ] 详情页顶部不再显示系统编号（04）。
- [ ] 项目名可点击进入编辑、改后保存并持久化；刷新后保持新名。
- [ ] 空名不能保存（前端提示 + 服务端校验，两层都拦）。
- [ ] Esc 可取消编辑，不写入。
- [ ] 权限：有编辑权限的角色可改；viewer 看不到铅笔图标，点标题也不进编辑态；服务端对越权改名返回 403。

## 7. 备注
- 与 REQ-025 一致：系统编号仅隐藏显示、数据保留 —— 详情页、接口、列表默认排序、**导出封面页（REQ-021）** 仍然用它。导出是给客户/存档的正式文件，编号在那里有意义，不一并去掉。
- 服务端新增 `renameProject` action：`canMeta` 权限、非空、上限 120 字，并在项目日志里记一条「项目更名：旧 → 新」。

## 追加：界面上全面隐藏编号（2026-09-29）

REQ-025 / REQ-028 当初只拿掉了项目列表和项目详情两处，编号仍散在别的界面里。0928 处理项目档案那列棕色数字时暴露出问题：档案上挂着一个 158，翻到项目里哪都找不到它，看着像两套编号。当时把档案那列去掉了；这次把剩下的界面也一并收齐。

**已隐藏（界面）：**

| 位置 | 原来 |
| --- | --- |
| 我的待办 | 工作流待办行、任务行、右侧项目卡 三处 |
| 总览 · 进行中项目抽屉 | 项目名前的棕色编号 |
| 总览 · 未解决风险抽屉 | 每行项目名前的棕色编号 |
| KPI 看板 · 项目明细 | 项目名前的 `编号 · ` |
| 项目档案（0928 已做） | 左侧那列棕色数字 |
| 项目列表 / 项目详情（REQ-025/028 已做） | 标题前缀 |

**仍然保留（都是文档与文件，不是界面）：**

- 导出封面页与导出文档的抬头、「项目编号」那一行（REQ-021 / REQ-028 的原口径：导出是给客户和存档的正式文件，编号在那里有意义）
- Job Record 导出的抬头、CSV 内容与文件名
- 日历排期导出的 `.ics` 事件标题与文件名

**另外两处界面上的编号，本次有意保留：**

1. **Job Record 顶部「同步自项目创建」只读表里的「项目编号」一行。** 全拿掉的话，导出文件上印着 001，系统里就再也查不到 001 是谁 —— 那恰好是 0928 那个抱怨的镜像。这张表的用途就是「这个项目的基本事实」，编号留在这里是唯一一个能反查的地方。
2. **复制项目 / 套用片段时的「来源项目」下拉。** 编号在这里是用来区分同名项目的，去掉之后同名项目就分不清了。

数据一如既往地保留（`project.serial`），只是不显示。
