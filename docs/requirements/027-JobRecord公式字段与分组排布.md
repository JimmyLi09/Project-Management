# 需求：Job Record 公式（计算）字段 + 字段分组 / 两列排布

- **需求编号**：REQ-027
- **标题**：资料卡公式字段 + 字段分组与两列排布
- **所属系统**：Project-Management
- **状态**：已确认
- **创建日期**：2026-08-11
- **优先级**：P2 · 0811 UI 批次

> **与 REQ-023 的关系**：REQ-023（字段增减 / 改名 / 换类型 / 拖动排序 / 必填 / 恢复默认，按服务类型同源）**已于 2026-08-11 开发并合入 main**。本条是其后续增补 —— 0811 UI 批次里新提的「公式字段」与「分组 / 两列排布」两项当时不在 REQ-023 范围内，故另立编号跟踪，避免改写一份已交付的需求文档。

## 1. 背景
REQ-023 让字段可以自己增减了，但两件事还没解决：

1. **算不了。** LED 的面积（`L × H ÷ 1000000`）、数量合计（`数量L × 数量H`）这类值现在只能手算再填进去，容易错、改了尺寸也不会跟着变。
2. **排布太散。** 字段是一长条竖着排的，尺寸、数量、计算结果这些本该挨在一起的字段被拉得很远，看一眼对不上。

## 2. 目标
① 新增**公式字段**类型：值 = 一个用户自己填写、可随时改的表达式，引用同一张资料卡里的其它字段；查看态只读显示计算结果，被引用字段一变就重算。
② 字段可**分组**、可**两列排布**，让相关字段归成一块。

## 3. 范围

**做：**
- 字段类型增加「公式」。在「增减字段」里为该字段填写表达式，例如 `L * H / 1000000`。
- 表达式支持：四则运算 `+ - * /`、括号、数字常量，以及引用同一服务类型下其它字段的 key。
- 结果按数字显示，可设小数位数（默认 2 位）。
- 查看态与编辑态均**只读**（公式字段不接受手工输入），被引用字段修改后即时重算。
- 表达式非法（语法错、引用了不存在的字段、除以零、循环引用）时：保存前给出明确提示、不允许保存；已存在的坏公式在显示处降级为「—」并标注原因，**不得让页面崩掉**。
- 字段可设置分组名；同组字段在资料卡里聚在一起，组内支持两列排布。
- 沿用 REQ-023 的同源规则：定义按服务类型生效，Job Record 与「项目档案」登记表一致。

**不做：**
- 不内置写死任何 service 的具体公式（一律由用户在界面里设置）
- 不做跨服务类型 / 跨项目的引用
- 不做函数库（SUM / IF 等），本期只有四则运算与括号

## 5. 验收标准
- [ ] 字段类型下拉里有「公式」。
- [ ] 可在字段设置里填写与修改表达式，引用其它字段的 key。
- [ ] 保存后，该字段在 Job Record 与项目档案中显示计算结果，且为只读。
- [ ] 修改被引用字段的值，公式结果即时重算，无需刷新。
- [ ] 表达式语法错 / 引用不存在的字段 / 循环引用 → 保存时被拦下并给出可读的错误说明。
- [ ] 除以零、被引用字段为空或非数字 → 显示「—」，不报错、不崩页。
- [ ] 可给字段设置分组名，同组字段聚在一起，组内可两列排布。
- [ ] 老数据兼容：没有公式字段的服务类型显示不变。

## 7. 备注（实现约束）
- **表达式绝不能用 `eval` 或 `new Function` 执行。** 公式由用户输入并对该服务类型下所有项目全局生效，用 `eval` 等于给任何能改字段的人一个在所有人浏览器里执行任意代码的入口。必须自己写一个只认「数字 / 字段 key / `+ - * / ( )`」的小解析器，遇到别的字符直接判非法。
- **循环引用必须在保存前查出来**（A 引用 B、B 又引用 A）。不查的话渲染时会无限递归，直接把页面卡死。
- 公式与分组信息存在服务类型的字段 schema 上（`record_fields` 表，REQ-023 已建），与字段定义同一份；字段值仍挂在各项目的 record 上。
- 公式字段是**派生值，不落库** —— 每次渲染时算，避免存下来之后和源字段对不上。
