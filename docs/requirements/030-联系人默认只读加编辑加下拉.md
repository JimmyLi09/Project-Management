# 需求：项目详情·联系人默认只读展示 + 编辑按钮 + 关键字段下拉

- **需求编号**：REQ-030
- **标题**：联系人区默认只读展示，点「编辑」才可改，关键字段改下拉选择
- **所属系统**：Project-Management
- **状态**：已确认
- **创建日期**：2026-09-02
- **优先级**：P2 · 0902 批次

## 1. 背景
项目创建后，项目详情右侧「联系人」区目前一进来就是一堆输入框（客户 / 公司 / 建筑师 / 角色 / 电话 / 邮箱都是可编辑态），容易误改、也显得杂乱（图2 红框处）。另外「角色」这类有固定选项的字段现在是手填，应该给下拉选。

## 2. 目标
① 联系人区默认「只读展示」：只显示已填的联系人信息，不显示输入框。
② 增加「编辑」按钮：点了才进入编辑态，可改 / 增 / 删联系人；有保存 / 取消。
③ 关键的可选字段（如「角色 / Role」：客户 / 总包 / 建筑师 / 景观 等）改成下拉选择，而不是纯手填。

## 3. 范围
**做：**
- 查看态（默认）：联系人以展示方式呈现（客户名、公司、联系人姓名、电话、邮箱、角色等以文本展示），无输入框、无删除按钮。无联系人时显示占位 + 一个进入编辑的入口。
- 编辑态：点「编辑」后，字段变为可编辑输入框，可添加联系人 / 删除联系人 / 修改字段；出现「保存 / 取消」，保存才写入（服务端仍照常校验）。
- 关键字段下拉：至少「角色 / Role」改为下拉选择（选项如 客户 Client / 总包 Main-con / 建筑师 Architect / 景观 Landscape / 其他，允许「其他」时可手填）；其余带固定选项的字段一并下拉化。
- 与信息清单的只读 / 编辑交互保持一致的观感（对齐已上线的 REQ-005 默认只读思路）。

**不做：** 不改联系人的数据结构与保存接口（纯前端交互模式 + 展示态）；不做联系人字段的自定义增减；下拉选项本期用固定枚举，不做后台可配置选项库（如需要另提）。

## 5. 验收标准
- [ ] 进入项目详情，联系人区默认是只读展示，不是一排输入框。
- [ ] 有「编辑」按钮；点后进入编辑态，可改 / 增 / 删联系人，有保存 / 取消；保存后刷新保持。
- [ ] 查看态不能直接改字段、不显示删除按钮。
- [ ] 「角色 / Role」等关键字段为下拉选择；选「其他」时可手填。
- [ ] 老数据兼容：已有联系人正常以展示态显示，可正常进入编辑。
