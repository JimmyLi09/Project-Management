# 需求：同一项目多业务共用一张信息清单

- **需求编号**：REQ-044
- **标题**：同一项目下多个服务包（CGI 静帧 / 3D VR / 沙盘模型 / Drone / 动画…）共用一张信息清单，服务标签只做筛选
- **所属系统**：Project-Management（项目协作台 · 信息清单）
- **状态**：已实现（预演 #77，功能 #78，2026-10-02）
- **创建日期**：2026-10-01
- **优先级**：P1 · 0924 批次
- **来源**：`Progress comments - 0924.docx` 第 1 条「同一个项目，不同业务的资料同步更新」，截图：项目 CGI 静帧 / 沙盘模型标签；159-Tan Boon Liat Drone Service 待处理项。1001 Jimmy 确认：**整张清单共用**。
- **原型**：`Audax_0924反馈_原型_v1.html` →「① 共用信息清单」

## 1. 现状（查代码确认）
- 清单存在每个服务包里：`packages[i].checklist`（`types.ts:185-207`）。加服务包时把该服务模板**整份复制**一份（`project.ts:64-83`）。所以 Siteplan、最终 CAD 这类各业务都要的资料，CGI 一份、沙盘一份，**彼此不相通**：在 CGI 里收到 CAD 并确认，沙盘那边还是「未开始」。
- 顶部「完成率 / 待处理项 / 已逾期」只算当前标签（`ChecklistTab.tsx:57-68`）；项目总览的 `infoProgress` 把所有包相加，重复项会**算两次**。
- 所有清单操作用「包序号 + 组序号 + 项序号」定位（约 15 个 action + `ItemReceipts`），不是用 id。
- 阶段徽章 1 售前 → 5 开票/收尾已经是项目级（`projStage`），不受影响。

## 2. 目标
一个项目只有**一张信息清单**。在任一服务标签下收到、确认、备注、上传参考图、记收料记录，所有用到这一项的服务都同步看到。服务标签只是筛选：看「这个业务需要哪些资料」。

## 3. 功能说明

### 3.1 数据
- 清单从服务包上移到项目：`project.checklist: ChecklistGroup[]`。每项新增 `svcs: string[]`（这一项哪些服务需要，如 `['cgi','model']`）。
- 项内字段不变（status、date、remark、received、shots、owner、highlight、receipts[] 等），REQ-042 的多条收料记录照旧。
- 所有清单操作改为**按项 id 定位**（不再用序号），避免筛选后错位。

### 3.2 界面
- 服务标签行最前面加「**全部**」，后面是各服务（CGI 静帧 / 3D VR/720 / 沙盘模型 / 其他 Drone / 其他 Animation…），默认停在「全部」。
- 选某个服务 = 只显示 `svcs` 含它的项；分组标题照旧。
- 多个服务共用的项，名称右侧显示小标签「共用 · CGI · 沙盘」。在任一标签下改，其它标签**立即**是同一个状态（本来就是同一条数据）。
- 顶部三张卡（完成率 / 待处理项 / 已逾期）按**当前筛选**计算，卡片下的小字写明范围：「全部服务合计」或「CGI 静帧」。项目总览 / 项目列表的进度用整张清单计算，**每项只算一次**。
- 「增减信息项」：新增项时勾选适用的服务（默认 = 当前标签；在「全部」下默认勾全部服务）。也可以给已有项增减服务标签。

### 3.3 模板与导入
- **新建项目 / 加服务包**：把该服务模板的项并入共用清单。**同名项不重复**，只给已有项加上这个服务标签。同名判断：去掉空格、标点、大小写后中文名或英文名相同；再加一张可维护的「同义项」对照（如「最终 CAD + 3D 模型」≈「最终 CAD + SKP」），PD / BD 在模板管理里维护。
- **删除服务包**：只移除该服务标签；某项不再属于任何服务时，进入「已移除的项」（可恢复），**不直接删除**。
- **套用模板 / 从项目导入 / 存为模板**：作用于当前标签对应服务的项；在「全部」下作用于整张清单（存为模板时会带上每项的服务标签）。
- **无固定分类**：改为项目级开关。
- **导出清单**：导出一张表，多一列「适用服务」；可按当前筛选导出。
- **内部收料记录**：同样随筛选，记录本身只有一份。

### 3.4 旧数据迁移（一次性，上线时自动跑）
1. 迁移前把每个项目原来的 `packages[].checklist` 原样备份到项目里的 `checklistLegacy`（可回退）。
2. 各包的项按 3.3 的同名规则合并成一条，`svcs` = 出现过的服务。
3. 合并冲突取值：
   - 状态取**最靠后**的（已确认 > 已收到 > 待处理 > 未开始；N/A 只有在所有来源都是 N/A 时才保留）。
   - 收到日期取最新；负责人取第一个非空。
   - 备注不同时**都保留**，前面标来源服务：「[CGI] …」「[沙盘] …」。
   - 参考图、收料记录（receipts）合并，按时间排序，去掉完全相同的。
4. 迁移报告写到 `data/migrations/044-checklist-merge-<时间>.md`：每个项目合并了哪些项、哪些有冲突，便于 PD 抽查。

## 4. 验收标准
- [ ] 同时有 CGI 静帧和沙盘模型的项目：在 CGI 标签把「最终 CAD」改为已确认 → 切到沙盘标签，同一项已确认，收料记录相同。
- [ ] 「全部」标签显示整张清单，共用项只出现一次并带「共用 · …」标签。
- [ ] 三张卡随筛选变化，小字写明范围；项目列表进度不再重复计算。
- [ ] 加一个新服务包：同名项不重复，只多一个服务标签；删服务包不丢数据。
- [ ] 旧项目迁移后数据完整：对比迁移报告抽查 3 个多服务项目，已确认的项没有被降级，收料记录没有丢失；`checklistLegacy` 存在。
- [ ] 导出清单有「适用服务」列。
- [ ] REQ-043 权限不变（PM / Engineer 只能编辑自己的项目）；所有新文案中英两套。

## 5. 不做
- 不改排期（排期仍按服务包，见 REQ-046 / 047）。
- 不做跨项目共用资料。

## 6. 迁移预演（#77，先于功能合并）
生产库只在内网，不上 Vercel。所以「用生产库副本先跑一遍」放在服务器上做：#77 只加预演工具和合并规则，**不改网站任何行为**。合进 main 并更新服务器后，跑 `scripts\req044-dryrun.bat`：
- 用 SQLite 在线备份把 `data\audax.db` 复制到 `data\migrations\044-dryrun-<时间>.db`，只在副本上合并，正式库不动（网站开着也能跑）；
- 报告写到 `data\migrations\044-checklist-merge-dryrun-<时间>.md`：每个项目合并了哪些项、冲突怎么取值、自检结果（没丢项、已确认没降级、收料记录 / 参考图一条不少）。

PD 按报告抽查 3 个多服务项目，没问题再合功能 PR。合并规则（`src/lib/checklistMerge.ts`）上线迁移和预演用同一份。

预演时定下的两点细则：
- **同一种服务有两份**（如「大堂 LED」「户外 LED」）时，两份里重名的项**不合**（两块屏各有各的尺寸、电源），第二份的那一项名字后加实例名，如「电源规格与位置（户外 LED）」。
- **默认同义项**（PD / BD 之后可在模板管理里改）：最终 CAD + 3D 模型 ≈ 最终 CAD + SKP + 平面/立面/屋顶 ≈ 确认 3D 模型 & CAD；场地竖向；彩色总平；种植布局；景观材料；灯光布局；单元户型平面；立面图；非 ID 木作与固定件；材料表；地址 + 联系人。宁少勿多 —— 合错了比没合上更难发现。

## 7. 落地说明（#78）
- **数据**：`project.checklist`（每项 `svcs`），项目级 `noCategories`；服务包上的 `checklist` 只在迁移前的老数据里有。新增 `checklistRemoved`（已移除的项）。同一种服务有两份时，只属于第二份起那一份的项记 `inst`（实例名）。
- **按 id 定位**：清单项的所有操作（状态、内容、备注、负责人、重点、参考图、收料记录、移动、拖动、删除、改服务标签、恢复）都按项 id；分组按它在整张清单里的序号。没刷新的旧页面发来按序号的操作，后端回「请刷新页面后再操作」，不会改错项。
- **界面**：
  - 服务标签行「全部」在最前、默认选中；只有一项服务的项目不显示这一行。
  - 选某个服务只显示适用它的项；一项都没有的分组不显示。
  - 共用项名字后有「共用 · CGI 静帧 · 沙盘模型」；在任一标签下改共用项，提示「已同步到 …」。
  - 三张卡按当前筛选算，小字写范围；项目总览「信息确认」按整张清单、每项只算一次。
  - 「增减信息项」：每项下勾「适用服务」（至少留一个）；「添加信息项」时勾适用服务，默认 = 当前标签，「全部」下 = 全部服务；新栏目同理。
  - 删项、删分类不再直接删，进「已移除的项」（在「增减信息项」模式下最下面），可恢复。
  - 内部收料记录随筛选，记录只有一份。
- **模板与导入**：
  - 新建项目 / 加服务包：各服务模板并成一张，同名 / 同义项只出现一次，只多一个服务标签。
  - 删服务包：只去掉服务标签；不再属于任何服务的项进「已移除的项」。同一种服务还剩别的份时标签保留，只移走那一份的专属项。
  - 套用模板 / 恢复默认 / 从项目导入：作用于当前标签对应服务的项（覆盖时只换掉这个服务的专属项，共用项保留内容、重新挂标签）；「全部」下作用于整张清单。存为模板存当前标签那一段，每项带服务标签。
  - 无固定分类改为项目级开关。
  - 导出清单是一张表，多一列「适用服务」；从某个服务标签点导出时默认只勾这个服务。
  - 复制项目：带清单骨架和服务标签，不带内容、迁移备份、已移除的项（和原来一致）。
- **同义项**：模板管理最下面「信息清单 · 同义项」，一行一组用 ≈ 隔开，PD / BD 可改，可恢复默认；只影响之后的合并。
- **迁移**：服务每次启动检查一遍，只处理还是老结构的项目；规则和预演工具同一份代码。预演时发现并修好一处：合并后行上的「收到内容 / 日期」要跟合并后最新的一条收料记录走（REQ-042 的约定），否则下次在行上改状态会把文件名写进另一个服务收的那条记录。
- **回退**：`scripts\req044-rollback.bat` 把共用清单按服务标签拆回各服务包（共用项每个服务包各一份），先自动备份数据库；以后再升级会重新合并。也可以用更新前的快照整库回退。
- **测试**：单元测试 120 项；端到端 49 项（用旧版本代码造的老结构库启动新版本：迁移报告、抽查 3 个多服务项目无降级 / 无丢记录、§4 每一条、加删服务、恢复、导入 / 恢复默认、同义项、新建 / 复制、中英文案）；另测了「迁移 → 拆回 → 再升级」来回一遍自检全过。
