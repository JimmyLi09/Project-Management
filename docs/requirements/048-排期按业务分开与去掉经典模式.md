- **所属系统**：Project-Management（项目协作台 · 排期）
- **状态**：已实现（#94，2026-10-09；落地说明见 §4）
- **创建日期**：2026-10-12
- **优先级**：P1 · 1009 批次
- **来源**：`Progress comments - 0924.docx`（1009 更新版）第 3、4 条。原型 `Audax_1009优化_全流程原型_v2.html` →「项目详情 · 排期」，JM 1012 确认。
- **关联**：REQ-040（日历排期）、REQ-046（右侧选日期）、REQ-047（按服务取默认阶段）。本需求取代 REQ-047 里 CGI 的阶段和周数。

## 1. 现状（查代码确认）
- 排期页有两套并存的东西：
  - 视图切换「经典 / 日历」（`ScheduleTab.tsx:34-36`，本地状态）；
  - 模板样式 `p.schedStyle = classic | weeks | dates`（`types.ts:297`，`ScheduleTab.tsx:142-154`）。
- **经典模式**用 `pkg.schedule`（阶段行），**日历**用 `pkg.calendar`（边界）。两份数据**不同步**：`saveCalendar` 只写交付日期（`actions.ts:644-688`）。
- 其他功能**都只读 `pkg.schedule`**：
  - 我的待办（`MyTasksView.tsx:46`）、侧栏数字（`App.tsx:171`）；
  - KPI（`kpi.ts:137`）、团队负载（`alloc.ts`）、积分（`points.ts`）、可见性（`permissions.ts:44`）；
  - 总览 / 报表、项目列表、导出（`ExportOverlay.tsx`）、复制项目（`fragments.ts`）。
- 所以**直接删掉经典模式会让这些功能失去数据**，必须先把日历写回阶段行。
- 当前 CGI 默认是 REQ-047 的 5 步（0 / 2 / 2 / 2 / 1 周，`templates.ts:82-92`）；动画仍是旧的 6 步（`templates.ts:129-137`）。

## 2. 功能说明

### 2.1 新默认阶段（第 3 条）——只是默认值

| 业务 | 阶段 | 默认 |
|---|---|---|
| 效果图 CGI | A. Angle stage：出 wireframe 草图，筛选 shortlist 角度 | 2 周 |
| | B. Mood & angle stage：每个角度出氛围图，确认角度与氛围 | 2 周 |
| | C. Material & model stage：微调模型与材质，最终确认 | 2 周 |
| 动画 | A. Storyboard stage：PM 出整体分镜（收到资料后） | 1 周 |
| | B. Animation preview：整体相机路径 + 内部讨论，第 1 轮预览 | 2 周 |
| | C. Still frame stage 1：各场景氛围静帧 | 1 周 |
| | D. Still frame stage 2：确认所有模型与材质细节 | 2 周 |
| | E. Post production | 1 周 |

- 中英文名都按上表（英文用 JM 原文）。
- **只是默认值**：
  - 每个项目的每个阶段都可以改工期（天数），也可以改起止日期；改了后面的阶段自动顺延。
  - 改过的阶段显示「已改 · 默认 2w」，不影响模板。
  - PD / BD 在「模板管理」里改默认周数，只影响之后新建的业务。
- 已有项目的排期不自动改，沿用 REQ-047 的「要换成新阶段吗？」提示（动画也加上这个提示）。

### 2.2 每个业务一份排期（第 4C 条）
- 排期页顶部是业务标签：「全部业务 · 总览」/ 效果图 / 动画 / 沙盘…（同一业务两份时显示「LED-1 / LED-2」）。
- **总览**：甘特图，每个业务一行，显示各阶段色块和今天线。
- **单个业务**：该业务自己的阶段列表，每行有开始 / 结束日期框和工期（REQ-046），以及「恢复默认阶段」按钮（按该业务的模板）。

### 2.3 去掉「经典模式」（第 4D 条）
- 排期页只保留这一种视图（日历 + 阶段列表 + 总览），去掉「经典 / 日历」切换和 `schedStyle` 的三种样式选择。
- **日历保存时同步写回 `pkg.schedule`**：每个阶段对应一行，写入阶段名、开始、结束、负责人、状态。待办、KPI、负载、报表、导出这些功能继续读阶段行，**不改读取方**。
- 经典模式独有、还在用的功能要搬进新视图：
  - 阶段负责人：每个阶段行加负责人选择，供「我的待办」和团队负载使用；
  - 阶段状态（未开始 / 进行中 / 完成）；
  - 导出排期；
  - 从项目导入排期（FragmentBar）；
  - 交付日历。
- 「特殊行」和「范围项」如果还有在用的数据，原样显示成只读的备注区；没有数据就不显示。
- **旧数据迁移（上线时一次性）**：只有经典阶段行、没有日历的业务，用阶段行的日期生成日历边界。负责人、状态、备注都保留。迁移报告写到 `data/migrations/048-schedule-<时间>.md`。

## 4. 落地说明

- **新默认阶段**（`templates.ts`）：
  - 效果图 3 段（Angle / Mood & angle / Material & model，各 2 周），动画 5 段（Storyboard / Animation preview / Still frame stage 1 / Still frame stage 2 / Post production，1 / 2 / 1 / 2 / 1 周）。中文名按 §2.1 的表，英文用 JM 原文。
  - 取代 REQ-047 的效果图 5 步。只影响之后新建的业务；PD / BD 在模板管理改周数也一样。
- **工期按项目可改**：
  - 阶段列表每行有「工期」框（天数）。改了这一段的结束日跟着变，后面各段整体顺延，工期不变。和默认不一样的标「已改 · 默认 2w」。
  - 天数的单位跟日历上的 Exclude Holidays 走：不勾是日历天，勾了是工作日。
  - **新建业务默认按日历天排**（1 周 = 7 天；**1010 Jimmy 确认**）：和原来经典排期一样，也符合 §3「改成 21 天 → 后面顺延 7 天」。需要排除周末 / 公众假期的，在那份排期上勾 Exclude Holidays。
- **每个业务一份排期**：
  - 顶部业务标签：「全部业务 · 总览」/ 各业务（同类两份显示「LED-1 / LED-2」）。从「排期」标签点进来，多个业务时先看总览。
  - 总览是甘特图，一行一个业务，各阶段一段色块，红线是今天，点一行进那个业务。
  - 单个业务依次是：
    - 一栏「排到 / Buffer / 本服务负责 / 项目交付日 / 富余或超期」；
    - 「从项目导入排期」；
    - 这个业务的甘特图，即原来的「交付日历」；
    - 日历排期：月历 + 阶段列表，阶段列表每行有开始 / 结束日期、工期、负责人、状态，下面有「恢复默认阶段」；
    - 资料链接。
  - 「提交完工」卡片在排期页底部，两种视图都有。以前它只在经典模式里，PM 用日历排期时看不到。
- **去掉经典模式**：
  - 没有「经典 / 日历」切换，也没有排期页上的三种样式。样式挪到「导出排期」里选（阶段表 / 按服务分组 / 按日期，默认沿用项目上次用的那种）。
  - FragmentBar 里那两个「参考模板（样式）」去掉了；要回到默认阶段，用「恢复默认阶段」。
- **日历保存时写回阶段行**（`lib/scheduleSync.ts`）：
  - 对应关系：一个阶段对应一行，阶段 id = 行 id。
  - 写回的内容：阶段名（中 / 英）、开始、结束、备注、周数。周数按日历的单位折：不勾 Exclude Holidays 时 7 天一周，勾了 5 个工作日一周。
  - 负责人、状态在行上，阶段列表里直接改，不用等保存。
  - 我的待办、KPI、团队负载、积分、报表、导出、复制项目，**读取方一个没改**。
  - 日历上删掉的阶段：那一行有内容（负责人、状态、备注）的挪到「留底的阶段行」（只读，可展开看），没内容的直接去掉。
  - 「已处理」的风险是按行号记的，行顺序变了就按行 id 对到新行号。
  - 新建业务、加业务、导入排期、复制项目时都同步生成日历；读项目时没有日历的也按阶段行补一份（兜底）。
- **特殊行 / 临时节点 / 服务内容**：里程碑、假日横幅、临时插入的节点不是阶段，原样留在行里（待办、导出照旧读得到），排期页上只读列出来。服务内容（范围项）有数据才显示，只读。
- **「要换成新阶段吗？」**：
  - 已有项目的排期不自动改。只要阶段名还是某一版老模板的原样（老效果图 6 步、REQ-040 日历的 6 阶段、REQ-047 的 5 步、老动画 6 步），就提示一次。动画也有这个提示。
  - 换的话：首日、末日不变，按新阶段的默认工期分配；阶段行一起换。原来整份排期只有一个负责人的，新阶段也给他。
  - 可撤销：阶段和阶段行都原样换回。
- **上线迁移**（`lib/mig048.ts` + `server/db.ts`，一次性）：
  - 先把整个库备份成 `data/backups/pre-req048-<时间>.db`，再在一个事务里改，报告写到 `data/migrations/048-schedule-<时间>.md`。三种情况：
    - **只有经典阶段行**（绝大多数）：用行上的日期生成日历，行一个字不动。原来 0 周、没日期的阶段（多是「信息收集」）在日历上各给 1 天，排在第一个有日期的阶段之前。原来有重叠 / 空档的行在报告里列为「日期调整」：下次在日历上保存时以日历为准，保存前行上的日期不变。
    - **只在日历上排过、行还是模板原样**：用日历重写行，原来的行留底。
    - **两边都有内容**：以行为准（待办、KPI 读的是它）重建日历，原来的日历放进「存档」，一点就能载回。
  - 模板管理里效果图 / 动画的排期如果是某一版老出厂模板原样，换成新默认阶段（信息清单不动）；改过的不动，报告里提一句。
  - 用 REQ-052 之后的库造了「上线前」的样子实测过：三种情况都对上，原有阶段行一个字没动。
- **回退**：`scripts\req048-rollback.bat`。
  - 不带参数只报告，加 `--apply` 才写库。写库前先备份，并出报告。
  - 迁移生成的日历如果上线后没再保存过就删掉，重写过的行换回原来的，换掉的日历换回，模板换回，最后清掉迁移标记。
  - 上线后在日历上保存过的那几份留着，在报告里列出来。
- **权限**：排期「不可见」的角色，日历的阶段名、备注、存档和留底行也不下发（REQ-051 那一层补上）。
