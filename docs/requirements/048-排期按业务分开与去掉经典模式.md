- **需求编号**：REQ-048
- **所属系统**：Project-Management（项目协作台 · 排期）
- **状态**：已确认
- **创建日期**：2026-10-12
- **优先级**：P1 · 1009 批次
- **来源**：`Progress comments - 0924.docx`（1009 更新版）第 3、4 条。原型 `Audax_1009优化_全流程原型_v2.html` →「项目详情 · 排期」，JM 1012 确认。
- **关联**：REQ-040（日历排期）、REQ-046（右侧选日期）、REQ-047（按服务取默认阶段）。本需求取代 REQ-047 里 CGI 的阶段和周数。

## 1. 现状（查代码确认）
- 排期页有两套并存的东西：
  - 视图切换「经典 / 日历」（`ScheduleTab.tsx:34-36`，本地状态）；
  - 模板样式 `p.schedStyle = classic | weeks | dates`（`types.ts:297`，`ScheduleTab.tsx:142-154`）。
- **经典模式**用 `pkg.schedule`（阶段行），**日历**用 `pkg.calendar`（边界）。两份数据**不同步**：`saveCalendar` 只写交付日期（`actions.ts:644-688`）。
- 其他功能**都只读 `pkg.schedule`**：
  - 我的待办（`MyTasksView.tsx:46`）、侧栏数字（`App.tsx:171`）；
  - KPI（`kpi.ts:137`）、团队负载（`alloc.ts`）、积分（`points.ts`）、可见性（`permissions.ts:44`）；
  - 总览 / 报表、项目列表、导出（`ExportOverlay.tsx`）、复制项目（`fragments.ts`）。
- 所以**直接删掉经典模式会让这些功能失去数据**，必须先把日历写回阶段行。
- 当前 CGI 默认是 REQ-047 的 5 步（0 / 2 / 2 / 2 / 1 周，`templates.ts:82-92`）；动画仍是旧的 6 步（`templates.ts:129-137`）。

## 2. 功能说明

### 2.1 新默认阶段（第 3 条）——只是默认值

| 业务 | 阶段 | 默认 |
|---|---|---|
| 效果图 CGI | A. Angle stage：出 wireframe 草图，筛选 shortlist 角度 | 2 周 |
| | B. Mood & angle stage：每个角度出氛围图，确认角度与氛围 | 2 周 |
| | C. Material & model stage：微调模型与材质，最终确认 | 2 周 |
| 动画 | A. Storyboard stage：PM 出整体分镜（收到资料后） | 1 周 |
| | B. Animation preview：整体相机路径 + 内部讨论，第 1 轮预览 | 2 周 |
| | C. Still frame stage 1：各场景氛围静帧 | 1 周 |
| | D. Still frame stage 2：确认所有模型与材质细节 | 2 周 |
| | E. Post production | 1 周 |

- 中英文名都按上表（英文用 JM 原文）。
- **只是默认值**：
  - 每个项目的每个阶段都可以改工期（天数），也可以改起止日期；改了后面的阶段自动顺延。
  - 改过的阶段显示「已改 · 默认 2w」，不影响模板。
  - PD / BD 在「模板管理」里改默认周数，只影响之后新建的业务。
- 已有项目的排期不自动改，沿用 REQ-047 的「要换成新阶段吗？」提示（动画也加上这个提示）。

### 2.2 每个业务一份排期（第 4C 条）
- 排期页顶部是业务标签：「全部业务 · 总览」/ 效果图 / 动画 / 沙盘…（同一业务两份时显示「LED-1 / LED-2」）。
- **总览**：甘特图，每个业务一行，显示各阶段色块和今天线。
- **单个业务**：该业务自己的阶段列表，每行有开始 / 结束日期框和工期（REQ-046），以及「恢复默认阶段」按钮（按该业务的模板）。

### 2.3 去掉「经典模式」（第 4D 条）
- 排期页只保留这一种视图（日历 + 阶段列表 + 总览），去掉「经典 / 日历」切换和 `schedStyle` 的三种样式选择。
- **日历保存时同步写回 `pkg.schedule`**：每个阶段对应一行，写入阶段名、开始、结束、负责人、状态。待办、KPI、负载、报表、导出这些功能继续读阶段行，**不改读取方**。
- 经典模式独有、还在用的功能要搬进新视图：
  - 阶段负责人：每个阶段行加负责人选择，供「我的待办」和团队负载使用；
  - 阶段状态（未开始 / 进行中 / 完成）；
  - 导出排期；
  - 从项目导入排期（FragmentBar）；
  - 交付日历。
- 「特殊行」和「范围项」如果还有在用的数据，原样显示成只读的备注区；没有数据就不显示。
- **旧数据迁移（上线时一次性）**：只有经典阶段行、没有日历的业务，用阶段行的日期生成日历边界。负责人、状态、备注都保留。迁移报告写到 `data/migrations/048-schedule-<时间>.md`。
