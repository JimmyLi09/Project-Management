# 需求：KPI 看板 + KPI 规则设置（数据式、多维加权，每业务可配）

- **需求编号**：REQ-037
- **标题**：KPI 看板（四维加权自动算）+ KPI 规则设置（适用范围 / 权重 / 阈值 / 评分方式 / 版本）
- **所属系统**：Project-Management
- **状态**：已确认
- **创建日期**：2026-09-02
- **优先级**：P1 · 运营中心批次

## 1. 背景
现在没有客观的绩效视图。平台已沉淀积分、交付日 / buffer、售后工作流、项目 / 负载等数据，可据此自动算 KPI 达成。用户明确：KPI 用**数据式看板**；且**每个业务的评分标准可能不一样**，要能各自配置——因此除了看板，还要有一套**KPI 规则设置**来定规则。

## 2. 目标
① **KPI 看板**：按现有数据自动算每人 / 每角色的 KPI 达成度，四维加权，可按周期看。
② **KPI 规则设置**：可配置适用范围（角色 / 业务）、每维的权重 / 达标阈值 / 评分方式，改动留版本、带生效日。

## 3. 范围
**做：**

### A. KPI 看板
- **四个维度**（数据来源复用现有）：积分产出（复用积分机制，见 REQ-038）、准时交付率（交付日 / buffer / 逐期）、售后返工 / 审批通过率（售后工作流 PD 审批 / Sales 核对）、项目数量 / 负载。
- **视图**：按人 / 角色 / 业务展示各维得分 + 加权总分；可选周期（本月 / 本季 / 自定义）；可排序；点某人看四维明细（点开看每维怎么来的）。
- 看板页提供入口链接到知识库（REQ-035）里的「KPI 标准说明」文档。

### B. KPI 规则设置（本次新增，独立「规则设置」页内）
- **适用范围**：可按角色（PM / Sales / Model Maker …）和 / 或按业务（服务类型）配置——**每个业务可各自配**，切换业务时权重 / 阈值不同。
- **每维可配**：开关（是否计入）、权重 %、达标 / 满分阈值、**评分方式**（阈值满分 / 线性 / 分段）。
- **权重校验**：提示权重合计（建议 100%）。
- **版本化**：规则改动存为新版本、注明生效日，可回看。

**不做：** 不做薪酬 / 奖金联动；不做打分申诉流程；权重 / 阈值默认由总监配置，不做多级审批。

## 5. 验收标准
- [ ] KPI 看板按人 / 角色 / 业务展示四维得分 + 加权总分，数据来自系统现有机制（非人工录入）。
- [ ] 可切换周期（本月 / 本季 / 自定义），数据随周期重算；可排序；可看每人四维明细。
- [ ] 看板有入口链接到知识库「KPI 标准说明」。
- [ ] **KPI 规则设置**：可按角色 + 业务配置；每维可开关、设权重、设阈值、选评分方式（阈值满分 / 线性 / 分段）。
- [ ] 切换业务，权重 / 阈值各自独立；改规则后该业务算分随之变化。
- [ ] 规则改动存为新版本、带生效日、可回看。

## 7. 备注（含默认假设，如需调整请在 PR 指出）
- **每业务评分标准**是重点：权重 / 阈值挂在「服务类型」上（与项目档案 / Job Record 字段同源思路，参考 REQ-023）；未单独配置的业务走一套默认。
- 四维**具体口径**（准时＝最终交付日还是每期节点、返工如何界定）实现时按现有数据能力先给默认，PR 列明供确认。
- 「积分产出」维度的分值来自 **REQ-038 积分定义标准**；两者对齐。
- 与已上线 **REQ-011 总览 KPI 下钻** 区别：011 是总览三张组合卡的下钻；本条是人 / 角色绩效看板，二者并存。
- KPI 的「文档式标准说明」归 **REQ-035**；本条做「数据看板 + 规则设置」，通过链接打通。
