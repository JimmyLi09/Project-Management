# 需求：AV 方案成本平台 · 01 立项询价与 01→07 流程导航

- **需求编号**：REQ-012
- **标题**：01 立项询价（项目信息、业务线勾选、规则包绑定）+ 贯穿各步的流程导航
- **所属系统**：AV 方案成本平台
- **状态**：01 已实现；06 成本核算 / 合并总报价、07 报价审批待定（见第 5 节）
- **创建日期**：2026-09-25
- **优先级**：P1 · 对应规格书 §2.1「01 立项询价」、§5 版本锁定、原型 Main.dc.html / Summary.dc.html

## 1. 背景

原型 Main.dc.html 给出了 01 立项询价界面，Summary.dc.html 给出了 06「四条业务线合并总报价」。
规格书 v1.0 §2.1 把 01 列入本期，§2.2 把价格库、BOQ、成本核算、报价单、审批流以及投影 / 弱电 /
太阳能三条业务线列为「第二期 / 架构预留」。

## 2. 本期实现

| 部分 | 位置 |
| --- | --- |
| 01 界面（侧栏「AV 立项询价」） | `src/components/views/AvInquiryView.tsx` |
| 立项接口 `POST/GET /api/av/inquiry` | `src/app/api/av/inquiry/route.ts` |
| 询价记录表 `av_inquiry` | `src/server/avdb.ts` |
| 业务线清单 | `src/av/core/lines.ts` |
| 流程导航 01 → 07 | `src/components/views/AvSteps.tsx`，出现在 01、02–04、05 三个界面顶部 |

- 表单字段按原型：项目名称、客户 / 甲方、项目地点、期望交付日期、需求补充说明。
- 业务线：LED 显示屏、投影系统、弱电系统、太阳能光伏。**只有 LED 有已发布的规则包**，其余三条显示
  「规则包未发布 · 架构预留」且不可勾选；服务端同样拒绝。
- 立项即在现有项目体系中建项目（每条业务线一个服务包），并在同一事务中写入询价记录与**绑定的规则包
  版本**。项目操作记录写入「立项询价：LED 显示屏（规则包 led@1.0）」。
- **05 方案配置按项目绑定的规则包计算，并锁定选择器**（§5：历史项目锁定其创建时的版本）。未经 01 立项的
  老项目按最新规则包计算，界面有提示。
- 立项后直接进入该项目的「02–04 图纸 · 解析 · 校核」。
- 保留原型中的「立项提醒：优先索取 DXF 源文件」。
- 权限：立项 = 销售 / PD / BD（沿用现有「新建项目」权限）。
- 流程导航中 06、07 显示为「第二期」，不可点击。

## 3. 与原型的差异

- 原型显示 LED「规则包 v1.3」、投影「v1.0」；系统里实际发布的只有 `led@1.0`，界面显示真实版本。
- 原型 Main 的第三条业务线是「小区管理系统」，Summary 与规格书 §2.2 / §4 是「弱电系统」（前缀 `elv_`）。
  **本期按规格书采用「弱电系统」**，待确认。
- 原型页脚「草稿已自动保存」未实现（立项是一次提交）。
