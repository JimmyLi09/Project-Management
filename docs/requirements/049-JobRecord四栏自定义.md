# 需求：Job Record 改为 4 栏全自定义（Service Item / Detail / Quantity / Special Notes）

- **需求编号**：REQ-049
- **所属系统**：Project-Management（项目协作台 · Job Record / 项目档案）
- **状态**：已确认
- **创建日期**：2026-10-12
- **优先级**：P1 · 1009 批次
- **来源**：
  - `Progress comments - 0924.docx`（1009 版）第 7 条「增加的业务形态，需要跟基础需求对应」，附 Sales 报价表截图（Service Item / Detail / Special Notes）；
  - JM 1012 回复：「Job Record 里面信息都需要自定义，只需要保留 A. Service Item B. Detail C. Quantity D. Special Notes」；
  - 原型 v2 →「项目详情 · Job Record」。

## 1. 现状（查代码确认）
- 每种业务的 Job Record 字段来自 `records.ts:98-232` 的 7 个内置登记表（scale / projector / led / vrar / maxhub / av / others），另有 `record-fields` 接口让 PD / BD 覆盖字段。数据存在 `pk.record`（键值对）。
- 不在内置表里的业务（比如无人机）只有空定义，所以档案里只看到一个「Drone Service」文本框（`baseDefOf`，`records.ts:257`）。
- 导出 `JobRecordExport.tsx:29-31` 只导内置表，无人机这类业务**导不出来**。
- 导入接口拒绝非内置业务（`if (!registerDef(svc))`）。

## 2. 功能说明

### 2.1 一张 4 栏表
- Job Record 改为一张表，每行 4 栏：**Service Item / Detail / Quantity / Special Notes**，和 Sales 报价表一致。
- 行按业务分组：组标题显示业务名和份数（如「LED × 2」），每组有「＋ 加一行」。每行可以改、删；每个业务至少保留 1 行。
- **全部自定义，不预设明细**：
  - 加一个业务时，只新增一组 1 行，Service Item 预填业务的英文名（Perspectives / Animation / Scale Model / Drone & 360 IPM / LED Display…），其余留空。
  - Quantity 是文本，可以写「2」「180s」「1 set」「5 spots」。
- **从报价单粘贴**：在表上粘贴 Excel 复制的 4 栏（或 3 栏：Service Item / Detail / Special Notes），按行追加；Service Item 能对上已有业务的就归到那一组。

### 2.2 和登记表 / 其他功能的关系
- 原来各业务登记表字段（`pk.record`）**不删除**，在 Job Record 下方折叠显示为「旧字段（只读）」，供查历史。
- 「项目档案」、登记表页、CSV 导出读的都是这张 4 栏表，所有业务（含无人机等自定义业务）都能导出。
- **登记表导入**：识别 4 栏表头（Service Item / Detail / Quantity / Special Notes，中英都认），去掉「必须是内置业务」的限制。
- **旧数据迁移**：已有 `pk.record` 里有值的字段，每个字段转成一行（Service Item = 业务名，Detail = 字段名，Quantity / Special Notes = 字段值），原数据保留。迁移报告写到 `data/migrations/049-jobrecord-<时间>.md`。

## 4. 落地说明

- **数据**：
  - 每个项目一张 4 栏表 `p.jobRecord`。每行是 `{ 业务, Service Item, Detail, Quantity, Special Notes }`，四栏都是文本。
  - 页面按业务分组：先按项目里业务的顺序，同类两份显示「LED × 2」。
  - 删了业务、或者粘贴时对不上业务的行，单独成组：「项目里已没有这项业务」/「未对应业务」。这些行可以「归到业务…」或者删掉，不受「至少 1 行」限制。
  - 原来的 `pk.record`（旧登记表字段）和排期页的「服务内容」**一个不动**。
- **Job Record 页**（`JobRecordTab.tsx`）：
  - 上面是「项目信息」（只读，同步自项目），然后是 4 栏表，再往下是「这个项目的业务」。
  - 4 栏表每组有「＋ 加一行」，新行沿用这一组上一行的 Service Item。格子失焦即保存。
  - 删到最后一行会提示「每个业务至少保留一行」，服务端也拦。
  - 「这个项目的业务」可以加业务或删业务：
    - 加一个业务 = 加一组 1 行，Service Item 预填英文业务名，例如 Perspectives / Animation / Scale Model / Drone & 360 IPM / LED Display；排期和信息清单照常生成。
    - 删业务：只有 Sales / PD / BD 能删，和原来一样；这项业务的 Job Record 行留着，需要的话自己删。
  - 下方「旧字段（只读）」默认折叠，只列有值的业务。没有编辑、增减字段、删除按钮。
- **从报价单粘贴**：
  - 两种方式：在 Excel 里选中几栏复制后，直接在表上 Ctrl+V；或者点「从报价单粘贴」，贴进框里先预览再追加。
  - 认 4 栏（Service Item / Detail / Quantity / Special Notes），也认 3 栏（Service Item / Detail / Special Notes，没有 Quantity）。
  - 表头行自动跳过。Excel 单元格里的换行、引号原样保留。
  - 报价单里一组几行只在第一行写 Service Item 的（合并格），空着的接上一行的 Service Item。
  - 粘贴的行追加到对应那一组的末尾。归组方法：Service Item 对上项目里已有行的 Service Item，或者对上业务名。对不上的放进「未对应业务」。
  - 一组里如果只有那 1 行空白预填行，直接被粘贴的行顶掉。
- **下载**（`JobRecordExport.tsx`）：打印 / PDF 和 CSV 都是这张 4 栏表，所有业务都在（以前只导 7 个内置登记表，无人机这类导不出来）。
- **项目档案**（`RegistersView.tsx`）：
  - 改成汇总各项目的 4 栏表。页签是「全部业务」加上每种有行的业务，包括无人机这类自定义业务。
  - 4 个指标：项目数 / 行数 / 只有业务名的行（待填）/ 未对应业务的行。
  - 筛选：搜索（项目、客户、4 栏内容）、PM、客户、年份（交付年份，没有交付日的按建档年份）。
  - 每列都能排序；格子点一下就地改；可以导出 CSV。
  - 「新增一行」：选项目和业务后填 4 栏；项目里没有这项业务的，先给它加上。
  - 原来按业务的专属列、状态、「即将到期 / 已交付 / 资料不完整」指标、「增删列」都去掉了：现在内容全部是自定义文本，这些没法再算。
- **导入**（`/api/registers/<业务或 all>/import`，只有 PD / BD 能用）：
  - 认 4 栏表头，中英都认（Service Item / Detail / Quantity / Special Notes；服务项目 / 明细 / 数量 / 特别说明）。
  - 按「项目」名称或「项目编号」找项目。有「业务」栏的按它归组；没有的话，用当前页签的业务；页签是「全部业务」时按 Service Item 去对。
  - **不再限内置业务**。项目里没有这项业务的，先给它加一份（和原来的登记表导入一样）。
  - 全有或全无：任一行找不到项目、或认不出业务，整批都不写入。
  - 页面上先预览：总行数、能匹配的、找不到的项目。
  - 旧的 `{ rows: [{ project, patch }] }` 接口留着，照旧写旧字段，供脚本使用。
- **上线迁移**（`lib/mig049.ts` + `server/db.ts`，只跑一次）：
  - 先整库备份到 `data/backups/pre-req049-<时间>.db`，再在一个事务里改。报告写到 `data/migrations/049-jobrecord-<时间>.md`，每个项目转了几行、各业务几行。
  - 每份业务里有值的旧字段，一个字段转成一行：
    - Service Item = 业务英文名；
    - Detail = 字段名（中英）。同类两份的，前面带实例名或 ①②，例如「Showflat LED · Address 地址」；
    - 数量类的值进 Quantity（数字字段、叫数量的字段、像「2」「180s」「3 sets」的值），其余进 Special Notes。下拉字段转成选项名。
  - 字段定义里已经删掉、但值还存着的列，也照样转，字段名用存储的键。
  - 排期页「服务内容」（`scopeItems`：item / qty / note）本来就是报价单上的内容，一条转成一行。
  - 不转的：状态、更新时间、公式字段（由别的字段算出来）、和项目同源的字段（项目名称 / 客户联系人 / 交付日，存在项目上）。
  - 一个值都没有的业务，给 1 行预填业务名。
  - 新建、复制的项目，以及读项目时没有 4 栏表的，也都补上每种业务 1 行。
- **回退**（`scripts\req049-rollback.bat`）：
  - **退回旧版本代码不需要跑任何东西**：旧代码不认 4 栏表，照常显示旧字段。
  - 不带参数：只报告，并把全部 4 栏行导出成 CSV（`data\migrations\049-jobrecord-export-<时间>.csv`）。上线后录进 4 栏表的内容，旧版本里看不到，就靠这份 CSV。
  - 加 `--apply`：导出之后，再删掉 4 栏表和迁移标记，写库前先备份。以后重新上线会按旧字段再迁移一次。一般不需要这一步。
- **权限**（REQ-043 / 051 不变）：
  - 4 个新动作（加行 / 改行 / 删行 / 粘贴）都归「项目档案 / Job Record」模块。
  - 设成「不可见」的角色，服务端不下发 4 栏表，日志里 Job Record 的条目也不下发。
  - 设成「只读」的，表是纯文字，没有粘贴、加行、删除，直接调接口也被拒。
  - 自测时发现 REQ-051 有一个问题：页面在服务端渲染后，改了权限表服务端不生效。另提了 #95 修复，本分支含这个修复。
- **影响**：
  - 积分的自动判档（`points.ts`）读的还是旧字段，老项目照旧自动落档。
  - 新项目没有旧字段，判不出档时和以前一样，提示 PM 手选。
  - LED 方案配置带过来的几个数（REQ-039 的「配」标记）只在旧字段里看得到；4 栏表里需要的话自己填。
