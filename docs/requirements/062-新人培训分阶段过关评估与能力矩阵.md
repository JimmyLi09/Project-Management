## 1. 现状（查代码确认）
- `src/lib/training.ts`：一条路径 = 一串步骤（`doc` 读知识库文档 / `note` 说明）+ 一份测验。走完步骤且测验达到及格线（默认 80）就算通过。
- 没有先后限制，没有需要人打分的评估，没有带教人，没有「每个人每个业务到了什么程度」的记录。
- 指派项目负责 PM 在 `src/server/actions.ts` 的 `addOwner`，只校验权限（`canAssign`），不看能力。

## 2. 功能说明

### 2.1 几个概念
- **业务（7 个）**：效果图、动画、实体模型、VR · 720 · AR、Sales Kit、LED · 投影、中控。用 REQ-061 的 `bizMap`（不含「总览」和「其他业务」）。
- **级别（每人每个业务一个）**：

  | 值 | 级别 | 含义 |
  |---|---|---|
  | 0 | 未学 | |
  | 1 | 了解 | 讲得清这个业务的流程 |
  | 2 | 可协助 | 能在别人带的项目里负责节点；**可以当负责 PM** |
  | 3 | 可独立 | 独立带过项目并做过复盘 |
  | 4 | 可带教 | 可以带别人 |

- **带教人**：每个学员指定一位。可以当带教人的：PD / BD，以及 PM 级别为 Senior PM 或 PM Director 的人。由 PD / BD 指定。
- **PM 级别**：`users` 加一列 `pm_level`（`coord` Project Coordinator / `pm` PM / `senior` Senior PM / `director` PM Director / 空）。只有 PD / BD 能改。REQ-063 的 KPI 看板也用这个字段。
- **新人期**：PD / BD 或带教人给某个人「开始新人期」。上线前已有的 PM 默认不在新人期。

### 2.2 新人主线：分阶段过关

| 关 | 内容 | 建议完成 | 过关评估 | 过关后 |
|---|---|---|---|---|
| 关 0 入职定级 | 自评问卷 + 带教人面谈 | 第 2 天 | 带教人填定级结果 | 定新人期带哪 2 – 3 个业务、各业务的起步级别 |
| 关 1 基础认知 | 读 SOP Map、总览 A、总览 F；跟 2 次项目会议并写纪要（E2） | 第 7 天 | SOP 基础测验 + 讲解「一个项目从交接到交付怎么走」 | 解锁所选业务的关 2 |
| 关 2 业务了解（每个业务） | 读这个业务的 B、C、D 板块 | 第 21 天 | 业务小测验 + 讲解这个业务的完整流程 | 这个业务 → 了解 |
| 关 3 跟项目（每个业务） | 跟 1 个这个业务的真实项目 | 第 45 天 | 模拟接 brief + 模拟写邮件 | 这个业务 → 可协助 |
| 关 4 独立带项目（每个业务） | 协助 1 个项目（至少负责 2 个节点）；独立带 1 个 Coordinator 级项目 | 第 90 天 | 项目复盘讲解 | 这个业务 → 可独立 |

规则：
- **关 0、关 1 所有人都一样，都要过。**
- **关 2 – 4 每个所选业务各走一遍。新人期同时带 2 – 3 个业务**（带教人在定级时选，最少 2 个、最多 3 个）。
- **解锁**：
  - 关 1 要关 0 通过；
  - 每个业务的关 2 要关 1 通过；
  - 每个业务的关 3 要**这个业务的**关 2 通过，关 4 同理；
  - **业务之间互不卡**：效果图还在关 2，不影响实体模型去跟项目。
- **一关之内**：学习步骤顺序自由；**学习步骤全部完成后才能约过关评估**；评估全部通过才算过关。
- 未解锁的关可以看内容，不能提交。
- **新人期结束** = 所选业务都到「可协助」，并且至少 1 个到「可独立」。结束后其余业务按项目需要再开，走同样的关 2 – 4。
- **建议完成时间**按「新人期开始日 + 天数」算，天数可在路径里改。原型里写的「第 3 周起」等是示意，以上表的天数为准。超过了：在带教人的「待我评估」页列出，并提醒学员。**只提醒，不自动判不通过。**

### 2.3 步骤和评估的类型

| 类型 | 谁完成 | 说明 |
|---|---|---|
| 读文档 `doc` | 学员自己勾 | 现有 |
| 板块阅读 `docset` | 学员自己勾 | 连到知识库的「业务 × 板块」。把里面的文档都打开过才能勾。以后这个板块加了文档，培训里自动出现，不用改路径；已经过关的不受影响 |
| 实操 `task` | 带教人签核 | 学员写完成说明、关联一个项目后提交；带教人「通过 / 退回」，可写评语 |
| 测验 `quiz` | 系统判分 | 现有题型和判分；80 分及格（可改） |
| 讲解 `present` | 带教人按评分表打分 | 学员「约评估」，线下讲完，带教人在平台上打分 |
| 模拟演练 `sim` | 带教人按评分表打分 | 两种：接 brief、写邮件 |
| 定级 `placement` | 带教人填 | 只在关 0 |

- 「板块阅读」对应的业务 × 板块里**一篇文档都没有**时：这一步算完成，同时在「路径与评分表」页给 PD / BD 标红「空板块」。
- 测验关卡**还没出题**时：这一关过不了，在「路径与评分表」页给 PD / BD 标红「还没出题」。PD / BD 可以把这个测验从关卡里去掉。**题目由 Audax 自己出，系统不预置题目。**
- **关 3、关 4 必须在真实项目上完成**：提交实操时必须关联一个自己参与的项目（见 2.7）。

### 2.4 评分表
- 每张表 4 项，每项 1 – 5 分。**平均 ≥ 3.5 且没有任何一项低于 3 才通过**（两个数可改）。
- 只由带教人一个人打分（PD / BD 也可以代打）。
- 评语选填，学员看得到每一项的分数和评语。
- 没通过：补完后可以再约，**每一次都留记录**。
- 预置三张表（PD / BD 可改文字）：

  | 讲解 Presentation | 模拟演练 · 接 brief | 模拟演练 · 写邮件 |
  |---|---|---|
  | 内容准确：业务、交付物、术语没有讲错 | 资料问全：对照这个业务的资料清单，没有漏项 | 用对模板（E3 小样确认 / E5 第 3 轮提醒…） |
  | 流程清楚：从交接到交付每一步、谁负责、哪里要客户确认（workflow 了解程度） | 确认范围、数量、交期 | 信息完整：附件、截止时间、需要客户回复什么 |
  | 应对提问：带教人追问 3 个「如果…怎么办」 | 会后纪要（E2）写清楚、当天发出 | 语气得体，中英文无误 |
  | 表达与时间：像对客户讲，10 分钟内讲完 | 应对加需求：知道什么时候要开变更单 | 2 小时内把客户意见整理好转给深圳 |

### 2.5 入职定级（关 0）
- 学员填自评问卷：7 个业务各选「没做过 / 做过 / 独立带过」。
- 带教人面谈后填定级结果：
  - 新人期带哪 2 – 3 个业务；
  - 每个业务的起步级别，**最高只能给到「可协助」**；
  - 要到「可独立」必须在 Audax 独立带过一个项目并做复盘。
- 业务定到哪一级，对应的关自动标「定级免修」：定「了解」免关 2；定「可协助」免关 2、关 3。
- 定级结果写进能力矩阵（来源记「入职定级」）。

### 2.6 能力矩阵（人 × 业务）
- 一张表：行是人，列是 7 个业务，格子是级别。另有级别（`pm_level`）、带教人、新人期进度三列。
- **谁能看**：PD / BD 看全部；带教人看自己和自己带的人；PM 只看自己；其他角色看不到。
- 点格子：看这一格是凭哪些评估升上来的（测验分数、评分表分数、签核人、日期）。
- **级别怎么变**：
  - 过关自动升级（关 2 → 了解，关 3 → 可协助，关 4 → 可独立）。自动升级**不会把已有的更高级别降下来**。
  - 「可带教」只由 PD / BD 手动给。独立带过 ≥ 3 个这个业务的项目时，系统给一个提示。
  - PD / BD 可以手动调整任何一格，**必须写原因**。带教人不能手动改，只能通过评估。
  - 每次变化都写日志（谁、什么时候、从几级到几级、来源、原因）。
- **上线初始化**：PD / BD 在矩阵页把现有 PM 的级别直接填进去（来源记「初始化」，原因可统一填一次）。
- 带教人和 PD / BD 可以给某个人「开下一级路径」（新人期之外加开业务）。

### 2.7 项目里的「跟项目 / 协助」成员
- 项目加一个成员列表（建议 `p.trainees: { name, mode: 'shadow' | 'assist' }[]`）。带教人（要有这个项目的编辑权）或 PD / BD 可以加、可以移除。
- **跟项目（shadow）**：对这个项目只读。
- **协助（assist）**：和现有的「编辑授权」（`p.perm`）一样能编辑。
- 这两种成员**不算负责 PM**：不计 KPI、不计积分。
- 学员提交关 3「跟 1 个项目」时，只能关联自己是跟项目成员的项目；关 4「协助」关联自己是协助成员的项目；「独立带」关联自己是负责 PM（`owners`）的项目。

### 2.8 派项目限制：没到「可协助」不能当负责 PM
- 位置：指派负责 PM（`addOwner`）和新建项目时选负责 PM。**后端校验，前端同步提示。**
- 规则：
  1. 把项目里的业务用 `bizOfSvc` 对到 7 个业务（对到「其他业务」的不看）。
  2. **要指派的人必须在其中至少一个业务上 ≥「可协助」**，否则拒绝，提示「××在这个项目的业务上还没到『可协助』，不能指定为负责 PM。可以加为『跟项目』成员。」
  3. 服务包负责人（`pk.owner`）是 PM 时，同样要在**这个服务包的业务**上 ≥「可协助」。
  4. 项目里某个业务没有任何一位负责 PM 到「可协助」：**不拦**，在项目上显示提醒，PD / BD 的总览里也列出。
  5. 只到「可协助」、没到「可独立」的人被指定时：不拦，提示「建议再指定一位『可独立』的 PM 一起带」。
- **PD / BD 指派时同样被拦**。要破例：先在能力矩阵里手动调整级别（要写原因）。
- 不检查的情况：
  - 被指派的人是 PD / BD；
  - 项目工程师（`p.engineer`）；
  - 项目的业务全部属于「其他业务」；
  - 售前接洽记录（REQ-054，本来就不指派）。
- **开关**：设置项「启用派项目限制」，**默认关**。关的时候上面第 2、3 条只提醒不拦。PD / BD 把矩阵初始化完再打开。
- **不追溯**：已经指派好的项目不受影响，只在新指派时检查。

### 2.9 页面（原型 ⑤）
- **我的培训**（学员）：关 0、关 1 两个框，下面每个所选业务一行、关 2 – 4 三个框（已过关 / 定级免修 / 进行中 / 未解锁）；点一个框看这一关的学习步骤和过关评估。
- **待我评估**（带教人、PD / BD）：学员提交的实操签核、已约的讲解和模拟演练、待定级的新人；下面一栏「超过建议时间」。
- **能力矩阵**：见 2.6。下方有「每一级怎么升上来」的说明表。
- **路径与评分表**：新人主线、7 条业务路径、6 个月课程、PM 晋级条件、三张评分表。PD / BD 可以编辑。

### 2.10 6 个月课程（技能线）
- 和新人主线并行，**不锁**。每两周一次，周二 3 – 4pm。
- 预置：M1 3ds Max 相机（3 课 + 考核）、M2 彩平制作（4 课 + 考核）、M3 SU 建模 → Max（4 课 + 考核）、M4 实体模型独立跟项目、M5 AI 效果 / mood 工具、M6 SOP Map + checklist、PS 后期基础（长期）。
- 两种步骤：
  - **培训课**：讲师（PD / BD 或带教人）课后点名；缺课的显示「待补」。
  - **考核**：带教人给「通过 / 未通过」和评语（M5、M6 用讲解评分表）。
- M4 不单独打分：等于「实体模型」到「可独立」。

### 2.11 PM 晋级条件
- 每个 PM 一张「晋级条件」清单，**系统只显示哪些已满足，不自动晋级**。级别由 PD / BD 改 `pm_level`。

  | 晋级 | 能力矩阵 | 其他 |
  |---|---|---|
  | Coordinator → PM | 效果图、动画、实体模型「可独立」；Sales Kit 或 VR · 720 · AR 之一「可独立」；LED · 投影 或 中控 之一「可独立」 | 连续 2 个季度项目分值 ≥ 60 |
  | PM → Senior PM | 至少 2 个业务「可带教」 | 带教 1 名新人走完新人期；独立主持 3 次客户会议；连续 2 个季度项目分值 ≥ 90 |
  | Senior PM → PM Director | — | 带团队、开发业务、创新；PD / Director 评审 |

- 能力矩阵和「带教 1 名新人」自动判断；「主持 3 次客户会议」「带团队」等由 PD / BD 手动勾。
- 季度项目分值来自 REQ-063。REQ-063 还没上线时，这一项显示「待 KPI 接入」。
- 条件里的数字和业务可在「路径与评分表」页改。

### 2.12 权限

| 操作 | PD / BD | 带教人 | 学员（PM） | 其他角色 |

| 签核实操、打分、填定级 | ✓ | 只对自己带的人 | — | — |

| 手动调整级别、初始化矩阵 | ✓ | — | — | — |
| 指定带教人、开始新人期、改 `pm_level` | ✓ | — | — | — |
| 开下一级业务路径 | ✓ | 只对自己带的人 | — | — |
| 编辑路径、评分表、及格线、晋级条件 | ✓ | — | — | — |
| 维护测验题库 | ✓ | ✓ | — | — |
| 开关「派项目限制」 | ✓ | — | — | — |

- 学员不能看到自己要考的测验的答案（沿用 REQ-036 的 `adminOnly` 思路）。
- 所有接口后端同样限制。

### 2.13 数据与兼容
- **REQ-036 现有的路径、进度、测验记录全部保留**，在「我的培训」里放在「其他培训」一栏，功能不变。不迁移、不删除。
- 新增内容建议用新表（路径的关卡结构、评估记录、评分表、能力级别及日志、定级记录、带教关系）；`users` 加 `pm_level`、`mentor`、新人期开始日；项目 JSON 加 `trainees`。具体结构由开发决定，写进落地说明。
- **只加表、加列，不改旧数据。** 提供回滚脚本 `scripts/req062-rollback`。
- 首次启动时预置：新人主线、7 条业务路径（各 3 关）、6 个月课程、三张评分表、晋级条件。已存在就不重复建。

### 2.14 不做
- 不做多人评审、不做学员互评。
- 不做邮件 / 短信通知；提醒只在平台内（待我评估、我的培训、我的待办）。
- 不做每年复评、流程更新后的重新确认。
- 不做题库随机抽题。

## 3. 验收标准
**分阶段过关**
- [x] 给新人 Alice 开始新人期、指定带教人 Skye：Alice 只有关 0 可做，关 1 和各业务的关显示未解锁，按钮不可点；直接调接口提交未解锁的步骤被拒。
- [x] Skye 定级：选 3 个业务（效果图、动画、实体模型），实体模型定「了解」。只选 1 个或选 4 个业务时不能保存；级别选不到「可独立」。
- [x] 定级后：矩阵里 Alice 的实体模型是「了解」；实体模型的关 2 显示「定级免修」。
- [x] 关 1 通过后：三个业务的关 2（或免修后的关 3）同时解锁。效果图还在关 2 时，Alice 可以提交实体模型关 3 的实操。
- [x] 一关里学习步骤没做完时，「约评估」「开始测验」不可点。

**评估**
- [x] Alice 约讲解评估 → Skye 的「待我评估」里出现 → Skye 打 4 / 4 / 3 / 4：平均 3.8，通过。
