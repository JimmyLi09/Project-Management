# 需求：Job Record 内容整体表格化 + 一个「总编辑」

- **需求编号**：REQ-032
- **标题**：Job Record 内容表格化，默认只读，用一个「总编辑」进入编辑
- **所属系统**：Project-Management
- **状态**：已确认
- **创建日期**：2026-09-02
- **优先级**：P2 · 0902 批次

## 1. 背景
之前给的 Job Record 只读改进原型是「每个块 / 每一行各自一个铅笔编辑」（现状 → 改进后 那版，图5）。用户看过后明确批注：「不对，改进后应该是整个内容表格化，再从那里加一个总编辑。」即不要碎片化的分块编辑，而是把 Job Record 的内容整体做成一张表，默认只读，只放**一个「总编辑」**按钮统一进入编辑。

## 2. 目标
Job Record 页把「同步自项目创建（只读）」信息 + 「额外业务信息」等内容整体**表格化**呈现，默认只读；右上放**一个「总编辑」**按钮，点后整张表进入可编辑态，改完统一「保存 / 取消」。

## 3. 范围
**做：**
- Job Record 内容整体以**表格**形式展示（含同步自项目创建的只读信息行 与 额外业务信息表，统一为清晰的表格排版，图4 上部那排信息也纳入表格化展示）。
- 默认**只读**：一进来是展示态，不是输入框。
- 右上一个「总编辑」按钮：点后**整张表**所有可改字段进入编辑态（一次编辑整表，不是每行 / 每块各自一个编辑）；出现「保存 / 取消」，保存才写入（服务端照常校验）。
- 「同步自项目创建」的字段保持只读（跟着项目档案走），不在总编辑里被误改；可编辑的是「额外业务信息」等本卡自身字段。
- 表格化后信息更紧凑、对齐（列头清晰，如 项目 / 内容 / 备注）。

**不做：** 不改字段模板机制（字段增减仍归已上线的 REQ-023）；不做多份同类业务的合并（那是已上线的 REQ-026）；「同步自项目创建」的只读字段不在此开放编辑。

## 5. 验收标准
- [ ] Job Record 内容以表格形式展示，排版整齐、列头清晰。
- [ ] 默认只读，无输入框；右上只有一个「总编辑」按钮（不是每行 / 每块一个铅笔）。
- [ ] 点「总编辑」→ 整张表可改字段一起进入编辑态；有「保存 / 取消」；保存后刷新保持。
- [ ] 「同步自项目创建（只读）」的字段始终只读，不被总编辑改动。
- [ ] 老数据兼容：已填内容照常显示、可正常进入总编辑修改。

## 7. 备注（含默认假设，如需调整请在 PR 指出）
- 本条**细化并取代**之前 Job Record 那版「每块各自编辑」的原型（用户已否决分块编辑）；与已上线的 **REQ-005**（默认只读思路）一致，只是把 Job Record 的编辑粒度定为「整表 + 一个总编辑」。
- 与已上线的 **REQ-023**（字段增减自定义）、**REQ-027**（公式字段 / 分组两列排布）配合：总编辑是改字段「值」；改字段「结构」仍走「增减字段」入口。
