# 需求：AV 方案成本平台 · 两套系统合并为一套，统一 8080 端口

- **需求编号**：AV-013
- **所属系统**：AV 方案成本平台（系统一，Next.js）
- **状态**：已实现
- **创建日期**：2026-09-29
- **决策来源**：2026-09-29 Jimmy「数据线按 560000 改，两套系统合并成一套系统。都是以 8080 的形式」

## 1. 决定

1. **只保留一套系统**：项目协作台（含 AV 方案成本平台，本仓库）。Streamlit 版 avcost-phase1（系统二）不再部署，其「AV 方案成本平台 · 上线操作单」作废。
2. **统一端口 8080**：原生（pm2）与 Docker 两种部署都监听 8080，访问地址 `http://<服务器IP>:8080`。
3. **单根数据线承载像素按 560,000**（见 AV-001 第 6 节），不再列为待确认。

## 2. 系统二的功能在本系统中的对应

| 系统二 | 本系统 |
|---|---|
| 案例检索 | AV 历史案例（AV-012），并修正了统计表错列、多屏续行的读法 |
| LED 方案配置：屏体类型（室内固装 / 室外固装 / 租赁）、L / H / P、控制系统（诺瓦 / 卡莱特）、观看距离、强电井距离 | LED 方案配置（AV-001），参数组、`calibrated: false` 阻断导出与系统二一致 |
| 计算链（来源 / 方法 / 置信） | 同，点数值看计算链 |
| 下载 DXF / SVG / 技术方案（Word） | 同（AV-010、AV-011），另有英文版方案书 |
| 保存配置到数据库（锁定公式版本） | 保存配置时绑定规则包版本（AV-003） |
| 11 条验收用例（144-Chuan Grove） | `npm test` 中的 LED 用例覆盖同一组断言 |

差异：系统二的系数与公式写在 `app/config/*.yaml`，改数值不改代码；本系统的规则包写在 `src/av/core/rulepack.ts`，按版本号（如 `led@1.0`）管理，改数值需要改代码并发新版本。

## 3. 端口改动

- `package.json` 的 `start` 改为 `next start -p 8080`。服务器上 `scripts\update.bat` 里的 `pm2 restart audax` 会重新执行 `npm start`，更新后自动换到 8080，无需改 pm2 配置。开发用 `npm run dev` 仍是 3000。
- Docker：容器内也监听 8080，`docker-compose.yml` 映射 `8080:8080`。
- 文档：`DEPLOY.md`、`DEPLOY-Windows.md`、`服务器装机流程.md`、`使用小贴士.md`、`DEPLOY-Cloudflare-Tunnel.md`（隧道指向 `localhost:8080`）、`上线操作单.md`（8080 空闲检查、停用已装的系统二、防火墙放行 8080、通知同事改收藏地址、Cloudflare 路由改 8080）。
- 回滚到本次之前的版本时，端口随之回到 3000。


## 变更记录
- 2026-09-29：**端口撤回为 3000**（用户决定）。合并后的系统仍用原地址 `http://<服务器IP>:3000`，同事收藏、防火墙规则、Cloudflare Tunnel 都不用改。`package.json` / Dockerfile / docker-compose / 部署文档已同步。
