# 需求：Job Record 优化 + LED 自动计算器

- **需求编号**：REQ-039
- **标题**：Job Record 可下载 / 下拉选择 / 自动计算（LED 功率·线缆）/ 编辑高亮
- **所属系统**：Project-Management
- **状态**：已确认
- **创建日期**：2026-09-02
- **优先级**：P1 · 运营中心批次（源：Progress comments 第2份 + Calculator reference.xlsx）

## 1. 背景
Job Record 现在不能下载、有一条固定的只读信息条显得冗余、很多该选择的地方是手填、LED 这类需要算功率 / 线缆的却要人工算。用户提供了《Calculator reference》给出 LED 计算口径，要求 Job Record 支持自动计算与一系列交互优化。

## 2. 目标
Job Record 支持：整份下载；去掉固定只读块；业务 / 规格 / 选项改下拉 + 列表；LED 尺寸自动算功率 / 散热（按 Calculator reference）；一个「编辑」按钮改内容、关键信息粗体高亮。

## 3. 范围
**做：**
- **可下载**：Job Record 整份导出（PDF / Excel）。
- **去掉固定块**：移除原「同步自项目创建(只读)」的固定信息条（待确认具体指哪条，见备注）。
- **整体选择 + list**：顶部用下拉选择 业务 / 规格（Screen Resolution）/ Location 等，并有「已添加」列表（配合同类业务可多块，见 REQ-026）；其它该选择的字段也改下拉。
- **自动计算（LED）**：填 Length(mm) / Width(mm)，实时算出：
  - SQM = 长 × 宽 ÷ 1,000,000
  - Max KW = SQM × 450 ÷ 1000（450W/SQM）
  - AVG KW = Max KW × 0.5（≈250W/SQM）
  - 散热 Heat KW = AVG KW × 0.8
  - 20A 单相电源线 / Cat6 数据线数量：暂做**手填**（参考表中为手填、无公式；待确认是否有规则）。
  - 计算结果只读、随输入实时更新。
- **编辑 + 高亮**：一个「编辑」按钮进入编辑态改「额外业务信息」内容（对齐 REQ-031 总编辑思路）；关键信息**粗体高亮**显示。

**不做：** 本期自动计算仅 LED（其它业务的计算器见备注，按需再加）；不改积分口径（归 REQ-038）。

## 5. 验收标准
- [ ] Job Record 可整份下载（PDF / Excel）。
- [ ] 原固定只读信息条已按确认去掉 / 调整。
- [ ] 业务 / 规格 / Location 等为下拉选择，并有已添加列表。
- [ ] 填 LED 长 / 宽后，SQM / Max KW / AVG KW / 散热按公式实时算出、只读；数值与 Calculator reference 一致（如 10560×3200 → SQM 33.792、Max 15.21、AVG 7.60、散热 6.08）。
- [ ] 电源线 / 数据线数量可手填。
- [ ] 有「编辑」按钮改额外业务信息；关键信息粗体高亮，保存后保持。

## 收尾：两个开放问题的答案（2026-09-29）

0917 这份需求留了两条待定。当时还没有计算规则，所以定的是「手填」。之后 AV 方案成本平台带着一套已标定的 LED 规则包进来了，两条都有答案：

### 一、数量 L / H 能否从「单块尺寸」自动算 —— 不能，但方案配置里已经算出来了

不能靠一个「单块尺寸」除出来。`src/av/core/layout.ts` 开头就写明：一块屏不是同一种箱体重复铺；宽和高各自对箱体库求解，结果是**一个序列**而不是一个整数（注释里举的就是 144-Chuan Grove：2560 = 480×4 + 640，最上面那块 640）。加一个「单块尺寸」字段再写 `ceil(长 / 单块宽)`，在混拼屏上必错，而混拼是常态。

真正算得出的是 LED 方案配置（F3 箱体排布）。

### 二、Power / Data Cable 有无计算规则 —— 有，F6–F9

| 数 | 规则 | 出处 |
|---|---|---|
| 回路数 F6 | `ceil(总功率 / 2.5 kW)` | 公司级常量 `circuitKw: 2.5` |
| 电源线 F7 | 回路数 + 1 备用 | `nPowerCable = nCircuit + 1` |
| 数据线路数 F8 | 按每行箱体算 | 单根承载 560,000 像素（AV-001 裁定） |
| 数据线 F9 | 线路数 + 1 备用 | `nDataCable = nDataRun + 1` |

常量与备用那一根经 2026-09-29 确认，与现场做法一致。

### 落地口径：带过来，但允许覆写

资料卡上 **数量 L / 数量 H / 电源线 / 数据线** 四格：

- 没人填过 → 显示该项目 LED 方案配置算出来的值，标一个「配」，hover 说明来自哪个规则包版本、算于何时；
- 有人填过且与算出来的不同 → 以人填的为准，标「已人工调整」，把算出来的那个数留在 hover 里；
- 填的和算的一样 → 不标（照抄一遍不算人工调整）；
- 该项目没存过 LED 方案配置 → 四格仍是空白手填，行为与改版前一致。

「数量 Total」是公式字段 `qtyL × qtyH`，公式求值时走同一套兜底，所以 L/H 来自方案配置时 Total 也算得出来。

**为什么不做成资料卡上的公式字段**：算这四个数要先解出箱体排布，而排布要箱体库、模组尺寸、控制系统这些输入 —— 资料卡上只有长、宽、点间距、类型，没有这些。

**实现**：新增 `GET /api/av/derived`，对调用者可见的每个项目（沿用 REQ-043 可见性），拿存着的那份 cfg 与当时绑定的规则包版本重跑一遍确定性内核。不直接读存下来的 summary，是因为 summary 里有箱体总数却没有横竖各几只。
