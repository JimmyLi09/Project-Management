# 需求：AV 方案成本平台 · 图纸解析与人工校核（03 / 04）

- **需求编号**：REQ-011
- **标题**：图纸分级、六项要素提取、计算链标注、04 校核闸门与样本回写
- **所属系统**：AV 方案成本平台（`services/drawing/avdrawing/ingest/`）
- **状态**：已实现（含 02–04 界面、04→05 交接、校核结果入库并关联项目）；OCR 与视觉两条支路待真实图纸与 API 额度联调
- **创建日期**：2026-09-25
- **优先级**：P0 · 对应规格书 §2.1（03/04）、§9、§13.2、§14，验收 A9 / A10

## 1. 背景

规格书 §1 的设计原则：**AI 只负责两头** —— 图纸信息抽取与文档文字生成，中间的排布、
功耗、线路计算全部是确定性代码。本需求实现的是「前面那一头」，并保证它交出去的每一个值
都带得住追溯。

## 2. 目标

把一份图纸变成六条带 provenance 三标签的要素记录（§4.1 的 `led_opening_w`、
`led_opening_h`、`led_mount_h`、`led_ctrl_dist`、`led_pwr_dist`、`led_view_min`），
并由 04 人工校核把关，未过闸门不得进入 05。

## 3. 范围

| 模块 | 文件 | 规格出处 |
| --- | --- | --- |
| 图纸分级 A / B / C | `grade.py` | §2.1 |
| 图层语义映射 | `semantic.py` | §14 |
| A 级 DXF 解析 | `dxf_reader.py` | §14（ezdxf） |
| B 级 矢量 PDF 解析 + 比例尺标定 | `pdf_reader.py` | §2.1、§14（PyMuPDF） |

| 按分级调度 | `pipeline.py` | §2.1 |

## 4. 关键设计决策

1. **图层语义映射不能只靠余弦相似度。** 实测真实 CAD 图层名，负例 `A-WALL` 对
   「led wall」得 0.79，而正例 `屏体轮廓` 只有 0.66 —— 两类重叠，任何阈值都会切错。
   因此每个要素额外带一组**标记词**（led / 屏 / 显示 等），图层名里必须真的出现其一才可能
   匹配；余弦只在通过标记词的候选中排序。加闸门后正例 0.655–1.0、负例全为 0，完全分开。
2. **比例尺不推断，只标定**（§2.1）。B 级 PDF 必须先给定图框比例或两点标定，否则拒绝解析。
   错误的比例会让每一个量都错得很像样。
3. **扫描件的结论权在人**（§13.2）。C 级记录的置信度上限压到 0.75，且闸门对 C 级要求
   **逐项人工确认**，与 OCR 自报的置信度无关。
4. **原始值与修正值并存**（§10）。确认时原值留在 `value`，修正值写入 `corrected`，
   05 读 `final`。修正即样本，追加写入 JSONL 样本库 —— 这就是 §14 所说「积累 300+ 标注样本
   后转 YOLO」的积累方式。
5. **模型只被问「你看到了什么」**。视觉提示词明写禁止计算数量、功率、回路数，并对
   `stop_reason` 的 `refusal` 与 `max_tokens` 显式报错，不把截断的 JSON 当结果。

## 4a. 界面与接口（02–04）

| 部分 | 位置 | 说明 |
| --- | --- | --- |
| 界面 | 侧栏「LED 图纸校核」`LedIngestView.tsx` | 上传、分级、系统值与人工值并排、逐项确认/修正/补录、闸门状态 |
| 解析接口 | `POST /api/av/ingest` | multipart 上传；PDF 需带 `scale`；销售 / PM / PD / BD 可用 |
| 校核接口 | `POST /api/av/review` | 仅 PM / PD / BD；修正人与时间由服务端按登录身份记录；回写样本库 `data/av-samples/led.jsonl`；**服务端复核 A10 闸门**，未通过不交接 |
| 调用方式 | `src/server/avdrawing.ts` | 每次请求启动 `python -m avdrawing.ingest.cli`，JSON 进出；一个应用部署在内网服务器即可，无需第二个常驻服务 |
| 交接 | `src/av/core/handoff.ts` | 校核值带着 provenance 进入 05，05 中这些字段只读，计算链可追到「文件 / 图层 / 坐标」 |

- **闸门阈值 85%**：冻结规格只写「低于阈值」，取值采用流程原型中的「置信度 < 85% 强制入队列」。
- **哪些项必须校核由 Python 一处判定**（每条记录带 `needs_review`），界面只记录确认动作，提交时服务端再判一次。
- **开口宽、高为必填**：确认时不得为空（未识别项补录）；其余四项允许「确认暂缺」，它们只影响
  LED-VD-01 / LED-PWR-07 这类提示。

## 4b. 入库与项目关联（§10 drawing / extraction）

| 表 | 关键字段 |
| --- | --- |
| `av_drawing` | 项目、文件名、等级、比例尺、阈值、说明、上传人/时间、校核人/时间（通过闸门后填写并锁定） |
| `av_extraction` | 图纸、要素、系统值、单位、来源、方法、置信度、规则、说明、是否需校核、确认人、修正值、修正人/时间 |

- 表名带 `av_` 前缀，放在 `src/server/avdb.ts`，与项目 JSON 文档分开存储，不参与项目的乐观锁，也便于整体抽离。
- **图纸只能挂在含 LED 服务包的项目上**（规格 01「业务线勾选 = LED」），服务端校验。
- **每次确认 / 撤销即时落库**，刷新不丢；「提交」时才调用 Python 复核闸门、回写样本、写入项目操作记录。
- **服务端只接受「确认」与「修正值」**：系统值、来源、置信度、是否需校核一律从数据库读取，客户端无法伪造置信度绕过闸门。
- **通过闸门即锁定**：之后任何修改都被拒绝，需要重新上传一版图纸，确认与修正的记录不会被改写。
- **样本只在闸门通过时写入**，被拦下后再提交不会重复写。
- **项目级权限**：上传 = PD / BD / 销售 / 该项目的 PM；校核 = PD / BD / 该项目的 PM；图纸清单所有登录用户可看。
- 项目操作记录（`audit_log`）写入「LED 图纸上传并解析」与「LED 图纸校核完成（修正 N 项，已锁定）」。
- 删除项目时一并删除其图纸与要素记录。

## 5. 验收标准

- [x] 分级：DXF → A，含矢量文字的 PDF → B，纯栅格 → C，其余类型拒绝。
- [x] A 级：从屏体图层实体范围取得开口宽高；provenance 形如
      `01_平面图.dxf / A-LED-DISPLAY / (0, 1200)`，与 §9 示例格式一致。
- [x] A 级：识别不到屏体图层时全部转人工，不猜。
- [x] A 级：`$INSUNITS` 非可换算单位时拒绝解析。
- [x] B 级：未标定比例尺时拒绝解析；标注文字与量取值一致时置信度提升并注明「双源互证」。
- [x] C 级：OCR 自报 0.99 也压到 ≤ 0.75，且闸门在逐项确认前不放行。
- [x] **A10** 校核闸门：置信度低于阈值且未确认的要素存在时，`may_enter_configuration`
      为假。
- [x] **A9** 每条记录三标签齐全，`label()` 输出形如 `rule · A级-DXF-实体范围`。
- [x] 修正回写样本库：仅修正过的要素成为样本，可追加累积。
- [x] 视觉识别：请求用 `claude-sonnet-5`、结构化输出、base64 图像；拒答与截断都报错。
- [x] 界面端到端（浏览器实测）：PDF 未标定被拒、1:50 标定后为 B 级并双源互证；DXF 有待确认项时
      提交按钮禁用；校核后进入 05，图纸字段只读，计算链显示图纸来源；销售可上传但无校核按钮，
      直接调用校核接口返回 403；修正写入样本库且修正人为登录用户。
- [x] 入库端到端（浏览器实测）：确认后刷新页面进度仍在；修正值与修正人落库；提交后锁定，再改返回 400；
      只发确认字段、附带伪造的置信度提交，闸门仍不放行；非 LED 项目上传返回 400；非负责人 PM 上传与校核
      均返回 403 但可查看清单；项目操作记录出现上传与校核两条；删除项目后图纸与要素记录清空。

验证方式：`services/drawing/.venv/bin/python -m pytest`（45 项）与 `npm test`（37 项）。

## 6. 本轮未能实机验证的部分

诚实说明，这两条支路代码完整但**未在真实数据上跑过**：

- **PaddleOCR（C 级）**：依赖 `requirements-ocr.txt`，体积大且首次运行需下载 PP-OCRv4
  权重。本轮未安装，`PaddleOcrBackend` 未实机执行；测试用假后端覆盖了调用契约与闸门行为。
- **Claude 视觉 API（图例识别）**：无 API 额度，未发出真实请求。测试用假 client 覆盖了
  请求形状（模型、结构化输出 schema、图像编码）与错误处理。

两者都在接口后面，替换或联调不影响其余代码。真实联调需要：一批扫描件样张、一批图例区截图、
以及 `ANTHROPIC_API_KEY`。

## 7. 备注

- 六项要素中，`led_view_min`（最近观看距离）不存在于图纸上，任何分级都直接转人工，符合 §4.1。
- `led_ctrl_dist` / `led_pwr_dist` 由图层几何中心的平面直线距离推得，未计走线路径，记录中
  已注明并降低置信度，须人工确认。
- `led_mount_h` 由屏体下沿 Y 坐标推得，前提是图纸 Y 原点为完成面标高，置信度上限 0.55。
