- **需求编号**：REQ-063
- **所属系统**：Project-Management（项目协作台 · KPI 看板 / 项目详情）
- **状态**：已开发（分支 `feat/req063-kpi-revisions`，待合并上线；§5 列的 4 条默认值待上线后校准）
- **创建日期**：2026-11-12
- **优先级**：P2
- **来源**：

  - JM 1112 选定：KPI 增加**平均修改轮数**、**修改费回收率**、**PM 级别和分值区间**；分值周期**每季度**。（「按 8 个业务分组看」没有选，不做。）

## 1. 现状（查代码确认）
- `src/lib/kpi.ts`：4 个维度 `points / onTime / quality / load`，按规则折成 0 – 100 分再加权。规则有版本（`kpi_rules`）。周期可选月 / 季 / 年 / 自定义。项目算在负责 PM（`owners`）头上。
- `scoreOf` 的线性模式只支持「越高越好」（`target ≤ floor` 时退化成阈值）。
- **平台没有记录客户修改了几轮**。现有的 `raiseVariation` 是完工后的范围变更审批，不是修改轮次。
- 没有 PM 级别的概念（`pm_level` 由 REQ-062 新增）。

## 2. 功能说明

### 2.1 项目修改记录（新功能，原型 ⑦）
**位置**：项目详情里，每个服务包（业务）一张「修改记录」。

**每一轮记什么**

| 字段 | 说明 |
|---|---|
| 轮次 | 自动编号 R1、R2…，**只数来源是「客户」的** |
| 日期 | 默认今天，可改 |
| 来源 | 客户 / 内部 |
| 修改内容 | 文字，必填 |
| 收费状态 | 见下 |
| 记录人、时间 | 自动 |

**轮次规则**（数字放在规则设置里，可改）
- 第 1、2 轮：免费。
- 第 3 轮：免费，显示提醒「请发 E5『第 3 轮提醒』邮件，请客户一次汇总意见」，带一个到知识库邮件模板的链接。
- **第 4 轮起：应收费。**
- 来源是「内部」的（内审、自己发现的错）：**不算轮数**，只留记录，没有收费状态。

**收费状态**
- `免费` → 不变。
- `应收费 · 待 Sales 报价` → `已出 revised quotation · 等客户确认` → `客户已确认收费`。
- 任何应收费的轮都可以改成 `PD 批准免收`，必须写原因。
- **不记金额**。金额仍以报价和 Finance 为准。

**给 Sales 的待办**
- 一轮被标成应收费时，给这个项目的 Sales 一条待办「××项目 · 效果图第 4 轮修改：48 小时内出 revised quotation」。项目上没有记 Sales 时，所有 Sales 角色都看到。
- 超过 48 小时还是「待 Sales 报价」：待办标红，PD / BD 的总览里也列出。
- Sales 点「已出报价」后待办消失。

**原因会提醒**
- 同一个服务包客户修改累计 ≥ 3 轮：在总览的「风险与受阻」里出一条「××项目 · 效果图修改已 3 轮 → 开原因会」。
- 项目 PM 或 PD / BD 点「已开原因会」并写一句结论后消失。同一个服务包只提醒一次。

**权限**

| 操作 | PD / BD | 项目负责 PM | Sales | 其他 |
|---|---|---|---|---|
| 看修改记录 | ✓ | ✓ | ✓ | 能看这个项目的人都能看 |
| 记一轮修改 | ✓ | ✓ | — | — |
| 改 / 删自己记的那一轮 | ✓（任何一轮） | 只在收费状态还是「免费」或「待 Sales 报价」时 | — | — |
| 已出报价 / 客户已确认 | ✓ | — | ✓ | — |
| 免收 | ✓ | — | — | — |

- 删除一轮后，后面的轮次自动重新编号，收费状态按新的轮次重算（已经是「已出报价 / 已确认 / 免收」的不动）。
- REQ-057 归档后 PM 端只读，修改记录同样只读。
- 修改记录**和 Variation 互不影响**：记一轮修改不会触发重新审批。

### 2.2 KPI 看板：每月看 3 个数（原型 ⑥ 顶部）
三张卡片，**全公司口径**，跟随看板上选的周期（默认本月）：

| 卡片 | 算法 | 默认目标 |
|---|---|---|
| 按时交付率 | 周期内完工的项目里，准时的比例。用现有的 `onTimeOf` | ≥ 90% |
| 平均修改轮数 | 周期内完工的项目，它们的服务包的客户修改轮数的平均值 | ≤ 3 轮 |
| 修改费回收率 | 日期在周期内的应收费轮里，「客户已确认收费」的比例 | ≥ 80% |

- **平均修改轮数只算有效的服务包**：项目交接日在本功能上线日之后的，0 轮按 0 算；上线之前交接的老项目，只有记过至少一轮才算进来。上线日写进设置（上线时自动记一次）。
- **修改费回收率** = 已确认 ÷ （待报价 + 已出报价 + 已确认 + 免收）。**免收算没收回。** 分母是 0 时显示「没有应收费的」。
- 卡片下面一行小字写明细，例如「本月应收费 5 轮：已确认 3 · 待报价 1 · 免收 1」。
- 目标值在规则设置里改。达标绿色，不达标红色。
- 能看 KPI 看板的人都能看这三张卡片。

### 2.3 KPI 看板：PM 级别和季度项目分值（原型 ⑥ 表格）
- 每个 PM 一行，新增两列：
  - **级别**：读 `pm_level`（REQ-062）。PD / BD 可以直接在这里改。
  - **本季度项目分值 / 级别区间**：一条横条，标出这个级别的区间和这个人现在的分值，下面一行文字。
- **项目分值** = 这个人在**所选周期所在的那个季度**的积分（现有 `points` 维度的原始值，REQ-038 的规则）。不管看板周期选的是月还是年，这一列都显示季度的数。
- **级别区间**（放进 KPI 规则，跟着规则版本走，可改）：

  | 级别 | 每季度项目分值 |
  |---|---|
  | Project Coordinator | 40 – 70 |
  | PM | 60 – 90 |
  | Senior PM | 90 – 120 |
  | PM Director | 不设 |

- 文字提示四种：`低于区间`（红）/ `区间内`（绿）/ `区间内 · 已达上一级下限`（蓝）/ `高于区间 · 可考虑晋级`（蓝）。
- **系统不自动晋级。** 级别只由 PD / BD 改。
- 没设级别的 PM：这一列显示「未设级别」，其他列照常。
- 提供一个取数函数给 REQ-062 的晋级条件用：某人最近 N 个季度的项目分值。**季度分值现算，不落库。**
- 下方加一张只读的「级别区间」说明表（原型有）。

### 2.4 KPI 看板：两个新维度
- 新增维度 `revRounds`（平均修改轮数）和 `revRecover`（修改费回收率），按人算：只算这个人是负责 PM 的项目，口径同 2.2。
- 表格里新增这两列（原型 ⑥）。平均修改轮数 > 3 标红；回收率 < 60% 标红；没有应收费轮的显示「没有应收费的」。
- **评分**：
  - `revRounds` 越低越好：默认 ≤ 2 轮 100 分，≥ 5 轮 0 分，中间线性。`scoreOf` 的线性模式要支持「越低越好」（实现方式由开发决定，例如允许 `target < floor`，或加一个 `lowerBetter` 标记；现有四个维度的结果不能变）。
  - `revRecover`：默认线性，0% → 0 分，80% → 100 分。
- **两个新维度默认关闭、权重 0**，不计入加权总分。PD / BD 在「规则设置 · KPI 规则」里打开并分配权重后才算。
- **旧的规则版本里没有这两个维度**：读取时按「关闭」补上，历史周期的总分不能因为升级而变化。`validateKpiRules` 同样要兼容。
- 原始值是空（没有有效服务包 / 没有应收费轮）时：和现有维度一样，这个维度不参与这个人的加权。

### 2.5 谁能看
- 不变：PM 只看自己这一行，PD / BD 看全部。
- 顶部三张卡片是全公司的数，PM 也能看。

### 2.6 数据
- 修改记录建议挂在服务包上（`packages[i].revisions`），或单独建表，由开发决定。老项目没有这个字段时按空处理。
- **只加字段 / 加表，不改旧数据。** 提供回滚脚本 `scripts/req063-rollback`。
- 不记金额、不改报价、不改 Finance 的任何数据。

### 2.7 不做
- 不按 8 个业务分组看 KPI（JM 没选）。
- 不做按金额算的回收率。
- 不自动晋级，不自动改级别。
- 不把季度分值存成历史快照。

## 4. 落地说明

### 4.1 开工前和 JM 确认的(1112)
- **KPI 看板仍只有 PD / BD 能进,不对 PM 开放。**所以 2.5「PM 只看自己这一行」和验收里「PM 登录只看到自己一行」**不做**;顶部三张卡片也只有 PD / BD 看得到。「PM 不能改级别(接口 403)」照做。
- **规则版本按周期挑(只对上线日之后结束的周期)**:
  - 周期结束日在上线日之前的:和以前一样,用「今天」生效的那一版。升级那一刻任何数字都不变。
  - 周期结束日在上线日(含)之后的:用周期结束那天的规则。只看那天已经存在的版本,挑法和以前一样;那天一版都还没存过,就是出厂默认。还没结束的周期按今天算。
  - 所以以后再存新规则,包括把生效日往前写的,已经结束的周期都不会被改写。
- **「这个项目的 Sales」**:交接是谁提交的就是谁(`handover.submittedBy`),前提是这个人是 Sales 角色。没走过交接、或者是 PD / BD 提交的,算「没记 Sales」,所有 Sales 都看到。

### 4.2 开发定的(文档写「由开发决定」或没写到的)
- **数据放哪**:修改记录挂在服务包上,即 `packages[i].revisions`,原因会是 `packages[i].reasonMeeting`。老项目没有这两个字段,按空处理,不迁移。
- **轮次怎么编**:按记录的先后编号(不按日期排),只数「客户」的。改了某一轮的日期,轮次不变。
- **收费状态什么时候重排**:每次记 / 改 / 删都按「今天生效的规则」重排这个服务包里「免费 / 待报价」的轮。已出报价、已确认、免收的轮永远不动。规则里的数字改了以后,已有的轮要等这个服务包下次记 / 改 / 删时才按新规则重排,不批量改历史。
- **收费状态怎么流转**:
  - 待报价 → 已出报价 → 客户已确认,只能按这个顺序;
  - 待报价、已出报价、已确认都可以改成免收,必须写原因;
  - 没有「撤回」(文档没写)。点错了,PD / BD 删掉那一轮重记。
  - 已出报价 / 已确认 / 免收的轮不能改来源。
- **谁能改 / 删**:负责 PM 只能动自己记的、收费状态还是「免费 / 待报价」的轮;内部修改没有收费状态,随时可改。权限走 REQ-051「项目列表」模块的编辑权限。
- **48 小时怎么算**:从这一轮变成「待 Sales 报价」那一刻(`dueAt`)算,打开页面时现算。PD / BD 总览只列超时的;Sales 的待办列全部(超时的标红)。
- **原因会**:客户修改累计 ≥ 3 轮(规则里的数)才能登记,同一个服务包只能登一次。提醒在项目详情「概览 · 风险与受阻」,修改记录页签顶上也有同一个按钮。
- **交接日**:Sales 提交交接的时间;没走过交接的,按建项目那天算。「上线日之后」含上线当天。
- **上线日**:存在 `app_settings.req063Since`,第一次启动新版本时记当天(已有就不动)。PD / BD 可在「规则设置 · KPI 规则」里改,立即生效,不是规则版本。
- **三张卡片的口径**:
  - 「全公司」= 不随看板上的角色 / 业务筛选;手动归档的不算(REQ-045 口径);
  - 「周期内完工」= 实际完工日在周期内;按时交付率的分母 = 这些项目里有交付日的。
  - 看板默认周期从「本季」改成「本月」(2.2「默认本月」)。
- **两个新维度按人算**:
  - `revRounds` = 这个人负责的、本期完工的项目里有效服务包的平均轮数;选了业务筛选就只算那个业务的服务包。
  - `revRecover` = 这个人负责的项目上、日期在本期的应收费轮。
  - 表格里标红的线按文档固定:> 3 轮、< 60%。
- **季度项目分值**:
  - 取所选周期结束日所在的季度,周期还没结束的按今天;
  - 不随业务 / 角色筛选;
  - 用的就是 `computeKpi` 的 points 原始值,和看板「积分产出」同一个算法。
- **晋级条件(REQ-062)**:「连续 N 个季度项目分值 ≥ X」看最近 N 个**已结束**的季度,不含当前季度。函数是 `recentQuarterPoints`,现算不落库。
- **级别列**:只对 PM 角色显示,其他角色显示「—」。级别改的是 REQ-062 的 `users.pm_level`(走 `POST /api/train setPmLevel`,只有 PD / BD)。
- **越低越好怎么实现**:`kpi.ts` 里加了 `LOWER_BETTER = {revRounds}`,`scoreOf(rule, raw, lower)` 多一个参数。原来四个维度不传这个参数,走的还是原来那几行。
  - 越低越好时:阈值 = 不超过 target 满分;线性 = floor(0 分线)> target(满分线);分段 = 不超过 at 给 score。
- **规则版本里新加的三块**:级别区间 `bands`、修改轮次 `rev`、三个数的目标 `targets`。全公司一份(不分角色 / 业务),跟着规则版本走。
  - `validateKpiRules` 读老版本时:缺新维度补「关闭 / 权重 0」;缺原来四维照旧补「开 / 25」(和以前一样);三块缺了补出厂值。
- **E5 模板链接**:指向知识库里标题(中文或英文)含「E5」的那篇文档。没有这篇时,写一句「知识库里还没有…」。
- **其他**:
  - 售前记录(还没转正式)不显示修改记录页签;复制项目不带修改记录。
  - 修改记录的「记录人」是历史类字段,按 REQ-051 的口径改名时不跟着改。PM 改名之后,改名前自己记的轮要 PD / BD 改。

### 4.3 数据结构(没有新表、新列)
