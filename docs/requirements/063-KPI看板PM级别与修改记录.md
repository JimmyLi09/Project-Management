## 1. 现状（查代码确认）
- `src/lib/kpi.ts`：4 个维度 `points / onTime / quality / load`，按规则折成 0 – 100 分再加权。规则有版本（`kpi_rules`）。周期可选月 / 季 / 年 / 自定义。项目算在负责 PM（`owners`）头上。
- `scoreOf` 的线性模式只支持「越高越好」（`target ≤ floor` 时退化成阈值）。
- **平台没有记录客户修改了几轮**。现有的 `raiseVariation` 是完工后的范围变更审批，不是修改轮次。
- 没有 PM 级别的概念（`pm_level` 由 REQ-062 新增）。

## 2. 功能说明

### 2.1 项目修改记录（新功能，原型 ⑦）
**位置**：项目详情里，每个服务包（业务）一张「修改记录」。

**每一轮记什么**

| 字段 | 说明 |
|---|---|
| 轮次 | 自动编号 R1、R2…，**只数来源是「客户」的** |
| 日期 | 默认今天，可改 |
| 来源 | 客户 / 内部 |
| 修改内容 | 文字，必填 |
| 收费状态 | 见下 |
| 记录人、时间 | 自动 |

**轮次规则**（数字放在规则设置里，可改）
- 第 1、2 轮：免费。
- 第 3 轮：免费，显示提醒「请发 E5『第 3 轮提醒』邮件，请客户一次汇总意见」，带一个到知识库邮件模板的链接。
- **第 4 轮起：应收费。**
- 来源是「内部」的（内审、自己发现的错）：**不算轮数**，只留记录，没有收费状态。

**收费状态**
- `免费` → 不变。
- `应收费 · 待 Sales 报价` → `已出 revised quotation · 等客户确认` → `客户已确认收费`。
- 任何应收费的轮都可以改成 `PD 批准免收`，必须写原因。
- **不记金额**。金额仍以报价和 Finance 为准。

**给 Sales 的待办**
- 一轮被标成应收费时，给这个项目的 Sales 一条待办「××项目 · 效果图第 4 轮修改：48 小时内出 revised quotation」。项目上没有记 Sales 时，所有 Sales 角色都看到。
- 超过 48 小时还是「待 Sales 报价」：待办标红，PD / BD 的总览里也列出。
- Sales 点「已出报价」后待办消失。

**原因会提醒**
- 同一个服务包客户修改累计 ≥ 3 轮：在总览的「风险与受阻」里出一条「××项目 · 效果图修改已 3 轮 → 开原因会」。
- 项目 PM 或 PD / BD 点「已开原因会」并写一句结论后消失。同一个服务包只提醒一次。

**权限**

| 操作 | PD / BD | 项目负责 PM | Sales | 其他 |
|---|---|---|---|---|
| 看修改记录 | ✓ | ✓ | ✓ | 能看这个项目的人都能看 |
| 记一轮修改 | ✓ | ✓ | — | — |
| 改 / 删自己记的那一轮 | ✓（任何一轮） | 只在收费状态还是「免费」或「待 Sales 报价」时 | — | — |
| 已出报价 / 客户已确认 | ✓ | — | ✓ | — |
| 免收 | ✓ | — | — | — |

- 删除一轮后，后面的轮次自动重新编号，收费状态按新的轮次重算（已经是「已出报价 / 已确认 / 免收」的不动）。
- REQ-057 归档后 PM 端只读，修改记录同样只读。
- 修改记录**和 Variation 互不影响**：记一轮修改不会触发重新审批。

### 2.2 KPI 看板：每月看 3 个数（原型 ⑥ 顶部）
三张卡片，**全公司口径**，跟随看板上选的周期（默认本月）：

| 卡片 | 算法 | 默认目标 |
|---|---|---|
| 按时交付率 | 周期内完工的项目里，准时的比例。用现有的 `onTimeOf` | ≥ 90% |
| 平均修改轮数 | 周期内完工的项目，它们的服务包的客户修改轮数的平均值 | ≤ 3 轮 |
| 修改费回收率 | 日期在周期内的应收费轮里，「客户已确认收费」的比例 | ≥ 80% |

- **平均修改轮数只算有效的服务包**：项目交接日在本功能上线日之后的，0 轮按 0 算；上线之前交接的老项目，只有记过至少一轮才算进来。上线日写进设置（上线时自动记一次）。
- **修改费回收率** = 已确认 ÷ （待报价 + 已出报价 + 已确认 + 免收）。**免收算没收回。** 分母是 0 时显示「没有应收费的」。
- 卡片下面一行小字写明细，例如「本月应收费 5 轮：已确认 3 · 待报价 1 · 免收 1」。
- 目标值在规则设置里改。达标绿色，不达标红色。
- 能看 KPI 看板的人都能看这三张卡片。

### 2.3 KPI 看板：PM 级别和季度项目分值（原型 ⑥ 表格）
- 每个 PM 一行，新增两列：
  - **级别**：读 `pm_level`（REQ-062）。PD / BD 可以直接在这里改。
  - **本季度项目分值 / 级别区间**：一条横条，标出这个级别的区间和这个人现在的分值，下面一行文字。
- **项目分值** = 这个人在**所选周期所在的那个季度**的积分（现有 `points` 维度的原始值，REQ-038 的规则）。不管看板周期选的是月还是年，这一列都显示季度的数。
- **级别区间**（放进 KPI 规则，跟着规则版本走，可改）：

  | 级别 | 每季度项目分值 |
  |---|---|
  | Project Coordinator | 40 – 70 |
  | PM | 60 – 90 |
  | Senior PM | 90 – 120 |
  | PM Director | 不设 |

- 文字提示四种：`低于区间`（红）/ `区间内`（绿）/ `区间内 · 已达上一级下限`（蓝）/ `高于区间 · 可考虑晋级`（蓝）。
- **系统不自动晋级。** 级别只由 PD / BD 改。
- 没设级别的 PM：这一列显示「未设级别」，其他列照常。
- 提供一个取数函数给 REQ-062 的晋级条件用：某人最近 N 个季度的项目分值。**季度分值现算，不落库。**
- 下方加一张只读的「级别区间」说明表（原型有）。

### 2.4 KPI 看板：两个新维度
- 新增维度 `revRounds`（平均修改轮数）和 `revRecover`（修改费回收率），按人算：只算这个人是负责 PM 的项目，口径同 2.2。
- 表格里新增这两列（原型 ⑥）。平均修改轮数 > 3 标红；回收率 < 60% 标红；没有应收费轮的显示「没有应收费的」。
- **评分**：
  - `revRounds` 越低越好：默认 ≤ 2 轮 100 分，≥ 5 轮 0 分，中间线性。`scoreOf` 的线性模式要支持「越低越好」（实现方式由开发决定，例如允许 `target < floor`，或加一个 `lowerBetter` 标记；现有四个维度的结果不能变）。
  - `revRecover`：默认线性，0% → 0 分，80% → 100 分。
- **两个新维度默认关闭、权重 0**，不计入加权总分。PD / BD 在「规则设置 · KPI 规则」里打开并分配权重后才算。
- **旧的规则版本里没有这两个维度**：读取时按「关闭」补上，历史周期的总分不能因为升级而变化。`validateKpiRules` 同样要兼容。
- 原始值是空（没有有效服务包 / 没有应收费轮）时：和现有维度一样，这个维度不参与这个人的加权。

### 2.5 谁能看
- 不变：PM 只看自己这一行，PD / BD 看全部。
- 顶部三张卡片是全公司的数，PM 也能看。

### 2.6 数据
- 修改记录建议挂在服务包上（`packages[i].revisions`），或单独建表，由开发决定。老项目没有这个字段时按空处理。
- **只加字段 / 加表，不改旧数据。** 提供回滚脚本 `scripts/req063-rollback`。
- 不记金额、不改报价、不改 Finance 的任何数据。

### 2.7 不做
- 不按 8 个业务分组看 KPI（JM 没选）。
- 不做按金额算的回收率。
- 不自动晋级，不自动改级别。
- 不把季度分值存成历史快照。

## 3. 验收标准
**修改记录**
- [ ] 项目 171 的效果图服务包：PM 连续记 4 轮客户修改。R1、R2 免费；R3 免费并出现 E5 提醒和模板链接；R4 自动标「应收费 · 待 Sales 报价」。
- [ ] 中间记一条「内部」修改：不占轮次，没有收费状态。
- [ ] R4 标应收费后：这个项目的 Sales 的待办里出现一条；把时间拨过 48 小时后标红，PD 的总览里也有。
- [ ] Sales 点「已出报价」→「客户已确认」；PM 没有这两个按钮（接口 403）；「免收」只有 PD / BD，不写原因不能保存。
- [ ] 记到第 3 轮时，总览「风险与受阻」出现「开原因会」；点「已开原因会」后消失，记到第 4 轮不再重复出现。
- [ ] 删除 R2 后：原 R3 变 R2、原 R4 变 R3，原来「待 Sales 报价」的那轮变回免费，Sales 的待办消失；已经「客户已确认」的轮不被改动。
- [ ] 项目进入开票 / 收尾（REQ-057）后，PM 端修改记录只读。
- [ ] 记修改不影响完工审批和 Variation 的状态。

**每月看 3 个数**
- [ ] 造数据：本月完工 2 个项目（共 3 个服务包，修改 2、3、4 轮）→ 平均修改轮数 3.0。
- [ ] 上线前交接、没有任何修改记录的老项目本月完工：不拉低平均数。上线后交接、0 轮的项目：按 0 算进去。
- [ ] 本月应收费 5 轮（已确认 3、待报价 1、免收 1）→ 回收率 60%，小字明细正确。没有应收费轮时显示「没有应收费的」。
- [ ] 切换周期（月 / 季 / 年）三张卡片跟着变。

**级别和季度分值**
- [ ] PD 把 Ken 设为 PM：横条显示 60 – 90 区间和 Ken 本季度的分值。分值 71 →「区间内」，55 →「低于区间」，95 →「高于区间 · 可考虑晋级」。Jason 是 Project Coordinator（40 – 70），分值 65 →「区间内 · 已达上一级下限」。
- [ ] 看板周期选「本月」时，这一列仍是本季度的分值。
- [ ] 改规则里的区间并生效后，横条跟着变；`pm_level` 没有被系统自动改动。
- [ ] PM 登录只看到自己一行，不能改级别（接口 403）。

**新维度**
- [ ] 升级后不做任何设置：所有人各周期的 KPI 总分和升级前**完全一致**（两个新维度默认关闭）。
- [ ] PD 打开 `revRounds`、给 10% 权重并生效：2 轮得 100 分、5 轮得 0 分、3.5 轮得 50 分；总分按新权重变化；生效日之前的周期仍按旧规则算。
- [ ] 现有四个维度的评分结果在改 `scoreOf` 前后一致（单元测试覆盖）。
- [ ] 所有新文案中英两套。
