# 需求：AV 方案成本平台 · 图片智能判读与方案建议（本机免费视觉模型）

- **需求编号**：AV-015
- **所属系统**：AV 方案成本平台（02–04 图纸 · 解析 · 校核 → 05 方案配置）
- **状态**：已确认
- **创建日期**：2026-09-30
- **优先级**：P1
- **来源**：2026-09-30 Jimmy：上传 PNG 报「PaddleOCR 未安装。执行 pip install -r requirements-ocr.txt 后重试」；附件「有可能是图纸，也可能只是截图」，系统要**自己判断整体需求并给出方案**。附现场照片一张（弧形 LED 屏，手写标注 2400mm × 2000mm）。
- **原型**：`Audax_图片智能判读_原型_v1.html`（4 种情况：现场照片 + 手写尺寸 / 施工图截图 / 无尺寸效果图 / 模型未启动兜底）
- **关联**：AV-001（确定性计算内核，§1 模型只读图、不出工程量）、AV-002（图纸分级与人工校核，C 级规则）、AV-012/014（历史案例）、AV-010（局域网部署）

## 1. 背景

现在 02 的逻辑按文件后缀分级：DXF = A、矢量 PDF = B、图片 / 扫描 PDF = C；C 级只走 PaddleOCR 读文字。问题：

1. PaddleOCR 是可选组件，服务器没装，同事看到的是一条开发命令，流程直接断掉。
2. 就算装了，OCR 只能读出「2400」「2000」这些字，**分不清哪个是宽、哪个是高，看不出是弧形屏，也分不清这张图是施工图、现场照片、截图还是效果图**，更判断不了是「要施工的现场」还是「客户想要类似效果的参考」。
3. 实际业务里，客户 / 销售发来的附件大量是手机照片、微信截图、效果图，不是 DXF。

## 2. 决定（0930 已确认）

- **只用免费方案**：本机运行开源视觉模型，**图片不出公司内网、不接任何收费 API**。
- **做到「05 方案配置草案」**：识别 → 列出缺的信息 → 按规则推荐点间距 → 人工确认 → 带入 05，由计算内核排箱体、算功耗 / 线材 / 成本。
- 坚持 AV-001 §1：**模型只「看」和「读」，不出任何工程量**；点间距、箱体、功耗、回路、线材、成本全部由确定性内核按规则包算。所有模型读出的值都是候选，**逐项人工确认后才能进 05**（沿用 C 级规则）。

## 3. 识别引擎（本机、免费）

- **运行方式**：服务器上装 **Ollama**（开源免费），以 Windows 服务方式运行，只监听 `127.0.0.1:11434`（不对局域网开放）。制图服务通过本机 HTTP 调用。
- **模型**：选一个**许可证允许商用**、中英文和数字识别好的本地视觉模型。默认建议 **Qwen2.5-VL 7B**（或其后续版本），请实测后定，并在 PR 里写明型号与许可证（注意：部分小尺寸型号是「仅研究用途」许可，不能用）。
- **硬件**：有 ≥ 8 GB 显存的 NVIDIA 显卡时用 GPU（目标：单张 < 60 秒）；没有就用 CPU（目标：单张 < 3 分钟，界面显示进度，不阻塞其他操作）。服务器 16 GB 内存，模型常驻要评估对平台本身的影响，空闲 N 分钟自动卸载（Ollama `keep_alive`）。
- **可替换**：引擎做成接口（本机视觉模型 / OCR / 手填），以后要换模型或接其他引擎，不动上下游。
- **管理设置**（「规则设置」或管理员页）：开关、模型名、服务地址、超时、「检测状态」按钮（显示：服务在不在、模型装没装、用 GPU 还是 CPU、最近一次耗时）。

## 4. 流程

### 4.1 分级（02）

- DXF → A、矢量 PDF → B：**不变**。
- 图片（png / jpg / jpeg / webp / bmp / tif）和**扫描件 PDF**（逐页转成图片）→ 进入「图片智能判读」。

### 4.2 判读（03）——模型输出一份结构化结果（JSON Schema 约束）

1. **图片类型**：施工图 / 施工图截图、现场照片、效果图 / 概念图、其他截图（聊天、表格、网页）、与屏无关。附把握度。
2. **场景**：室内 / 室外、空间类型（大堂、会议室、展厅、零售、户外立面…）、一句话描述。
3. **用途猜测**：要施工的现场 / 参考效果（客户想要类似的）/ 只是资料。**必须由人确认**（原型的三选一）。
4. **读到的要素**（对应 AV-002 的六要素 + 形状等补充项）：
   - `led_opening_w`、`led_opening_h`、`led_mount_h`、`led_ctrl_dist`、`led_pwr_dist`、`led_view_min`；
   - 补充：形状（平面 / 内凹弧 / 外凸弧 / 转角 / 异形）、安装方式（嵌墙 / 挂墙 / 落地 / 吊装 / 桁架）、图上写明的点间距或型号（如「LED-01 P1.86」）、画面比例。
   - 每项带：值、单位、把握度、**来源说明**（「读自手写标注『2400m m』」「读自尺寸线『5760』」「看图判断」）、是否**估算**。
5. **读数规则**（写进提示词，并在服务端校验）：
   - 数字**只能来自图上看得见的标注或文字**；看不见就留空，**不许编**。
   - 按比例推算的值（例如按门高推离地高度）必须标「估」，把握度上限 0.4。
   - 单位容错：「2400m m」「2,400」「2.4m」统一换算成 mm；超出合理范围（如宽 < 200 mm 或 > 50,000 mm）丢弃并提示。
   - 沿用 C 级规则：模型自报把握度再高，C 级也压到 ≤ 0.75；**每一项都要人工确认**。

### 4.3 还缺什么（确定性规则生成，不交给模型）

按「图片类型 + 形状 + 缺哪些要素」查一张规则表，列出要补充的问题，例如：

| 条件 | 追问 |
|---|---|
| 形状是弧形 | 标注的宽是**弧长还是弦长**？弧半径或弧高是多少？ |
| 没有最近观看距离 | 观众离屏最近几米？（点间距要用） |
| 嵌墙安装 | 屏后有没有检修空间（前维护 / 后维护）？ |
| 没有控制室 / 配电距离 | 大概多远？不填按规则包默认值估算并标「待补」 |
| 效果图，没有尺寸 | 宽和高？（给一边可按画面比例推另一边，推出的值标「按比例推算」） |
| 施工图截图 | 提示「请向甲方要 DXF / PDF 原件」 |

### 4.4 方案建议（内核给，不是模型给）

- **点间距**：按规则包 `LED-VD-01`「点间距(mm) ≤ 最近观看距离(m)」，从价格库里对应环境（室内 / 室外）的型号中筛出满足的，默认选**满足规则中最省的**，人可以改。图上写明了点间距（如施工图的 P1.86）就以图为准，只校验是否满足规则。
- **弧形屏**：现有内核不支持曲率。本期按**弧长平铺**排箱体、算功耗和线材；06 成本核算里单列「弧形箱体 / 柔性模组 / 弧形钢结构 —— 待询价」。弦长 + 弧高 / 半径 → 弧长的换算由确定性代码做。
- **类似历史案例**：从历史案例库按面积（±50%）、点间距、形状（备注 / 型号里含 curve / 弧）找 3 条，显示在建议区。

### 4.5 带入 05

- 所有项确认、用途不是「只是资料」、选定点间距后，「带入 05 方案配置（草案）」才可点。
- 带入的每个值标来源「来自图片 · 已人工确认」；按默认值估算的项在 05 顶部提示「按默认值估算，待补」。
- 用途 = 「参考效果」时：尺寸默认留空、由人填我们现场的尺寸（图只用来参考形状 / 效果）；原型里这一点可再按实际业务调整，PR 里说明。
- 人工确认 / 修正后的结果写回标注样本（沿用 `models.write_back_samples`），为以后评估和换模型积累数据。

## 5. 兜底（任何情况都不能再出现开发命令）

1. 视觉模型不可用（服务没起 / 超时）→ 自动退回 **OCR**（若装了 PaddleOCR）：列出读到的数字，让人指定「这是宽 / 高 / 不是尺寸」。
2. OCR 也没有 → 直接给**手填表单**，流程不断。
3. 同事看到的提示是人话：「本机识别服务暂不可用，已改为手填；请联系管理员」。技术细节只出现在管理员的状态页和服务器日志里。

## 6. 部署

- 上线操作单增加一节：安装 Ollama（服务方式、仅本机监听）、拉取模型（约 5 GB，一次性）、检测命令、如何确认用的是 GPU。
- `update.bat`：不负责装 Ollama，但更新完做一次「识别服务状态检测」并打印结果；可选开关一并安装 OCR（`requirements-ocr.txt`）。
- **注意依赖冲突**：`paddleocr 2.9.1` 要求 `numpy<2.0`，而现有制图服务环境里是 numpy 2.x。若保留 OCR 兜底，请处理好版本（或把 OCR 放独立虚拟环境 / 换兼容版本），并在 Windows + Python 3.11 上实测。
- 模型与图片都在本机，**不向外网发送任何图片**。

## 7. 验收标准

- [ ] 上传附带的现场照片（弧形屏、手写 2400mm × 2000mm）：类型识别为「现场照片」；屏宽 2400、屏高 2000（手写「2400m m」能正确换算）；形状识别为弧形；「还缺什么」里出现「弧长还是弦长」「弧半径 / 弧高」「最近观看距离」「前 / 后维护」。
- [ ] 上传施工图截图：读出尺寸线上的宽、高和图注里的距离；提示要 DXF / PDF 原件；图上写的点间距被带出并按规则校验。
- [ ] 上传没有尺寸的效果图：**不出现任何编造的尺寸**；只给画面比例，并要求补尺寸。
- [ ] 所有模型读出的值都要逐项确认，C 级把握度不超过 0.75；估算值有「估」标记且把握度 ≤ 0.4。
- [ ] 点间距候选只出现满足 `LED-VD-01` 的型号，默认选最省的；模型没有参与点间距决定。
- [ ] 弧形屏带入 05 后按弧长排箱体，06 有「弧形箱体 / 结构 待询价」一项。
- [ ] 停掉 Ollama 服务再上传：界面给人话提示并退回 OCR / 手填，不报错、不出现开发命令。
- [ ] 断开外网时照常工作（证明不依赖外部服务）。
- [ ] 管理员状态页能看到服务 / 模型 / GPU 或 CPU / 最近耗时。
- [ ] GPU 环境单张 < 60 秒；CPU 环境单张 < 3 分钟且有进度显示。
- [ ] 新增文案中英两套；操作日志记录「谁上传、识别结果、谁确认 / 修改了什么」。
