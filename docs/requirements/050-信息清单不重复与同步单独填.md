# 需求：信息清单不再重复——同业务多份分格、不同业务「同步 / 单独填」、导出可选业务

- **需求编号**：REQ-050
- **所属系统**：Project-Management（项目协作台 · 信息清单）
- **状态**：已确认
- **创建日期**：2026-10-12
- **优先级**：P1 · 1009 批次
- **来源**：
  - `Progress comments - 0924.docx`（1009 版）第 6 条「checklist 里面太多重复的内容。不同的业务可以共用资料，但是不能重复信息」，截图为 143-Royal Plaza LED 出现「(#2)」重复项；
  - JM 1012 确认原型 v2，并补充：「checklist 的导出，需要可以选择不同的 services」。

## 1. 现状（查代码确认）
- REQ-044 之后每个项目只有一张清单（`Project.checklist`），每项用 `svcs` 标出适用业务。
- **同一业务第二份**（如第二块 LED）：`addServicePackage(asNew)` 用 `mergeIntoProject(..., {inst})` 把模板再并一次，同名项改名为「名字 (#2)」并打上 `inst`（`sharedChecklist.ts:26-31,90-100`）。结果连地址、联系人、时间节点都出现第二份。
  - `inst` 是写死的字符串，改实例名或删掉前一份会对不上。
  - 显示用的 ①② 和这里的 #2 也不一致。
- **每项只有一份状态 / 内容**（`types.ts:130-147`），不能「效果图收到了、沙盘还没」分开记。
- **导出**（`ExportOverlay.tsx:55, 260-271, 356-365`）有按服务包勾选，但只在多服务包时出现；不勾 LED #2 时它的 `inst` 项仍被导出。

## 2. 功能说明

### 2.1 同一业务多份：规格项分格，不复制
- 模板里每项标注范围：
  - **项目级**：地址、联系人、图纸、时间节点等，整个项目只有一条；
  - **规格项**：屏幕尺寸 / 类型、是否含铁架 / 电脑 / 音响、放置位置等，每份业务各不相同。
- 加第二份同类业务时**不新增任何行**。规格项在同一行里多一格「LED-2」，各自有状态、内容、收料记录。
- 每格用服务包 id 关联，不再用写死的「#2」字符串：改实例名会自动更新，删掉一份只去掉那一格。
- 标签统一显示实例名，没有实例名时显示「LED-1 / LED-2」。

### 2.2 不同业务：每项可选「同步 / 单独填」
- 适用于两个及以上业务的项（如效果图 + 动画 + 沙盘都要的「最终 CAD + 3D 模型」），行上有开关：
  - **同步**（默认）：所有业务共用一份状态、内容、收料记录。在任一业务标签下修改，其他业务同时更新。行下注明「↔ 同步到 CGI · 动画 · 沙盘」。
  - **单独填**：同一行里按业务分格，各自有状态、内容、收料记录（比如沙盘只要主干树位置）。切换时，每个业务先复制一份当前内容。
- **改回同步**：弹窗选「以哪个业务那份为准」。其他业务的内容和收料记录保留在这一项的修改记录里，不会丢。
- 只适用于一个业务的项不显示开关，标「只此业务」。

### 2.3 统计与显示
- 业务标签筛选（全部 / 效果图 / 动画 / 沙盘 / LED…）。单独填的项在某个业务标签下只显示该业务那一格。
- 完成率、待处理、逾期按格计算：同步项算 1 格；单独填的项和规格项按份数 / 业务数计，在单个业务标签下只算该业务的格。
- 内部收料记录（REQ-042）同样按格记，记录上标明业务或实例。

### 2.4 导出可选业务（1012 补充）
- 「导出清单」弹窗**总是**显示业务选择（不再只在多服务包时出现）。可勾多个，同一业务两份时可分别勾「LED-1 / LED-2」。默认是当前标签。
- 导出规则：
  - 只导所勾业务适用的项；
  - 单独填项和规格项只导所勾业务 / 实例的那几格；
  - 同步项导一次，「适用业务」列写全部业务。
- 导出文件名带上所选业务，如 `171-50JHS_Checklist_CGI+Animation.xlsx`。

### 2.5 数据与迁移
- `ChecklistItem` 新增：
  - `mode: 'sync' | 'sep'`（默认 sync）；
  - `scope: 'proj' | 'inst'`（来自模板）；
  - `cells: { [svc 或 包id]: { status, date, remark, received, owner, receipts[] } }`。
- 状态、收料、备注等修改动作都要带上「哪一格」。
- **上线迁移（自动，可回退）**：
  1. 现有「名字 (#N)」项和对应原项合并成一行；
  2. 原项的值放进第 1 格，(#N) 项的值放进第 N 格；
  3. 项目级的项保留最靠后的状态，其余值记进修改记录。
- 迁移前原样备份到 `checklistLegacy050`；报告写到 `data/migrations/050-checklist-<时间>.md`。提供 `scripts\req050-dryrun.bat` 先预演、`scripts\req050-rollback.bat` 回退（同 REQ-044 的做法）。
- 模板管理里每项可以设「项目级 / 规格项」，默认值由开发按现有模板整理，PD 复核。

## 4. 迁移预演（先于功能合并）
生产库只在内网，不上 Vercel，所以「先用生产库副本跑一遍」放在服务器上做。这一步只加预演工具和迁移规则，**不改网站任何行为**。合进 main 并更新服务器后，跑 `scripts\req050-dryrun.bat`：
- 用 SQLite 在线备份把 `data\audax.db` 复制到 `data\migrations\050-dryrun-<时间>.db`，只在副本上处理，正式库不动（网站开着也能跑）。
- 报告写到 `data\migrations\050-checklist-dryrun-<时间>.md`：
  - 每个有「(#N)」重复项的项目一张表：分组 / 项 / 范围（规格项或项目级，以及是怎么定的）/ 原来几份各什么状态 / 上线后（一行分格，还是合成一条、留的是哪一份）；
  - 补的空格、对不上服务包的项；
  - 自检结果：每一项都有去处、没有被降级、收料记录和参考图一条不少；
  - 最后附「规格项默认值」，请 PD 复核。

PD 按报告抽查（至少 143-Royal Plaza 和一个两块 LED 以上的项目），没问题再做功能 PR（附 `scripts\req050-rollback.bat`）。上线迁移和预演用同一份规则（`src/lib/mig050.ts`、`src/lib/checklistScope.ts`）。

迁移规则：
- **服务包补 id**：规格项的格按服务包 id 关联，不再靠写死的「#2」。
- **(#N) 项对到服务包**：
  - 先按实例名，再按 #N 序号。
  - 实例名后来改过的：同一业务里还没对上的实例名和还没被占的那几份，个数一样就按出现顺序对。
  - 前面那份删掉、只剩一份的：都算这一份。
  - 还对不上的不动，报告里列出来。
- **找原项**：去掉名字后缀「(#2)」「(户外 LED)」，按名字（含同义项）找没有实例标记的原项，合成一组。
- **规格项，且这个业务现在有两份以上**：
  - 原项留下（id 不变，链接不变），同一行里每份一格。
  - 原项的值进第 1 格，(#N) 的值进第 N 格；状态、内容、收料记录、参考图各自原样。
  - 某一份原来没有这一项的，给一个空格。
  - 行上的老字段跟第 1 格（老代码和导出读它们）。
- **项目级，或这个业务只剩一份**：
  - 合成一条，保留状态最靠后的那一份（一样就看最近的收料日期）的状态、内容和收料记录。这样「行上的状态 = 最新一条收料记录」（REQ-042 的约定）不会被打破。
  - 其余几份原样（含收料记录）记进这一项的修改记录 `history`，一条不丢；空的那份不记。
- **跨业务共用的项**（比如 LED 和投影共用的「地址 + 联系人」）：不分实例格，按一条处理。要分开的，上线后切「单独填」。
- **已经有两份以上、但没有 (#N) 的规格项**（老数据）：也补上格，新的那格是空的。
- **范围怎么定**：
  - 项上已经设过的，照它。
  - 业务模板里有这一项的：在规格项表里就是规格项，否则是项目级。规格项表由开发按出厂模板整理，见报告最后一节；PD 存过的模板也算。
  - 模板里没有的项按名字猜：带地址 / 联系人 / 图纸 / 时间节点 / 截止 / 下单 / 发货的，是项目级；带尺寸 / 规格 / 型号 / 类型 / 比例 / 位置 / 铁架 / 模型台的，是规格项。
  - 都不是的，算项目级（最多少一格，不会凭空多出要填的东西）。
- **备份**：清单有改动的项目，原来的整张清单原样存进 `checklistLegacy050`（回退用）。每个项目记 `mig050`，只跑一次。

自测：
- 单元测试 5 个，覆盖：

  - 不降级；
  - 实例名改过、#N 和名字混用、对不上的不动；

## 5. 落地说明（功能）
- **数据**（`lib/clCells.ts`）：
  - 服务包有 `id`。信息项可以有 `cells`（分格）、`mode`（`sep` = 单独填）、`scope`（`inst` = 规格项）、`history`（修改记录）。
  - 规格项：同一业务有两份以上时，每份服务包一格，键是服务包 id。标签是实例名，没有实例名时是「LED-1 / LED-2」。改实例名标签自动跟着变；删掉一份，只少那一格。
  - 单独填：每个业务一格，键是业务 key。
  - 不分格的项和以前一样，内容就在项本身上。
  - 分格的项，行上的状态 / 日期 / 内容 / 备注 / 负责人跟第一格（看板这类读老字段的地方不出错）。参考图和收料记录只放在格里，不在行上再存一份。
- **加 / 删业务**：
  - 加第二份同类业务，不再另起「(#2)」那一条。规格项在同一行多一格（新格是空的）；项目级的项只多一个业务标签。
  - 删掉一份：那一格去掉，有内容的连同收料记录进这一项的修改记录。只剩一份时，收回成一条。
  - 新建项目时同一业务选两份，也是直接分格。
- **同步 / 单独填**：
  - 适用两个以上业务的项，行下注明「↔ 同步到 CGI 静帧 · 动画 · 沙盘模型」。编辑时有「⇉ 单独填」按钮。
  - 切成单独填：每个业务一格，先各复制一份当时的内容（收料记录也复制，id 换新）。
  - 「↔ 改回同步」会弹窗，选以哪个业务那份为准。其余几份的内容和收料记录原样进修改记录（「🕘 修改记录」可展开看），不会丢。
  - 只适用于一个业务的项标「只此业务」，没有开关。
- **按格改**：
  - 状态、收到内容、日期、备注、负责人、重点、参考图、收料记录都按格改（动作带 `cell`）。名字是整行的。
  - 分格的项不带格会被拒（「请刷新页面后再改」），不会改错格。
- **统计**：完成率、待处理、逾期都按格算：同步项算 1 格；规格项和单独填按份数 / 业务数。在单个业务标签下只算这个业务的格。项目列表的清单进度也一样。
- **显示**：分格的项名字一行，下面每格一小行，各自有状态、收到内容、日期、备注、负责人、参考图、收料记录。单独填的项在某个业务标签下只显示那个业务那一格。
- **内部收料记录**：按格列出，标明是哪个业务 / 哪一份；搜索和导出 CSV 也带着。
- **导出**（`ExportOverlay.tsx`）：
  - 「服务」选择总是显示（以前只在多服务包时出现）。同一业务两份时可以分别勾「LED-1 / LED-2」。默认是当前标签。
  - 只导所勾业务适用的项。同步项导一次，「适用业务」写全部业务；单独填项和规格项只导所勾业务 / 实例的那几格（「景观平面 · CGI 静帧」）。
  - 文件名带所选业务：打印另存 PDF 时默认文件名是 `171-50JHS_Checklist_CGI+Animation`。
  - 多了一个「清单下载 Excel (CSV)」，文件名 `171-50JHS_Checklist_CGI+Animation.csv`。导出没有用 .xlsx：不引新依赖，和 Job Record 下载一样用带 BOM 的 CSV，Excel 直接打开。
- **模板管理**：每个清单项多一个「项目级 / 规格项 · 每份一格」下拉，默认值来自 §4 的规格项表，请 PD 复核。只影响之后新加的项（已有项目的项在上线迁移时已经定好）。
- **从别的项目导入 / 存为模板**：规格项的格按「第几份」带过去，到目标项目对回它的第 1 / 2 份；复制项目时格的结构跟着走，内容清空。
- **人员**：改名、转交负责人时，每一格的负责人都会跟着改 / 转。
- **权限**（REQ-043 / 051 不变）：
  - 「同步 / 单独填」归「信息清单」模块；只读的人改不了任何一格。
  - 不可见的人拿不到清单，包括格、修改记录和迁移备份。
- **上线迁移**：规则见 §4。服务第一次启动时跑一次（`meta` 记 `mig.req050.checklist`）。先整库备份到 `data/backups/pre-req050-<时间>.db`，报告写到 `data/migrations/050-checklist-<时间>.md`。
- **回退**：`scripts\req050-rollback.bat`。不带参数只报告；加 `--apply` 先备份，再拆格：
  - 规格项的第 2、3 格拆回「名字(#2)」「名字(户外 LED)」单独一条，就是 REQ-044 那一版的样子；
  - 单独填的项按业务拆成几条，名字后加业务名；
  - 去掉迁移标记。
  - 修改记录和 `checklistLegacy050` 原样留着。
  - 上线时合成一条的项目级重复项不拆回，没被采用的那份在修改记录里，报告逐项列出。
  - 退回后再升级，规格项会重新合并成分格；单独填拆出来的几条名字不同，不会自动合回。
