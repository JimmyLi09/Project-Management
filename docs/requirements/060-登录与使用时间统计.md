# 需求：登录与使用时间——PD / BD 查看每个人的在线状态、登录记录和使用时长

- **需求编号**：REQ-060
- **所属系统**：Project-Management（项目协作台 · 用户与权限）
- **状态**：已确认
- **创建日期**：2026-10-23
- **优先级**：P2
- **来源**：
  - JM 1022：「需要额外增加的功能，如何查看每个人的登录与否与使用平台的时间？」
  - 1022 选定：
    - 只有 PD / BD 能看；
    - 记录在线状态、登录记录和使用时长；
    - 只算真正在用的时间。
- **原型**：`docs/requirements/assets/058-060-1022反馈_原型_v2.html`，标签「⑥ 登录与使用」，JM 1023 确认。
- **关联**：REQ-051（用户与权限、停用 / 删除账号）。

## 1. 现状（查代码确认）
- **会话是无状态的签名 cookie**：
  - `server/session.ts` 里 `createToken(uid)` 生成签名 cookie，有效 14 天；
  - 服务端**没有会话表**；
  - **不记录**登录、登出时间，也没有任何活跃度数据。
- 登录在 `api/auth/login`，登出在 `api/auth/logout`。
- `users` 表只有账号基本信息。

## 2. 功能说明

### 2.1 记录什么
**登录 / 登出**
- 新表 `user_sessions`：

  | 字段 | 说明 |
  |---|---|
  | `id` | 主键 |
  | `user_id` | 用户 |
  | `login_at` | 登录时间 |
  | `logout_at` | 登出时间，没登出时为空 |
  | `logout_reason` | `manual` / `expired` / `disabled` |
  | `last_seen_at` | 最后一次活动时间 |
  | `device` | User-Agent 归纳成「Chrome · Windows」「Safari · iPhone」这类简单说法 |
  | `ip` | 只存，界面上不显示 |

- 登录成功时写一条，cookie 里带上 session id。
- 主动登出时写 `logout_at`。
- 会话过期，或被 REQ-051 停用 / 删除时，下次判断补上 `logout_at = last_seen_at`，原因写 `expired` / `disabled`。

**使用时长（只算真正在用的时间）**
- 浏览器端心跳：
  - 页面在前台（`document.visibilityState === 'visible'`）；
  - 并且**最近 5 分钟内**有点击、按键、滚动或鼠标移动；
  - 满足这两条时，每 60 秒发一次 `POST /api/activity`。
- 服务端收到心跳：
  - 给 `last_seen_at` 打点；
  - 在 `user_activity_daily(user_id, day, active_minutes)` 里按**本地日期**累加 1 分钟；
  - 同一个用户开多个标签页时，同一分钟只算一次（按「用户 + 分钟」去重）。
- 只是页面开着、5 分钟以上没有操作的，不发心跳、不计时。
- **不记录**看了哪些页面、哪些项目。

**在线状态**（算出来，不存）
- **在线**：2 分钟内有心跳。
- **空闲**：会话还有效，但超过 5 分钟没有活动。
- **离线**：已登出，或超过 15 分钟没有任何请求。

### 2.2 谁能看、在哪里看
- 「用户与权限」新增标签「**登录与使用**」，**只有 PD / BD 能看**，后端接口同样只给 PD / BD。
- 列表每人一行：
  - 用户、职位；
  - 状态（在线 / 空闲 / 离线）；
  - 最后活动（「2 分钟前」「昨天 17:42」）；
  - 最近登录；
  - 使用时长（可切换今天 / 本周 / 本月）；
  - 近 14 天小柱状图；
  - 「明细」按钮。
- 顶部显示「N 人在线」，有「导出 Excel」按钮。
- 停用 / 已删除的账号默认不显示，可勾「含已停用」。历史记录保留。
- **明细**：
  - 近 7 天，可往前翻；
  - 每天的登录 / 登出时间段（一天多次就分段列）、当天使用时长、设备；
  - 会话过期的标「超时自动登出」。
- **每个人看自己**：右下角头像菜单加「我的使用记录」，只显示自己的明细，内容同上。

### 2.3 告知与保留
- 登录页底部加一行小字：「为统计使用情况，平台会记录登录时间与使用时长 / Login times and usage time are recorded for usage statistics.」
- 数据保留 **12 个月**。服务每天清理一次更早的 `user_sessions` 和 `user_activity_daily`。

### 2.4 性能与安全
- 心跳接口只更新两张小表，不读写项目数据。60 秒一次，用户数很少，不影响性能。
- 没登录时心跳返回 401，**不跳转登录页**（避免打扰）。
- 心跳失败时静默重试，不弹提示。
- 不新增第三方统计服务，数据只存在本机 SQLite。

## 3. 验收标准
- [ ] JM 登录后：「登录与使用」里 JM 显示在线，最近登录是刚才；
  - 操作 3 分钟后，今天时长约 3 分钟；
  - 页面切到后台或 6 分钟不操作，时长不再增加，状态变成「空闲」。
- [ ] 同时开两个标签页操作：时长不会翻倍。
- [ ] JM 点「登出」：状态变成离线，明细里有这次的登录和登出时间。
- [ ] 会话过期，或账号被停用后：明细里这一段标「超时自动登出」或「已停用」。
- [ ] 以 PM 登录：看不到「登录与使用」标签，直接调接口返回 403；头像菜单里「我的使用记录」只有自己的。
- [ ] 今天 / 本周 / 本月切换正确，按本地日期（UTC+8）算。导出 Excel 和列表一致。
- [ ] 登录页有告知文字。
- [ ] 所有新文案中英两套。

## 4. 落地说明

- **记录**（`src/server/usageStore.ts`，规则在 `src/lib/usage.ts`）：
  - `user_sessions` 一行一段：登录时间、登出时间、原因（`manual` / `expired` / `disabled`）、最后一次请求、最后一次操作、设备、IP。比 §2.1 的表多两列：
    - `sid`：cookie 里带的随机串。同一个 cookie 15 分钟以上没动静、之后又回来，用同一个 `sid` 新开一段 —— 这样「一天里登录多次就分段列」和原型一样，又不用让人重新登录；
    - `last_active_at`：最后一次点击 / 按键 / 滚动 / 鼠标移动（心跳带上来的），用来判断空闲。
  - `user_activity_daily(user_id, day, active_minutes, last_minute)`：`last_minute` 记最后算过的那一分钟，同一个人同一分钟第二次心跳（另一个标签页、另一台设备）不加。按服务器本地日期（新加坡）算。
  - 两张都是新表，启动时自动建，不迁移、不动旧表。
- **一段什么时候结束**：
  - 点「退出登录」：登出时间 = 点的那一刻；
  - 15 分钟以上没有任何请求（关了页面、电脑睡了、cookie 过期）：在最后一次活动那里结束，标「超时自动登出」。下一次有人读列表 / 明细、或者这个人再发心跳时补上；
  - REQ-051 停用 / 删除账号：当场在最后一次活动那里结束，标「已停用」。之后这个 cookie 的心跳 401。
- **上线前就登录着的人**：旧 cookie 里没有 `sid`。第一次心跳时开始记一段（登录时间就是这一刻），cookie 补上 `sid`，到期时间不变。旧版本也认新 cookie（多一个字段不影响），退代码不会把人踢下线。
- **心跳**（`useHeartbeat`，在 `App` 里）：页面在前台、5 分钟内有操作才每 60 秒发一次，打开页面时先发一次。失败、401 都不提示、不跳登录页。只发「距离上次操作多少毫秒」，不带页面、项目。
- **状态**：在线 = 2 分钟内有心跳、且 5 分钟内有操作；空闲 = 还没登出、15 分钟内有请求，但不算在线；离线 = 已登出或 15 分钟没有请求。只有心跳更新「最后活动」，普通的页面请求不写这两张表。
- **页面**：
  - 「用户与权限 → 登录与使用」：本来就只有 PD / BD 进得来，接口 `/api/usage` 也只给 PD / BD（别人 403）。每分钟自动刷新。今天 / 本周（周一开始）/ 本月切换、「含已停用」、导出 Excel（和列表同样的 6 列，再加近 14 天每天的分钟数）。
  - 「明细」和头像旁新加的「我的使用记录」（时钟图标）共用一个组件：近 7 天从新到旧，可以前后翻。`/api/usage/detail` 只能看自己，PD / BD 可以看任何人。
  - 登录页底部加了告知。
- **保留 12 个月**：服务启动时清一次、之后每天一次，删 12 个月以前结束的段和 12 个月以前的每日时长。
- **自测**（1023）：
  - 单元测试新增 8 个（`req060.test.ts`，内存库）：设备归纳、两个标签页 / 两台设备同一分钟只算一次、5 分钟没操作不算、在线 / 空闲 / 离线、登出 / 超时 / 停用和超时后回来开新段、今天 / 本周 / 本月（含本地 0:30 算当天）、明细分段和设备、12 个月清理。UTC 和新加坡时区都过。
  - 端到端 e060 共 27 项，按 §3 逐条，真实时间跑（服务器 `TZ=Asia/Singapore`、浏览器 UTC+8）：
    - 库用上线前的代码造，JM 在旧版本登录着：新版本上线后旧 cookie 第一次心跳就开始记、补上 `sid`，照常能用；
