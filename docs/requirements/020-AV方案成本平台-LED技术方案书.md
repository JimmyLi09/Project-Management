# 需求：AV 方案成本平台 · LED 技术方案书（Word）

- **需求编号**：REQ-020
- **所属系统**：AV 方案成本平台（系统一）
- **状态**：已实现
- **创建日期**：2026-09-28
- **决策来源**：2026-09-28 Jimmy「先做技术方案书，移植系统二的模板」

## 1. 做法

移植 avcost-phase1 的 `app/core/proposal.py`：模板 + 槽位填充，不调用任何模型。

- 数值：TypeScript 内核 `src/av/core/proposal.ts` 从同一次计算取出（与出图、箱体清单、成本一致）。
- 成文：制图服务 `services/drawing/avdrawing/proposal.py`（python-docx 1.1.2，与系统二同版本）按条件拼装预写段落。
- 章节与系统二相同：一、方案概述；二、屏体参数；三、箱体清单；四、供电与信号；五、说明与限制；六、待确认事项（有校验提示时）。

相对系统二的修正：

| 系统二 | 系统一 |
| --- | --- |
| 箱体清单「状态」一律写「库内标准」 | 按实际写「库内标准」或「库外，需定制」 |
| 备用回路、备用数据线写死为 1 | 取自计算结果（F7 − F6、F9 − F8） |
| 观看距离一律写「相匹配」；强电井按 30 m 另判 | 跟随校验结果：有 LED-VD-01 时写「小于推荐最小观看距离」；有 LED-PWR-07 时写加装分配电箱 |
| 中文字体只写西文字体槽 | 同时写东亚字体槽，Word 中实际显示微软雅黑 |
| 没有客户名时副标题留「｜」 | 只拼接非空部分 |

## 2. 界面与接口

- 05 LED 方案配置「拼接与线路图」区域新增「技术方案 (Word)」按钮，下载 `led-proposal.docx`；项目名取自校核图纸所属项目，客户名取自该项目。
- 接口与 DXF 合并为 `POST /api/av/export { kind: 'dxf' | 'proposal', cfg, packVersion, title, client? }`：
  服务端重新计算、再次执行导出闸门（未校准参数组与阻断项 400）；仅 PM / PD / BD 可导出（销售 403）。
