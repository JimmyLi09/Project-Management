# 需求：AV 方案成本平台 · LED 技术方案书（Word）

- **需求编号**：REQ-020
- **所属系统**：AV 方案成本平台（系统一）
- **状态**：已实现
- **创建日期**：2026-09-28
- **决策来源**：2026-09-28 Jimmy「先做技术方案书，移植系统二的模板」

## 1. 做法

移植 avcost-phase1 的 `app/core/proposal.py`：模板 + 条件段落，不调用任何模型。2026-09-28 按 Jimmy 的回复加上抬头、标志、版权页与英文版。

- **内容**：TypeScript 内核 `src/av/core/proposal.ts` 的 `proposalDoc()` 一处生成全部文字——封面、版权页、各章段落、表格、待确认事项，中文或英文——数值取自同一次计算（与出图、箱体清单、成本一致）。
- **排版**：制图服务 `services/drawing/avdrawing/proposal.py`（python-docx 1.1.2，与系统二同版本）只负责排版，不产生数字或叙述。
  TS 与 Python 之间的约定由 `services/drawing/tests/fixtures/proposal/*.json`（TS 内核生成，改动 proposal.ts 后用 `node --experimental-strip-types scripts/proposal-fixtures.ts` 重新生成）锁住。
- **章节**与系统二相同：方案概述、屏体参数、箱体清单、供电与信号、说明与限制、待确认事项（有校验提示时）。

### 版式

- 封面：AUDAX 标志（附图，白色字标改为深色以适应白纸，标志内的白色保留）、标题、项目 / 客户 / 日期；无客户名时不留空行。
- 第 2 页：版权声明（© 年份 AUDAX，仅供该客户就该项目评估使用，未经书面许可不得复制转发；注明生成所用规则包与日期）。
- 正文每页页眉：标志 + 「AUDAX」+ 右侧文档名，下方分隔线；页脚：文档名 · 页码。封面不带页眉页脚。
- A4；中文用微软雅黑；英文用 Calibri（东亚字体仍为微软雅黑，客户名等中文可正常显示）；章标题不单独落在页底。
- 标志文件：`services/drawing/avdrawing/assets/audax-logo.png`（完整标志）、`audax-mark.png`（仅图形），由附图裁切。

### 英文版

- 与中文版章节一一对应、数值相同；参数组、控制系统、待确认事项均有英文表述（LED-VD-01 / FIT-03 / CAB-01 / PWR-07 / PWR-08）。
- 英文版正文不含中文（客户名、项目名除外）。

相对系统二的修正：

| 系统二 | 系统一 |
| --- | --- |
| 箱体清单「状态」一律写「库内标准」 | 按实际写「库内标准」或「库外，需定制」 |
| 备用回路、备用数据线写死为 1 | 取自计算结果（F7 − F6、F9 − F8） |
| 观看距离一律写「相匹配」；强电井按 30 m 另判 | 跟随校验结果：有 LED-VD-01 时写「小于推荐最小观看距离」；有 LED-PWR-07 时写加装分配电箱 |
| 中文字体只写西文字体槽 | 同时写东亚字体槽，Word 中实际显示微软雅黑 |
| 没有客户名时副标题留「｜」 | 只显示有的项 |

## 2. 界面与接口

- 05 LED 方案配置「拼接与线路图」区域：「技术方案（中文）」「技术方案（英文）」两个按钮，下载 `led-proposal-zh.docx` / `led-proposal-en.docx`。
  项目名取自校核图纸所属项目，客户名取自该项目；没有项目时封面写「未命名项目 / Untitled project」。
- 接口与 DXF 合并为 `POST /api/av/export { kind: 'dxf' | 'proposal', lang: 'zh' | 'en', cfg, packVersion, title, client? }`：
  服务端重新计算、再次执行导出闸门（未校准参数组与阻断项 400）；仅 PM / PD / BD 可导出（销售 403）。日期按新加坡时区。
- 测试链接：两个按钮在页面内预览同一份方案书内容（测试页不能下载文件）；DXF 按钮给出说明。
