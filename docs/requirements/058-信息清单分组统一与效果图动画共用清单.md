- **优先级**：P1
- **来源**：
  - `Progress comments - 1009.docx`（1022 版）第 3 条「Checklist 不需要重复的 items」。截图是一个效果图 + 动画 + 其他的项目，共 9 个分组：建筑方 / 景观方 / ID 方各出现两次，「需求信息」和「销售/需求」也重复。

## 1. 现状（查代码确认）
- 每个业务模板各带一套清单分组（`src/lib/templates.ts`）：
  - `cgi`：建筑方 · 外观 / 景观方 · 外观 / 建筑方 · 室内/单元 / ID 方 · 室内；
  - `ani`：建筑方 / 景观方 / ID 方 / 销售/需求；
  - `scale`：场地/市场/需求 / 建筑方 / 景观方 (consultant)；
  - `vrar`、`unitmodel`：建筑 / ID、需求 / 市场；
  - `GENERIC`（其他）：需求信息。
- 新建项目时 `mergeChecklists`（`checklistMerge.ts`）**按分组名合并**：中文名或英文名规范化后相同才算同一组。项按同名 / 同义项（`DEFAULT_SYNONYMS`）合并。
  - 分组名不一样，所以效果图 + 动画会出 8 组，加上「其他」业务就是 9 组；
  - 很多项意思相同、名字不同，也没合上，比如「景观图 + 详图」和「景观平面」。
- PD / BD 可以在模板管理里覆盖模板，存在 `templates` 表，`getEffectiveTemplate` 优先读覆盖。**如果某个业务已经被覆盖过，只改代码里的内置模板不会生效**。

### 2.3 室内资料是可选的
- **新建项目**的「服务类型」下面加一个勾选：**「包含室内部分 Include interior」**，默认不勾。
  - 只有选了带室内资料的业务（效果图 / 动画）时才显示。
  - 3D VR/720、单元模型这两种业务本来就是做室内，**自动包含，不显示勾选**。
- 项目上存 `p.includeInterior`（布尔）。
- 不包含时：
  - 室内资料组**照样生成、存在项目里**（不丢数据，之后可以打开），但：
    - 清单页不显示这一组；
    - 不算完成率、待处理、逾期；
    - 不导出；
    - 不进我的待办。
- 清单页顶部加开关「包含室内部分」，PM / PD / BD 可以随时开或关，写日志。关掉时，已有状态和收料记录都保留。
- 项目详情「概览」的服务信息里显示「含室内 / 不含室内」。

- **宁少勿多**：不确定的不要合。

### 2.5 只影响新项目
- **已有项目一个字都不改**，不跑迁移。
- **模板覆盖的处理**：上线时先检查 `templates` 表里 cgi / ani / scale / vrar / unitmodel / 其他 有没有被 PD / BD 覆盖过。
  - 没覆盖过的：直接用新的内置模板。
  - 覆盖过的：**只把清单部分换成新的**，排期部分保留覆盖值。
    - 先出报告：`scripts\req058-dryrun.bat` → `data\migrations\058-templates-<时间>.md`，逐个列出覆盖前 / 后的分组和项；
    - JM 确认后再正式改；
    - 原覆盖值备份到 `templatesLegacy058`；
    - 提供 `scripts\req058-rollback.bat`。
  - 如果一个都没覆盖过，报告里写「无覆盖，直接生效」。
- 模板管理页可以看到新的分组和项。PD 以后照样可以改。

## 3. 验收标准
- [ ] 新建「效果图 + 动画」项目，不勾「包含室内部分」：
  - 清单只有 3 组：建筑资料（6）、景观资料（8）、销售 / 需求（2）；
  - 每项同时标「效果图」「动画」；
  - 没有任何重复项。
- [ ] 同样的项目勾上「包含室内部分」：多出室内资料（11 项，两段小标题）。项目建好后关掉开关：这一组隐藏、完成率不算它，再打开时原来的状态还在。
- [ ] 新建「效果图 + 动画 + 其他」：4 组；「销售 / 需求」里截止日只有一条；「需求 / 规格」「素材 / 参考」只标「其他」。
- [ ] 新建「效果图 + 沙盘」：建筑资料、景观资料各一组，同义项合成一条（如「最终 CAD + 3D 模型」和沙盘的「最终 CAD + SKP…」）；沙盘的「场地/市场/需求」单独一组。
- [ ] 新建「3D VR/720」：自动包含室内资料，没有勾选框；没有「建筑 / ID」组。
- [ ] 带分项的项（如 8 Planting layout）：清单、PDF、Excel 都在下面显示 a / b 分项；中英切换正确。
- [ ] 已有项目（如 171-50JHS）：清单完全没变。
- [ ] 模板覆盖预演报告能列出覆盖情况；回退脚本能还原。
- [ ] REQ-050 的同步 / 单独填对新清单照常可用；所有新文案中英两套。

## 4. 落地说明

- **模板**（`src/lib/templates.ts`）：
  - 分组带固定 key，放在分组的第 5 位：建筑资料 `arch`、景观资料 `land`、室内资料 `int`、销售 / 需求 `brief`。名字、颜色四个业务共用一份常量。
  - `cgi` 和 `ani` 的 `checklist` 是同一个常量（27 项，照 §2.2 的表）。
  - 分项 / 小标题放在项的第 4 位：`[中文, English, 范围, { sub, subEn, sec, secEn }]`。和 §2.2 建议的写法不一样：第 3 位已经是 REQ-050 的「项目级 / 规格项」，所以分项、小标题合成一个对象放后面。
  - 沙盘、3D VR/720、单元模型、其他照 §2.4 改；沙盘的「场地/市场/需求」不加 key，照旧单独一组。
- **合并**（`checklistMerge.ts`、`sharedChecklist.ts`）：
  - 分组先按 key 合，再按名字合（老项目、老覆盖值没有 key，照旧按名字）。
  - 同义项：REQ-058 新名字并进原来的组（如「最终 CAD + 3D 模型(至少 WP 审批版)」进「最终 CAD + 3D 模型」那组），另加三组：截止日 ≈ 最终截止日；景观平面 ≈ 景观平面图 ≈ 景观图 + 详图；户外家具 ≈ 室外家具 / 健身 / 儿童设施布置 ≈ 家具与设备。原来的同义项一条不删。
  - 截止日合成一条时用效果图 / 动画的名字「最终截止日」（先加的业务的名字留下）。
- **「4 组」的理解**：「效果图 + 动画 + 其他」勾了室内是 建筑资料 / 景观资料 / 室内资料 / 销售 / 需求 4 组，「其他」的三项并进销售 / 需求（截止日合成一条，需求 / 规格、素材 / 参考只标「其他」）。不勾室内时清单页 3 组，室内资料存着但不显示。
- **室内资料可选**（`src/lib/interior.ts`）：
  - 项目上 `includeInterior`；3D VR/720、单元模型自动包含（不存字段，现算）。
  - 不包含时：清单页、完成率 / 待处理 / 逾期、导出（预览 / PDF / Excel）、「内部收料记录」都跳过这一组；数据留在项目里。「我的待办」只有排期任务，清单项本来就不进，不用改。
  - 清单页开关：只在项目里有室内资料组、又不是自动包含时显示。负责的 PM、PD、BD 能开关（别的 PM、Sales、Engineer 后端 403），写日志「打开 / 关掉室内部分」。
  - 概览「服务包」旁边显示 含室内 / 含室内(自动) / 不含室内；老项目没有室内资料组，不显示。
- **分项 / 小标题**：清单页项名下面一行灰字；小标题在组内和上一项不同时出一行。导出预览、PDF 一样；Excel 里分项是项名格子的第二行（小一号灰字），小标题是一整行合并的粗体。模板管理每项多了「分项」中英两格，保存时 key、小标题都保留。
- **模板覆盖**（`src/lib/mig058.ts`）：
  - 受影响的业务：效果图、动画、沙盘、3D VR/720、单元模型，加上所有用通用模板的业务。覆盖值的清单和新的内置清单一样就跳过（再跑一次不重复改）。
  - **PD 存过同义项也要处理**：存过就不再用代码里的默认那份，新同义项不会生效。所以迁移把 REQ-058 新加的并进 PD 存的那份（原来的不删），一起备份、一起回退。文档只写了模板表，这一条是补的。
  - 覆盖值里 PD 自己加的项会随清单整份换掉。预演报告「换之前」逐项列着，JM 可以决定上线后要不要在模板管理里加回去。
  - 预演 / 确认 / 迁移 / 回退和 053、054 同一套：`req058-dryrun.bat`（只读）→ `--approve` 在正式库记一笔 → 重启时整库备份 `pre-req058-<时间>.db`、原值进 meta `templatesLegacy058`、出报告 → `req058-rollback.bat [--apply]`。没有要改的就只记标记，不出备份。
- **已有项目一个字不动**：没有任何项目迁移。只是读的时候：老项目没有 key，开关不显示，和以前一样。
