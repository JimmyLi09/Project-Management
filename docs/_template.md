# 需求文档模板

> 用法：每写一条新需求，复制本文件到对应仓库的 `docs/requirements/` 下，
> 重命名为 `NNN-简短标题.md`（例：`001-登录页.md`），然后按字段填写。
> 字段固定不变，是为了让 Claude Code 每次都能照着同一套结构直接开工。

---

## 元信息

- **需求编号**：REQ-NNN
- **标题**：
- **所属系统**：<Property-APP / Personal-OS / Project-Management / Worker-Management-System>
- **状态**：草稿 / 已确认 / 开发中 / 已完成
- **创建日期**：YYYY-MM-DD
- **最后更新**：YYYY-MM-DD

## 1. 背景 / 为什么做

<用两三句话说清楚：现在有什么问题，或想抓住什么机会。>

## 2. 目标（这条需求要达成什么）

<一句话说明成功长什么样。可量化最好。>

## 3. 范围

**做：**
-

**不做（明确排除，避免范围蔓延）：**
-

## 4. 详细需求 / 用户故事

<按"作为<角色>，我想<做什么>，以便<获得什么价值>"来写；或直接分点列出功能要求。>

## 5. 验收标准（Claude Code 照这里验证）

> 每条都要可验证——能写成一个测试、或一句能被明确判定"通过/不通过"的话。

- [ ] 给定 <输入/状态>，当 <操作>，则 <预期结果>
- [ ]
- [ ]

## 6. 边界与异常情况

<空值、超长、并发、网络失败等要怎么处理；哪些情况明确不处理。>

## 7. 依赖 / 备注

<依赖哪些外部服务、其他需求、或需要谁确认的开放问题。>
